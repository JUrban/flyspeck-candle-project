Strong progress overnight: S0 and G5 closed, the complete 875-job geometry contract and topology representation proved, and the nine inward-rounded radii caught and fixed uniformly. Two things must be settled before any verified build.

1. G5 is generic over data, not over inequalities

bounded_case16594_word_whole_witnessed_fast_eval accepts only the canonical case-16594 167-step code/source streams and a fixed 875-by-31 certificate header. Certificates, packed cells and jobs vary at call time; the program and the cell count do not.

Installed as is, the kernel gains a branch that serves only case 16594. Any other inequality, or a re-subdivided case-16594 certificate with a different cell count, would need another kernel change and another verified build. Plan v2 ruled that pattern out for production.

It is still a legitimate choice for a first-theorem demonstrator, but it must be an explicit owner decision, not a side effect.

Requests:

(a) Relabel G5 in the gate map as "case-16594 callback: payload-generic, program-fixed". Add a separate pending gate for the plan-generic callback, so the map does not read as if the production callback is done.

(b) Before G8, write a short estimate of what generalising the callback requires: decoding an arbitrary supported plan, using the existing plan compiler and its soundness theorems (3b1f875aa, e5d168e7d); a trace theorem over compiled programs rather than the canonical 167 actions; delta recognition; and variable cell counts and headers. Give focused effort, caps and the main risk.

(c) Do not start G8 until the owner chooses between a case-16594-only build now and generalising first. G6 and G7 can proceed meanwhile, since both are needed either way.
