Audit 7: measure what the fast route actually buys (2026-11-07, after v4.379)

G6 is closed and did exactly what it is for: the >80 GiB topology failure was found and replaced by a proved direct runner, and the complete type-inferred case-16594 callback now accepts the genuine 875-cell / 1,749-token payload in 4:42 at about 6 GB, with all nine mutations returning None. The stale cell-0 oracle was caught before the run. Proceed with G7 as planned; it is needed whichever route wins.

The G6 timing changes the priority of everything else.

1. Case 16594 on the stock route is now the deciding measurement

The complete fast callback takes 282 s for 875 cells, about 0.32 s per cell. The only stock-route timing is case 10173: 434 s for 4,173 cells, about 0.10 s per cell. These are different programs and not directly comparable, but on current evidence the fast route is not demonstrably faster than the stock route. The earlier standalone checker did the same 875 cells in 8-11 s, so the proved callback is about 30x slower than the checker that motivated this route.

Please, before anything else except G7:

(a) Run case 16594 through the stock fixed-nonlinear route via ordinary Kernel.compute, with no kernel change. Record Kernel.compute, handoff, reconstruction and peak RSS. If the stock checker cannot express the six delta instructions, say exactly what is missing, and run it with the ordinary polynomial expansion if available.

(b) Attribute the 282 s: external byte packing and parsing, the 145 s numerical phase, packet recomputation, cv encoding, and the unexplained 137 s. Say how much of the 30x gap to the standalone checker is recoverable inside the proved seam, and at what proof cost.

2. The timed projection sample

The projection has not moved beyond the v4.372 inventory. Finish the join to certificate cell counts and topology sizes, run the stratified 20-30-leaf stock sample including case 16594 from point 1, and publish the one-page CPU-hour and memory projection with uncertainty and the unsupported fraction.

3. G5P only if the fast route earns it

Run the G5P discriminator only if point 1 shows a material per-case speedup of the fast route over the stock route, say 5x or more, or a recoverable one per point 1(b). Otherwise park G5P: the plan-generic callback, a verified build and prepared-state reconstruction would cost days for little gain.

The owner's G8 decision then rests on one comparison: stock-route cost for all of NL against the fast route's measured speedup and its remaining cost (G5P, one verified build, prepared state). No G8 build until these are in and the owner has decided.
