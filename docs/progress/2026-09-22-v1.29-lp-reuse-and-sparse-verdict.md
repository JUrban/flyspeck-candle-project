## Sparse one-shot numerical checker

The next-stage arithmetic core is now implemented and proved on isolated
branch `codex/cv-lp-sparse-verdict-v1`.

It represents each exact row as a sorted sparse map from variable indices to
subtraction-free signed integers, plus a signed rhs. The verified evaluator
performs insertion/merge, row addition, nonnegative scaling, whole-certificate
folding, coefficient cancellation, and the strict-negative-rhs test. Its
public result is only `Cexp_num 1` or `Cexp_num 0`, rather than a reconstructed
dense accumulator.

The branch contains assumption-free representation theorems for every stage
and a complete verdict theorem. The focused fixture checks both a concrete
sparse fold and a cancelling infeasibility certificate. It passed:

- a checkpoint-isolated clean replay from the computation base; and
- the repository test from a fresh `hol.ml` process.

One evaluator-contract detail was discovered and handled without weakening
the proof: user equations cannot place raw `Cexp_num (SUC 0)` on their rhs.
The compute equation constructs true through a supported cval expression,
while the ordinary correctness theorem still identifies the result with
`SUC 0`.

## Interpretation and next boundary

The requested phase separation is now actionable:

- exact reuse lowers per-terminal source conversion but leaves it dominant;
- theorem reconstruction is only 11.38 seconds in the current dense path;
- dense `Kernel.compute` remains 85.20 seconds; and
- a sparse complete-verdict evaluator now exists to attack both dominant
  costs at once.

The sparse core is not yet a Flyspeck proof path. The next required milestone
is a checked source bridge proving that authenticated sparse rows denote the
original real inequalities and that a true complete verdict implies the exact
legacy contradiction. The first benchmark will reuse terminal 15 and report
source conversion, evaluator execution, one-theorem handoff, total CPU, memory,
and exact theorem-interface comparison. No release claim will use the sparse
path before that bridge and comparison pass.
