## Question tested

The real five-terminal `hard_2.dat` profile has a 1,662-row reusable master.
Its cold reflected lane spends about 172 seconds constructing authenticated
master rows, then about 97 seconds checking five terminals. The bounded
prototype tested whether replacing 1,662 weight-general row theorems with one
complete unweighted-master correspondence could reduce that cost and provide
a checked boundary for externally prepared sparse tables.

The prototype added:

- a `cval` encoding and proved injective decoder for the complete unweighted
  sparse master table;
- one `Kernel.compute` equality verdict between the authenticated source table
  and proposed planned table;
- one assumption-free theorem transporting the table's denotation; and
- exact rejection tests for a changed row, reordered rows, and a wrong
  source index.

The existing final theorem interface, source conclusions, sparse arithmetic
verdict, and axiom checks were unchanged.

## Restored-state namespace defect

The first real-state run stopped during prototype loading. Flyspeck had already
defined `rows` as a matrix predicate, so an untyped recursive-definition binder
with the same name was resolved to that constant in the richer namespace. The
focused state had not exposed the collision.

The failure is preserved at:

```text
/project/flyspeck-candle-runs/
  cv-lp-sparse-hard2-batch8-12-master-correspondence-v1
```

The correction only renamed and explicitly separated the recursive binders.
The focused reflected-verdict suite passed, and the corrected source then
loaded in the actual post-action-183 state. This was an integration defect in
the experiment, not a Flyspeck theorem or certificate failure.

## Real five-terminal result

The corrected v2 run restored the same clean post-action-183 checkpoint and
used the same terminals 8 through 12 as the v1.38 baseline. All five reflected
theorems matched the legacy theorem exactly in conclusion, hypothesis set,
printed-theorem digest, and axiom set.

| Batch phase | v1.38 baseline | whole-master candidate | Change |
|---|---:|---:|---:|
| legacy five terminals | 118.34 s | 121.15 s | run noise / +2.80 s |
| computed source plan | 42.62 s | 42.14 s | -0.48 s |
| shared selector context | 23.85 s | 24.06 s | +0.21 s |
| authenticated source-row theorems | 171.35 s | 171.54 s | +0.20 s |
| table denotation | absent | 4.56 s | +4.56 s |
| computed table correspondence | absent | 4.31 s | +4.31 s |
| complete master | 172.31 s | 181.37 s | +9.06 s |
| five reflected terminals | 97.13 s | 188.21 s | +91.08 s |
| complete profiled batch | 455.32 s | 558.00 s | +102.68 s |

Subtracting the in-session legacy baseline, the reflected lane rose from
**336.98 seconds to 436.85 seconds**, a **29.64% regression**.

The source-row phase was effectively identical: removing weight
generalization did not touch the real bottleneck. The new row handoff expanded
the stored source-pair theorem again for every selected terminal row. Its five
row-denotation phases therefore rose from **5.48 seconds to 98.01 seconds**.
This precisely localizes the regression; it is not evaluator or sparse-verdict
noise.

The complete-table equality itself was inexpensive: the computed
correspondence took only **4.31 seconds** for all 1,662 rows, and the global
denotation chain took 4.56 seconds. That is useful evidence for a future
external-data contract, but it does not reduce the expensive concrete proof
that each exact Flyspeck coefficient/variable list denotes its sparse row.

## Decision

The candidate is **rejected and reverted**. The experimental commits are:

```text
c33eb88  Prototype checked LP master correspondence
9121cd5  Avoid Flyspeck rows namespace collision
01101c3  Revert "Avoid Flyspeck rows namespace collision"
27032b5  Revert "Prototype checked LP master correspondence"
```

Branch `codex/cv-lp-master-correspondence-v1` now has the same Candle tree as
its retained numeral-cache base `c3508ca`. The focused sparse-verdict suite
passed after the revert. No slower production source remains.

This result strengthens the v1.39 conclusion. A useful LP redesign must
aggregate or eliminate the concrete source-entry correspondence proof while
preserving the existing constant-time indexed row instantiation. Merely
wrapping the already authenticated rows in one table equality cannot improve
cold cost; reconstructing their denotations at terminal time is much worse.
The 4.31-second full-table equality may be reused only if a later architecture
actually avoids the 171-second source proof boundary and retains cheap terminal
selection.
