## Closed review findings

The final Candle implementation now requires:

- exact lexical `Filename.concat` request strings, including repeated `/`;
- one logical key per canonical physical source path;
- exact JSON scalar types throughout trace and receipt projections;
- an exact, immutable attempt/receipt envelope;
- complete nested controller source, commit, Python/ELF, and host-tool
  provenance;
- exact cardinality for retained controller closures;
- a runtime executable record bound to the immutable attempt and command;
- the actual ordinary, read-only executable file with matching size,
  SHA-256, MD5, path, and executable mode during receipt validation;
- the actual ordinary, read-only `candle.log` during receipt validation;
- rederivation of action events, the physical loader trace, logical source
  closure, and fingerprints from those exact log bytes; and
- finite resource measurements and normalized provenance paths.

The final independent audit reran the earlier coercive-scalar, duplicate
closure, path spelling, empty/tampered log, unbound command, relocated
executable, and producer compatibility cases.  All invalid cases rejected.
Producer-shaped completed, logged-failed, and no-log early-failure receipts
validated under their respective contracts.  The exact direct-evidence branch
passes 232 Python tests.

## Formal replay launch

The CakeML worktree was artifact-cold: it contained no `.hol/objs`, compile
heap, `cake.S`, `config_enc_str.txt`, or reusable x64 proof objects.  A
dependency-only plan reported 5,956 objects for
`x64BootstrapProofTheory.uo`; therefore there is no honest small focused proof
replay from the current cache state.

After exact CakeML/HOL4 head checks, clean-worktree checks, runtime hash checks,
more than 160 GiB `MemAvailable`, 5 TiB free disk, and a zero-swap-I/O sample,
a one-worker cold replay was launched at:

`/project/flyspeck-candle-runs/cakeml-parser-diagnostic-proof-964406486`

The stages are:

1. `cv_translator/cake_compile_heap`
2. `compiler/bootstrap/translation/compiler64ProgTheory.uo`
3. `compiler/bootstrap/compilation/x64/64/x64BootstrapTheory.uo`, including
   `cake.S` and `config_enc_str.txt`
4. `compiler/bootstrap/compilation/x64/64/proofs/x64BootstrapProofTheory.uo`

The replay uses `Holmake -j1 --mt=1`, so it adds approximately one build CPU.
Each replay process has a 112 GiB address-space last-resort limit.  Because the
PFT and reference processes currently account for about 27 GiB, monitoring
alerts are set when replay RSS approaches 88--90 GiB or aggregate project RSS
approaches 115 GiB.  Alerts also cover less than 32 GiB system memory
available, sustained swap I/O, duplicate replay instances, or build failure.
The cold closure is provisionally a multi-day operation; elapsed time is not
itself a failure.  At the 13:15 UTC heartbeat, the first stage had produced
322 objects and was still advancing with exactly one `Holmake`; replay RSS was
about 1.07 GiB, aggregate replay/PFT/reference RSS was about 24.7 GiB, system
memory available was about 184.4 GiB, and the latest swap interval was 0 pages
in/0 pages out.  No resource or liveness alert was active.

This replay is formal source/x64 proof evidence only.  Even if it succeeds, a
new canonical bootstrap, linked-provenance record, combined runtime build, and
direct Flyspeck strata remain required before Candle is usable for checking
Flyspeck.
