Date: 2026-08-27

## Result

The compatibility inventory now has a deterministic reviewed overlay for all
217 pointer-operator candidates and both custom FFI calls.  This closes the
source-triage portion of G3/G4; it does **not** close either semantic gate.

The selected direct S3 source route contains 15 pointer tokens:

| Disposition | Count | Evidence-backed meaning |
|---|---:|---|
| confirmed non-reference identity incompatibility | 12 | ten structural-sharing controls and two identity-filter predicates |
| confirmed immediate-int incompatibility | 1 | `count_terminals` int compared with `1` |
| equivalent after local name resolution | 2 | binding/use of theorem-producing `eq_eq` |

The other 202 records are explicit selected-route exclusions.  They remain in
the inventory and receive semantic classifications; they are not asserted to
be dead in other HOL Light workflows.

G3 therefore remains open for remedies and proofs, but the two relevant
divergence classes are confirmed.  OCaml 4.14.1 accepts and passes minimized
list `==`, list `!=`, and int `==` forms.  The pinned Candle binary reports:

- list `==`: a type mismatch because its built-in operator has type
  `'a ref -> 'a ref -> bool`;
- list `!=`: `Impossible: nRelOp`, followed by a parse failure;
- int `==`: the same reference-only type mismatch.

The local `(==)` shadowing oracle succeeds in both systems, so the
theorem-producing `eq_eq` use is not misclassified as pointer identity.  A
verified implementation or individually justified source transformations and
regressions are still required for the 13 built-in selected uses.

## FFI reachability and current contracts

`candle/chdir_to_root.ml:14` calls `customFFI "chdir"`.  The build script
appends that file to `candle_boot.ml`, and line 17 invokes it immediately.  It
is therefore required for every selected compiled-Candle startup.

`candle/ocaml.ml:294` calls `Cake.Runtime.customFFI "system"` inside
`Sys.command`.  The selected full Flyspeck sequence loads the LP certificate
reader and `tame/linear_programming_results.hl`; verification enumerates the
tracked `formal_lp/glpk/binary/hard_7.tar.gz`, so the compressed reader executes
`tar` and cleanup through `Sys.command`.  This is a required runtime call, not
merely a loaded but dormant definition.

The minimized selected Candle success path for `Sys.command "exit 7"` returns
7.  G4 nevertheless remains open.  The current C patch relies on assertions and C-string
assumptions; `system` delegates to an unrestricted host shell and inherits
PATH, environment, and filesystem effects.  Separate ledger entries now record
ABI encoding, error conventions, totality gaps, sandbox duties, and the
unverified C/syscall/shell/tool trust boundary.

## Reproduce

```sh
scripts/update-compatibility-inventory.sh /project/repos
scripts/check-compatibility-ledger.sh /project/repos
python3 scripts/test-inventory-compatibility.py
python3 scripts/test-compatibility-triage.py
python3 scripts/test-compatibility-ledger.py
ocaml -noinit -noprompt compatibility/oracles/pointer_identity_ocaml.ml
```

The update command regenerates the lexical inventory first, then applies
source-coordinate review rules.  Generation fails if a finding has zero or
multiple rules or if either FFI call moves.  Validation independently checks
the inventory digest, schemas, all 217/2 joins, aggregate counts, reviewed
source coordinates, FFI reproducer presence, ledger selectors, and exact
affected-file enumerations.

## Remaining limitations

- The selected-route status is source-backed against the explicit loader/full
  sequence; it is not a substitute for the still-open complete loader DAG G6.
- Two selected identity-filter predicates retain medium-confidence high-level
  intent; no structural-inequality rewrite is authorized by this triage.
- The `system` success path and boot-time `chdir` success are observed, but
  malformed, failure, signal, environment, and sandbox cases are untested.
- No runtime ABI/refinement theorem, total validation, sandbox implementation,
  fuzzing, or stable regression ID is claimed.
