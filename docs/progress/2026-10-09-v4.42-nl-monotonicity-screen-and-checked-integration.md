## Interpretation and plan change

This is a useful negative result.  A generic monotone-face wrapper around the
current case16594 whole-box gradient does not reproduce the historical C++
derivative-pruning effect.  The failure is informational rather than
arithmetic: the unresolved nodes expose no sign-definite coordinate through
this enclosure, so a faster scalar backend would not make the proposed
restriction applicable.

The result does **not** show that derivative pruning is useless throughout
Flyspeck.  It shows that proof work for this generic restriction is not
justified on the present forest.  The reference C++ result used specialized
derivative routines and a different search instance.  Any further pruning
experiment must first reproduce that distinguishing information rather than
adding another generic wrapper.

The revised larger-gap plan is:

1. keep the primary implementation effort on the checked historical
   whole-box operation, because the exact factorial already demonstrated an
   8.48-times algorithm/search effect;
2. before another pruning implementation, extract a sign-coverage census from
   an authenticated fixture on which the historical derivative toggle is
   known to change visits;
3. if needed, port one source-specific historical derivative enclosure in
   native code while holding arithmetic and rounding fixed, and require it to
   recover material sign coverage and a complete-search improvement;
4. stop that path before proof work if it does not predict at least a
   substantial recurring benefit; and
5. after the winning low-work operation is checked, remeasure the independent
   encoded-Candle/native boundary with preparation and theorem handoff charged.

Thus the original roughly 15-times Candle/native gap and the roughly
340-times starting native-generic/specialized-C++ gap remain separate
diagnoses.  The current exact measurements attribute a large part of the
second gap to numerical work and search, but this screen rejects one cheap
attempt to recover additional search pruning.
