## Method

Every selected source node was resolved by its manifest SHA-256, not merely by
whatever bytes happened to be present in a dirty worktree.  Flyspeck files were
read from the pinned Git object.  Candle files were accepted from the worktree
only when their digest matched; otherwise the manifest-bound Git bytes were
used.

The scanner counted paths of the form
`Capitalized.Module.UPPERCASE_OR_MIXED_TERMINAL`.  It excluded nested OCaml
comments, string literals, and HOL backtick quotations, and did not count an
intermediate module prefix when the path continued to a lowercase value.  The
classification is lexical plus source-context analysis, not typed inference.

## Root cause and branch audit

This is an interaction regression introduced by the Dopen integration, not a
long-standing absence of qualified value parsing.

Before CakeML commit `29c4d2c94a2cd39593507b8f319832e0ef907b2d`, a
module name used the narrow `identUpperLower` predicate.  In the old
`nValuePath` rule,

```text
(nModulePath ".")? nValueName
```

the path parser therefore stopped before `EQ_MP`, which is not
`identUpperLower`, and the terminal was correctly accepted as a value.  Commit
`29c4d2c94` correctly broadened grammar-context module identifiers to
`identModule` so Dopen could accept singleton and internally-capitalized module
names.  The greedy `nModulePath` can then consume `Kernel.EQ_MP` wholly as a
module path, leaving no terminal value and causing the expression parse to
fail.

The pre-Dopen `upstream/master`, `codex/flyspeck-v13-actions`, and
`codex/flyspeck-v13-actions-float` refs retain the narrow behavior and are
useful differential anchors.  The Dopen and integration refs contain the
regression.  No committed CakeML ref, Candle fix-top100/PFT/merge anchor, or
Flyspeck normalization supplies a general repair.

CakeML commit `2b425ca87ef1b155f76a8396ce4b6494453db01f` repaired the
identical ambiguity for qualified constructor paths with a right-recursive
grammar.  The minimum corresponding value-path repair is:

```text
value-path ::= module-name "." value-path | value-name
```

with a matching recursive `ptree_ValuePath` conversion.  At audit time an
uncommitted candidate implementing that change existed on CakeML integration
HEAD `0c170aa374ec178e5db8a9fe9276244ed7e0dcf7` in only:

- `compiler/parsing/ocaml/camlPEGScript.sml`;
- `compiler/parsing/ocaml/camlPtreeConversionScript.sml`; and
- `compiler/parsing/ocaml/camlTestsScript.sml`.

Its focused tests included a multi-component
`Aa.B_b.POLY_ASSUME_TAC` path, the `Kernel.EQ_MP` expression, and a
`let f = Kernel.EQ_MP` definition.  That candidate is structurally analogous
to the established constructor repair, but analogy and local source review
are not proof or runtime evidence.  Its proof build and all downstream gates
remain **pending**.

## Why a source-open workaround is forbidden

Replacing the ten kernel aliases with `open Kernel` is not an acceptable
promotion fix:

1. It deletes the first trigger instead of repairing the parser regression.
   The next trigger remains in `strictbuild.hl`, followed by 12,449 surviving
   value occurrences across the selected route.
2. It changes an authenticated source node.  Until every manifest, digest
   table, plan, and artifact is deliberately regenerated, it breaks the exact
   source contract.
3. It makes a parser gate circular: a binary tested only against the edited
   source can pass without ever parsing `Kernel.EQ_MP`.
4. A module open imports the whole namespace and can alter shadowing and name
   resolution.  That is materially broader than preserving ten explicit
   aliases.
5. Per-file opens or rewrites across 216 executed files would be an
   unauditable source fork and would obscure whether the verified parser
   supports the selected corpus.

The original kernel bytes have been restored and again hash to
`6ef26962e67f7e5e647074af8864800b5765a51c792ac58eaf3d6352f688c206`.
They must remain in the positive parser/bootstrap gate.  A source-open variant
may be useful only as a clearly separated diagnosis; it cannot count toward
promotion.

## Required promotion gates

The parser candidate must not be promoted until all of the following are
green and bound to the same final coordinates.

1. **Verified parser proof build.** Build the affected OCaml parser and parse
   tree conversion theories from the candidate CakeML commit.  Require no
   cheat, admission, new axiom, or unchecked theorem constructor and retain
   the complete build transcript and resource receipt.
2. **Positive parser unit gates.** Require exact AST results for a single
   component uppercase value, `Kernel.EQ_MP`, the real definition phrase,
   and a multi-module uppercase terminal.  Retain the existing lowercase and
   mixed-case value-path tests.
3. **Constructor and fail-closed gates.** Preserve qualified constructor
   parsing for `Ab.Cd`, `Text_io.Bad_file_name`, and expression-level
   `Pretty_printer.Pp_data`; preserve nested lower-value parsing such as
   `Pretty_printer.Text_io.stuff`; and reject malformed paths.  The five
   selected constructor-bearing files remain a bounded regression corpus.
4. **Dopen differential gate.** Show the pre-Dopen anchor accepts
   `Kernel.EQ_MP`, the unpatched Dopen coordinate exhibits the diagnosed
   failure, and the candidate accepts both the qualified-value fixtures and
   the existing Dopen corpus.  Qualified-value support must not be purchased
   by weakening Dopen or module-name support.
5. **Clean bootstrap and artifact provenance.** Finish the CakeML bootstrap,
   link Candle only from the proved candidate, and bind the executable to that
   exact CakeML commit.  A host parser test or an old cached executable is not
   evidence for the new grammar.
6. **Original-source runtime gate.** Feed the exact manifest-bound kernel
   bytes containing all ten `Kernel.UPPERCASE` aliases, then advance through
   pinned `strictbuild.hl:157`, and then through action 7
   `leg/basics.hl`.  Each boundary must fail on parse, inference, evaluation,
   source-identity, or error-marker drift.
7. **Manifest and normalization integrity.** Reproduce the raw and effective
   corpus inventory against the final manifest, authenticate every selected
   source and normalized output, and prove that no source-open or equivalent
   hiding rewrite entered the route.
8. **Broader replay remains downstream.** Only after the narrow gates pass may
   the normal stratum replay and eventual full Flyspeck run use this parser.
   A successful parser proof or bounded bootstrap alone does not close S2,
   S3, or the overall Flyspeck project.

Current state: the candidate parser change, its proof build, its bootstrapped
