## Action 159 diagnosis

The normalized `constants_approx.hl` reaches its interval square-root helper
and calls `Int64.to_string (Int64.of_float n)`. Candle had no `Int64` module,
so this is an OCaml runtime compatibility omission rather than a theorem,
tactic, parser, search-order, or Flyspeck source defect.

No `Int64` implementation or patch exists in `fix-top100` or the relevant
Candle branch history. A mechanical scan of the complete pinned Flyspeck tree
finds exactly five used members: `of_float` and `to_string` at the current
boundary, `to_string` in `formal_lp/more_arith/prove_lp.hl`, and `of_int`,
`shift_left`, and `logor` in the later LP binary-certificate reader.

The isolated `codex/v59-ocaml-int64` candidate implements exactly those five
members using CakeML's 64-bit word operations. Signed rendering uses
`Cake.Word64.toIntSigned`; shifts and disjunction remain modulo 2^64. Negative
OCaml integers are converted by word subtraction from zero so the
implementation does not rely on `Cake.Word64.fromInt` outside its proved
natural-number domain. The candidate is commit
`5cf688b6bebe8454f670d4be62d87799582d82b4`.

A shared OCaml/Candle fixture covers truncating positive and negative float
conversion, negative integer conversion, signed minimum, left-shift
wraparound, bitwise disjunction, and signed decimal rendering. The native
OCaml 4.14.1 oracle passes. All 18 normalization tests, all 28 manifest tests,
and the independent 297-root/400-source/43-generated-input manifest fixed-point
check pass. The manifest authority records the exact five-member supported
