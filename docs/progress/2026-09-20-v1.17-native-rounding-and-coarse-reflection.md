## Proved directed-radix computation

verified-compute program for lower and upper directed radix rounding. It proves
ordinary representation correspondence and the directional theorems

```text
FST (round_lo ...) * radix ^ SND (round_lo ...) <= n * radix ^ e
n * radix ^ e <= FST (round_hi ...) * radix ^ SND (round_hi ...)
```

compression only: exhaustion returns the exact remaining mantissa and does not
weaken soundness. The fresh-state suite passed in 2:06.86 with 1,089,536 KiB

## Focused measurement changes the integration granularity

The development runtime's `Unix.gettimeofday` is deterministic zero, so the
focused comparison used process CPU ticks from `/proc/<pid>/stat`; the host's
`CLK_TCK` is 100. Both paths ran warm in the same Candle state on the same raw
base-200 `num_exp` value, a 60-decimal-digit mantissa, exponent 37, and
precision 8. The conclusions had already been checked equal.

| Path | Repetitions | User ticks | System ticks | CPU seconds | CPU per call |
|---|---:|---:|---:|---:|---:|
| Legacy `Arith_float.num_exp_lo` | 10,000 | 211 | 0 | 2.11 | 0.211 ms |
| Reflected `cv_num_exp_lo` | 1,000 | 2,661 | 11 | 26.72 | 26.72 ms |

At this granularity reflection is approximately **126.6x slower per call**.
The result is compatible with the earlier `compute_all` finding: one
`Kernel.compute` call plus representation and theorem handoff is too expensive
for a tiny operation that already has a specialized proof conversion.

This rules out globally replacing every directed rounding conversion. The
proved adapter remains useful machinery and an oracle for a coarser program,
but the performance target must move outward to one complete multiplication,
interval/Taylor step, or certificate-checking batch per compute call. That is
also consistent with the accepted 3.66x--9.87x gains from bulk LP construction
slices.
