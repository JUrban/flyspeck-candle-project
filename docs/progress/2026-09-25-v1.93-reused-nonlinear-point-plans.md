## Target

The v1.86 preparation profile found that generating seven exact square-root
proposals independently for every action-296 box still cost 10.383 seconds for
eight boxes after discarded proof-producing rational reduction had been
removed. Each call walked and decoded the same large HOL source terms again.

The v1.92 research-note assessment therefore identified a narrow reusable
target: compile the seven rational square-root argument expressions once per
authenticated source, then evaluate only ordinary exact data at each center.
This optimization remains outside the trusted proof boundary. Every proposed
interval is still checked against the original expression by the unchanged
reflected program and universal soundness theorem.

## Reusable exact point plan

The point-certificate module now has a small untrusted representation of its
existing supported rational fragment:

```text
constant, indexed variable, negation, addition, subtraction,
multiplication, division, inverse, and natural power
```

The certificate-variant layer:

1. traverses the authenticated source once in the existing square-root order;
2. extracts and compiles the seven square-root arguments;
3. records the source function and source term with the plan;
4. checks both logical identities before a plan can be reused; and
5. evaluates the seven programs on exact rational centers for each new box.

The direct term evaluator remains available as an oracle and fallback. The
plan changes neither the proposed interval format nor any checked equation,
guard, theorem interface, source expression, or rounding policy.

A focused regression compared both ordinary evaluators with
`REAL_RAT_REDUCE_CONV` on all nine supported operation shapes. All 18 direct
and compiled results matched the proof-producing oracle, and the axiom set was
unchanged.

The one-time plan cost was 1.250--1.251 seconds. Shared whole-box source
preparation, measured separately, was 4.795--4.958 seconds.

Against the already optimized v1.86 results:

- charging the plan once, 64-box preparation fell from 126.661--128.243
  seconds to 47.511--47.623 seconds: **2.66--2.70 times faster**, a
  **62.4--63.0% reduction**;
- plan plus 64-box preparation plus the complete checked batch fell from
  299.253--302.916 seconds to 228.421--228.898 seconds: **1.31--1.33 times
  faster**, a **23.5--24.6% reduction**; and
- relative to the original 521.421-second path before the v1.86 untrusted
  arithmetic repair, that recurring total is now about **2.28 times faster**,
  a **56.1% reduction**.

The numerical checker was intentionally unchanged. Its 161.3--161.9-second
64-box time is consistent with the earlier 154--161-second run range and is
not attributed to this preparation change. It is now decisively the largest
single recurring phase.

## Revised next costs

The research note's preparation diagnosis has now yielded two cumulative,
retained improvements: eliminating discarded proof-producing arithmetic and
reusing the compiled point arguments. The remaining 64-box preparation is
about 46 seconds, mostly per-box proof-producing program compilation and
encoding. Removing that cost would require the larger, already identified
interface change in which one shared compiled source program consumes
certificate intervals as checked data.

That change remains plausible, but the immediate measured priorities are now:

1. the approximately 161-second reflected numerical computation, for which a
   whole-algorithm fixed-scale discriminator is the next bounded experiment;
2. the remaining 46-second per-box variant compilation, if a shared
   certificate-data interface can remove it without duplicating the existing
   soundness architecture; and
3. the approximately 19-second batch wrapper above the numerical call.

The plan optimization is retained because it is exact, source-bound,
independently checked, materially faster at scale, and leaves the general
analytic theorem unchanged.
