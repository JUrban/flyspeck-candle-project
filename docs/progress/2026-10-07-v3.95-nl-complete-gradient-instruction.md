## First complete actual-data instruction

`grad(delta)`:

```text
-2*x0*x3 + x1*x3 + x1*x4 - x1*x5 + x2*x3
- x2*x4 + x2*x5 - x3*x3 + x3*x4 + x3*x5
```

It executes on all 875 authenticated case16594 boxes.  Each batch performs
8,750 interval products, 17,500 directed endpoint products, and 19,250 checked
signed additions.  Every product uses the proved radix-22 full-word product
and exact directed `2^40` shift; accumulation uses the proved canonical
signed comparison/subtraction/addition layer.

Malformed box and product-list lengths return `NONE`.  Every arithmetic
overflow also returns `NONE`.  An early exact-list implementation translated
with shape preconditions; it was replaced by explicit total deconstruction.
The final gradient, batch, and closed digest-check functions translate with
**no preconditions**.

## Keeping both larger gaps explicit

The two historical observations remain distinct:

1. the encoded/verified-execution boundary was roughly 15 times on the earlier
   matched operation and is **30.60 times** on this lighter complete
   instruction; and
2. the original generic fixed-scale/specialized-C++ comparison was roughly
   340 times.  Later case10173 native specialization reduced that fixture's
   residual to about 1.35 times, but this does not erase the architectural
   lesson.  On case16594, the still-unintegrated reflected batch is about
   225.8 seconds versus 0.776 seconds for the latest exact native target,
   roughly **291 times** across algorithm, representation, executor, and
   handoff together.

The latest 2.743-times native factorial and 30.60-times matched instruction
ratio allocate parts of that cross-layer gap without pretending that either
is the complete answer.

## Bounded forward plan

1. Keep the present analytic proof packet bounded to the authenticated delta
   families.  Do not prove the previously rejected inverse-root/whole-chain
   variants.
2. Run one allocation/data-flow discriminator on this exact verified
   instruction: keep arithmetic and outputs fixed while replacing the
   intermediate product and signed-sum lists with a flat fused accumulator.
   This directly tests a plausible cause of the 30.60-times executor gap.
3. If that wins materially, use the same total flat representation for the
   complete authenticated delta graph and return only final bounds/verdict.
   If it does not, stop local tuning and measure the full compact graph as-is.
4. Execute the complete 875-cell verified verdict and charge input
   preparation, recurring execution, exact fallback, theorem handoff,
   required repeats, and memory against 22.58 seconds and 875/875 acceptance.
5. Transfer a winning instruction/executor design to the structurally
   different case10173 family before expanding universal instruction proofs.
   Continue native exploration only for a genuinely different enclosure
   algorithm or second family, not another case16594 scalar variant.

This keeps the specialization proof small while directing the larger effort
at the now-measured executor boundary and preserving algorithm/enclosure
quality as an independent native research lane.
