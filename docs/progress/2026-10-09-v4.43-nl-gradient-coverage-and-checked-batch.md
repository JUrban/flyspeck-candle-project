## Source-specific gradient-coverage discriminator

The negative case16594 screen left one narrow question: did it fail because
monotonicity is unimportant, or because the generic derivative enclosure had
lost the source-specific information used by the historical verifier?

A new native profile answers that question on all **4,173 genuine case10173
certificate boxes**.  The two lanes hold fixed:

- the exact authenticated 54-instruction source and job set;
- exact 128-bit fixed-scale dyadic arithmetic and directed rounding;
- reconstructed boxes, tight square-root certificates, source-DAG caching,
  final Taylor completion, and sign-aware interval multiplication; and
- all input parsing and reusable preparation.

Only the derivative/enclosure graph changes.  The control uses generic
whole-expression jet composition.  The candidate uses the source-derived
historical dihedral operation.  The profile records whether at least one
coordinate derivative is sign-definite over each genuine box.

Seven warmed, order-balanced repetitions give:

| Lane | Boxes with a sign-definite coordinate | Fraction | Accepted boxes | Evaluation | Fully charged batch |
|---|---:|---:|---:|---:|---:|
| Generic composition | 476/4,173 | 11.41% | 96/4,173 | 1.091116 s | 1.280105 s |
| Historical operation | 2,342/4,173 | 56.12% | 4,173/4,173 | 0.703495 s | 0.892161 s |

The historical derivative graph exposes a sign-definite coordinate on nearly
five times as many boxes and is **1.55 times** faster in the fixed native
batch.  It also accepts the complete certificate where this deliberately
coarse generic whole-box path accepts only 96 boxes.  No box has all six
coordinates sign-definite; the information is for face restriction, not a
global constant verdict.

This result explains the prior negative screen: the cheap generic wrapper was
missing the useful information.  It is consistent with, but does not itself
reproduce, the historical C++ search result in which derivative pruning
reduced visits from 8,896 to 5,334.  A future search-level experiment should
therefore consume these source-specific derivative bounds.  There is no case
for proving the rejected generic wrapper.

## Concrete larger-gap plan

The next work is split deliberately:

1. **Search/enclosure axis.**  Use source-specific historical derivative
   bounds in an authenticated case10173 search or reconstructed search forest.
   Hold arithmetic fixed and require complete acceptance plus a material
   reduction in visits.  The 56.12% sign-coverage result justifies this one
   bounded experiment.
2. **Matched checked-execution axis.**  Compile the authenticated case10173
   compact historical plan to the existing bounded-word/fixed-layout
   substrate.  Reuse its proved carries, products, directed shifts, checked
   overflow, exact fallback, packed input discipline, and compact verdict;
   do not add another generic cval interpreter or re-prove those primitives.
3. **Held representation comparison.**  Run the encoded `Kernel.compute` and
   compiled bounded-word lanes on the same 128 genuine jobs first, then the
   full 4,173-box batch.  Authenticate identical boxes, roots, source plan,
   scale, and final bounds so the result isolates encoded evaluator and data
   representation cost from mathematical work.
4. **Proof gate.**  Extend the historical quotient/atan analytic proof only
   after that matched candidate materially improves the complete batch.  The
   completed universal square-root theorem supplies the first reusable
   analytic case; the existing bounded checker supplies the execution
   machinery.
5. **Decision gates.**  Require all 4,173 case10173 boxes to accept, record
   cold preparation, input conversion, recurring execution, exact fallback,
   compact theorem handoff, total elapsed time and peak memory, then confirm
   any new reusable instruction on the independent case16594 family.  A local
   microbenchmark is not sufficient.

This keeps the current specialization useful and bounded while pursuing the
orders-of-magnitude objective.  The native gradient result argues for richer
source-specific numerical instructions; the checked batch argues for moving
them onto the already successful bounded-word/fixed-layout execution route.
