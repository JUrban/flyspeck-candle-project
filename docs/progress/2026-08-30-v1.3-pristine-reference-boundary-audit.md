# Pristine direct-reference boundary audit (2026-08-30)

## Decision

Do not implement the pristine OCaml/HOL Light runner against the current
three-way fixture unchanged.  Its single equality condition requires the
compiled candidate and both pristine references to have byte-identical
semantic and detailed **coverage-v1** projections.  Semantic equality is the
right cross-runtime oracle boundary, and a new disjoint cross-runtime
**coverage-v2** projection is also required.  Coverage-v1 is not a sound
cross-runtime boundary: it preserves Candle-specific loader request nesting,
cache outcomes, four Candle control keys, action load/skip outcomes, and
execution-normalization records.

Forcing pristine HOL Light to synthesize Candle's internal physical trace
would make the reference less independent and could report equality created
by the adapter rather than observed in the reference runtime.  The release
protocol must instead separate:

1. three-way semantic and coverage-v2 equality among one authenticated
   compiled result and two nonce-distinct pristine reference runs;
2. exact detailed coverage-v1 equality among the two clean compiled runs and
   the later qualified resume result.

Both remain unapproved until their disjoint authenticators and later approval
validators run.  PFT is forbidden in both lanes.

## Evidence for the split

The common semantic projection is intentionally runtime-neutral.  It contains
only the exact serializer, four ordered theorem identities, structural
post-state, and four ordered `Serialization.full_digest_thm` dependency
records.  The existing `candle/fingerprint.ml` already runs under the pinned
HOL Light reference, and the final reference request can load the same
`candle/flyspeck_l2_target.ml` before observing
`Candle_flyspeck_l2.tame_imp_kepler_conjecture`.

Coverage-v1 has different semantics.  Its physical part retains every loader
request/outcome pair, parent nesting, request/cache-skip counts, and exact
top-level controls:

- `control:runtime-setup`;
- `control:instrumented-prefix`;
- `control:stratum-check`;
- `control:postlude`.

The pristine runtime instead initializes through `hol.ml`, Flyspeck
`strictbuild.hl`, and the OCaml `needs`/`loadt`/`flyspeck_needs` closures.
Those closures preload files and maintain a different cache and call graph.
Even when both runtimes execute the same mathematical source closure, exact
physical event equality is neither expected nor a useful semantics claim.

Coverage-v2 must retain only facts that all three runtimes can independently
derive from their authenticated plans and observations:

- the final boundary, all 297 ordered action identities, and successful
  completion observations; Candle-specific `load`/`skip-ledger` outcomes stay
  in coverage-v1;
- the exact authenticated 400-node original-source inventory, separately
  from the runtime's executed/selected closure;
- original identities and explicit execution-mode/selected-normalization
  identities, without claiming that pristine OCaml executed Candle's overlay;
- the exact selected logical-key closure, excluding Candle control keys,
  loader nesting and cache outcomes;
- all 43 generated inputs and the nonlinear, LP, and final-premise completion
  facts;
- the 39 canonical certificate identities and an exactly-once successful
  deserialization fact for every certificate; and
- `pft_used = false`.

Each raw candidate must retain its role-specific physical trace, event order,
cache behavior, and control inventory outside coverage-v2.  This keeps the
common equality strict without manufacturing Candle events in OCaml.

The v1.3 release criterion already requires two clean compiled full runs plus
one matching resume.  Those are the correct consumers of coverage-v1 because
they share the same loader, normalization, generated-input, and
certificate-consumption protocols.

## Smallest sound reference producer

The future pristine producer should be a new exact-source CLI rather than an
extension of the Great100 sweep schema.  Each run must:

- authenticate a clean project collector/validator checkout, pristine HOL
  Light checkout, pristine Flyspeck checkout, exact full plan, serializer,
  generated inputs, OCaml runtime/stublibs, GP/CSDP tools, and ELF closure;
- start a fresh `ocaml-hol` process with a 256-bit session nonce and a sanitized
  one-thread environment; no checkpoint, PFT input, inherited loader override,
  or modified Git source tree is allowed;
- execute the exact original Flyspeck build sources under reference-only
  instrumentation with `FLYSPECK_SERIALIZATION` absent, retaining the request
  source and complete transcript;
- observe all four final theorems and structural post-state through the common
  serializer, followed by the four dependency-history digests;
- record a reference-specific source/build closure and exactly-once successful
  reads of the same 39 LP certificates, and bind the authenticated Candle
  normalization identities without claiming to execute that overlay or
  relabelling the observation as Candle's physical source trace;
- emit an unapproved, PFT-false reference descriptor only after replaying its
  raw plan/request/transcript and reauthenticating all sources and runtime
  authority.

The two runs must have distinct nonces, transcripts, and candidate content
digests while using the same exact validator project commit, reference runtime
commit, entrypoint, source inventory, plan content record, tool closure, and
serializer.  Candidate bytes alone never authenticate a run; the production
comparator must replay the pinned reference CLI twice against both retained raw
bundles.

## Reusable implementation

The v9 S1 reference collector is useful for provenance patterns, not as a
schema to widen.  Reusable concepts include clean-Git authentication, runtime
and stublib pinning, OCaml/findlib library-tree inventory, GP/CSDP and ELF
closure, sanitized fresh-process invocation, session/complete markers,
retained request/transcript hashes, structural-v2 parsing, and post-run plan
reconstruction.

The direct runtime provides the common theorem-name order, serializer and
dependency-history marker formats, exact 297-action plan, 43 generated-input
inventory, and 39-certificate identity set.  Its CakeML source-trace event
stream and `Cakeml.configureSourceTrace`/`requestSourceTraceFinish` controls are
not reusable as pristine-reference observations.

For LP evidence, the original Flyspeck runtime defines
`Lp_certificate.read_lp_certificates` before `Verify_all` consumes it.  A
reference-only wrapper can call the original function, emit an event only
after successful deserialization, and require the exact authenticated 39-file
set.  Raw OCaml directory enumeration order need not equal Candle's selected
event order; the reference validator must retain raw order and derive canonical
certificate identities plus exactly-once successful-deserialization facts for
coverage-v2.  Exact event order and event identifiers remain in coverage-v1.

## Required protocol repair before runner code

The comparison descriptor and report schemas need role-specific evidence:

- the compiled descriptor retains its strict semantic projection, detailed
  coverage-v1, and cross-runtime coverage-v2;
- each pristine descriptor carries the common semantic projection,
  cross-runtime coverage-v2, and a reference-specific execution-closure record
  authenticated by its own CLI;
- the reference comparison requires exact three-way semantic and coverage-v2
  equality plus exact reference-plan/serializer/authority agreement, but does
  not claim cross-runtime physical-trace equality;
- a later compiled qualification record separately requires coverage-v1
  equality for two clean compiled candidates and one resumed candidate.

The comparison status must say
`three-way-semantic-and-cross-runtime-coverage-match-unapproved`, not
`three-way-exact-match-unapproved`.  All approval and promotion fields remain
false.  This repair needs hostile tests for missing or reordered actions and
source inventory, normalization relabelling, copied Candle controls, loader
bypass, missing/duplicate/reordered LP observations, serializer/dependency or
fourth-theorem omissions, authority drift, nonce or transcript reuse, raw
bundle splicing, PFT paths, and any attempt to treat comparison as S2/S3
approval.

## Next implementation order

1. Define and hostile-test the independently derivable cross-runtime
   coverage-v2 schema before changing either candidate descriptor.
2. Repair the role-specific descriptor/comparison fixture and obtain an
   independent hostile rereview.
3. Define a strict reference raw plan/candidate schema and transcript parser on
   tiny full-boundary-shaped fixtures.
4. Implement fresh-process reference collection with exact source/runtime/tool
   authority and common semantic observation.
5. Add reference-specific source/build and LP-read closure, mutation tests, and
   retained raw-bundle replay.
6. Run two tiny pilot references before authorizing either full pristine run.
7. Only after a real compiled schema-6 candidate exists, run the two full
   pristine references and the unapproved semantic-and-coverage-v2 comparator.

This audit changes no release status.  No pristine direct reference candidate,
semantic comparison, direct coverage approval, S2, S3, or release approval
currently exists.
