## What is and is not the same checker

The earlier **2.07-second** direct-`cake` executable and the 388--412-second
reflected runs were not two execution mechanisms for the same function.

The direct executable checks the specialized historical box operation.  For
each cell it parses six box intervals, two primary root certificates, nine
reciprocal certificates, and 28 expected value/gradient/Hessian intervals. It
recomputes the specialized second-order historical dihedral jet and compares
those 28 results.  It does not run the center computation, four-root record,
complete production guard, authenticated source patches, unchanged program
suffix, final Taylor verdict, or original-theorem handoff.

The complete reflected gate performs all of those additional operations on
the original encoded job stream.  It uses arbitrary-precision `cval` data and
the generic Candle compute equations.

There is also no interpreted-versus-compiled dichotomy at the exact reflected
boundary.  Candle's `Kernel.compute` invokes the compiled CakeML `exec`
engine.  Its surrounding work validates equations and the closed source term,
converts them to the generic executable representation, runs `exec`, converts
the result back to a HOL term, and returns an assumption-free equality
theorem.  The external 2.07-second program instead executes a separately
translated, specialized word-level function.

Accordingly, the direct executable remains a useful lower-level performance
result, but its ratio to the exact gate is not a same-checker speed ratio.

## Interpretation and production route

The stronger root/domain contract is not measured as the explanation for the
gap: those checks are included in the 200.318-second discriminator, but this
experiment does not remove them individually.  The measured conclusion is
narrower and firmer:

1. old 388--412-second wall totals mixed restore, fragment loading, fixture
   construction, warm-up calls, the full computation, and machine load;
2. the current exact full computation itself is about 212 seconds in this
   run;
3. only about eleven seconds of that is attributable to full-input traversal
   and equality-theorem packaging under the matched control; and
4. a substantial execution gap therefore remains between the generic `cval`
   checker and the specialized word implementation, in addition to the
   specialized executable's currently smaller contract.

The intended production path is still the specialized compiled checker, but
only after it has the complete contract: center and box computations, four
authenticated roots, every production guard, suffix/Taylor acceptance,
canonical job/source identity, and the topology/original-theorem connection.
Its general word-level soundness theorem must then be connected to execution
by a proof-producing evaluation route or by a compact execution certificate
checked inside Candle.  Compiler correctness plus observed stdout is not an
LCF theorem.

The current reflected route is therefore the exact correctness/integration
oracle and can deliver the first original theorem in minutes.  It is not the
desired recurring production engine once the complete compiled checker and
trusted verdict bridge are finished.  Building a new external wrapper for
the generic `exec` call would duplicate the mechanism already running inside
Candle and would not close that trusted bridge, so this bounded experiment did
not open that side project.
