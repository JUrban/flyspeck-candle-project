## Correction to the development loop

The project's append-oriented long-run hazard database is now explicitly the
pre-mortem as well as the retrospective record.  Before any run with a declared
maximum above 1,800 seconds, every observed and newly credible failure mode
must have a cheap executable discriminator.  An anticipated hazard without a
check blocks admission exactly as an observed failure does.  Receipts bind the
exact controller, ledger, sources, predecessor, and runtime; changing those
bytes invalidates the earlier admission.

This is deliberately stronger than an hour threshold.  A 30--60 minute stage
is already an integration run, not an exploratory edit loop.  New defects must
be preserved in the ledger before retry, and the retry must first pass a cheap
faithful reproducer.  Passing the gate is not a prediction that the theorem is
true; it is evidence that we are not knowingly repeating an already understood
failure.
