## Question

The established fixed-algebraic evaluator calls
`candle_cv_fsa_program_has_nonlinear` on the remaining instruction suffix at
each program step and for every cell.  Could computing that schedule once from
the authenticated source program materially reduce recurring checking time?

## Conclusion

Repeated nonlinear-suffix scanning is not a material bottleneck in the current
genuine workload.  Removing it regressed rather than improved all three batch
sizes, presumably because the explicit schedule construction/traversal costs at
least as much as the inexpensive existing predicate at this program size.

No general equivalence proof or production integration is justified.  The
prototype remains isolated as a reproducible negative result.  Work should
return to costs that remain large in the measured profile, especially recurring
evaluator computation and compact proof/verdict handoff across the complete
certificate forest.
