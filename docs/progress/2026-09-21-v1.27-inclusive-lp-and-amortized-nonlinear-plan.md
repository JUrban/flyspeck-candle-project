## Nonlinear optimization is now judged by amortized total cost

The historical scale makes a larger reusable checker investment rational. The
Flyspeck paper reports more than 23,000 partitioned nonlinear inequalities,
about 5,000 processor-hours for the main run, and about 9,370 processor-hours
for an independent recheck. These measurements are historical context, not a
Candle forecast, but they rule out using a small standalone arithmetic call as
the sole decision criterion. See [A formal proof of the Kepler conjecture,
section 5](https://arxiv.org/abs/1501.02155).

The working cost model is now:

`T_total = T_checker_once + sum_i (T_normalize_i + T_setup_i + T_search_i +
T_adaptive_i + T_plan_i + sum_j T_leaf_ij + sum_k T_glue_ik + T_handoff_i)`.

The terms are measured in three operational classes:

| Class | Included work | Reuse target |
|---|---|---|
| Once per checker image | authenticated analytic closure, generic correctness theorems, computation-wrapper initialization, adapter load, clean checkpoint creation | all inequalities processed by fresh restores of the same checkpoint |
| Once per inequality | source normalization, symbolic function/derivative setup, informal certificate search, adaptive validation, split-plan materialization, final root handoff | all subdivisions of that inequality |
| Per subdivision/node | split-domain theorem, Taylor theorem, numerical derivative/Hessian bounds, leaf verdict, and partition glue | move the repeated numerical validity work behind a coarser verified call |

Wall time and processor time will be reported separately. A load paid once to
create a reusable checkpoint is different from a load repeated in every worker;
the latter must be multiplied by the bounded worker count. Break-even will be
reported as `T_checker_once / (T_legacy_repeated - T_new_repeated)`, not as a
microbenchmark ratio.

At 5,000 processor-hours, even four processor-hours of genuinely reusable
runtime preparation would require only about a 0.08% total reduction to break
even. This does not relax the proof boundary: all computed answers must still
be turned into the existing assumption/axiom-preserving Flyspeck theorem.

## Design consequence

The production nonlinear target is a coarse proof-producing verdict, not a
collection of faster arithmetic conversions.  A promising design may spend
substantial time once proving and loading a generic checker, provided each
inequality supplies compact authenticated data and each certificate avoids
rebuilding large ordinary validity proofs per subdivision. The final boundary
must still produce the existing root inequality theorem with the same
hypotheses and allowed axioms.

The next empirical decision is therefore based on the exact real leaf and
complete 16-leaf certificate profile. If ordinary per-leaf preparation remains
dominant while `Kernel.compute` remains negligible, the next prototype will
move rounding-plan validation and the complete leaf verdict into one proved
program and cross the ordinary theorem boundary once. If search or Taylor
construction dominates instead, optimization will move to that measured phase
rather than broadening the evaluator speculatively.
