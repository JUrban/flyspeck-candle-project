`cv-action296-stable-batch-prove-v2-debug-dev-001`. It exposed a narrow
implementation defect before a numerical verdict: the earlier focused test
used the convenience `compute` wrapper, which normalizes `LET_END`, whereas

## Reconstruction bottleneck and linear repair

The first successful proof-producing run was deliberately retained as a
matched performance discriminator. It exposed quadratic source-theorem
extraction: each requested cell independently rewrote the entire materialized
job list to establish `MEM` before applying the soundness theorem.

The replacement peels the accepted materialized list once. At each list node,
it obtains the head acceptance theorem and passes the tail acceptance theorem
to the next node. Source theorem statements, hypotheses, and digests are
unchanged.

| Phase | 1 cell | 8 cells | 32 cells |
|---|---:|---:|---:|
| Exact domain normalization | <0.001 s | 2.488 s | 11.065 s |
| Changing certificate data | <0.001 s | <0.001 s | 0.406 s |
| Proof-input preparation | 0.407 s | 2.235 s | 10.623 s |
| `Kernel.compute` | 2.081 s | 16.699 s | 73.577 s |
| Compact verdict handoff | 0.508 s | 0.406 s | 2.234 s |
| Linear source-theorem extraction | <0.001 s | 3.356 s | 17.183 s |

For the matched 32-cell extraction, the old implementation took 282.955
seconds and the linear implementation took 17.183 seconds: **16.47x faster**.
The complete matched run, including all three positive families, two negative
checks, interactive result printing, and harness overhead, fell from 446.786
seconds to 185.983 seconds: **2.40x faster**. Peak sampled RSS remained
2,253,704 KiB.

The 32-cell recurring path is now dominated by numerical execution rather than
certificate construction or theorem-list membership. In the canonical run,
the numerical call took 73.577 seconds, proof-input preparation 10.623
seconds, compact handoff 2.234 seconds, and final source reconstruction 17.183
seconds. The changing square-root certificate data itself took only 0.406
seconds.

## Cost boundary after this result

For a fixed expression, these costs are reusable:

- source reification and the universal analytic proof;
- the authenticated instruction skeleton;
- point-certificate plan compilation;
- whole-box certificate data where the enclosing parent box is shared; and
- the stable-batch support checkpoint during development.

The remaining recurring work is:

- exact domain extraction for new cells;
- inexpensive center certificate data;
- encoding the cell jobs into the proved reflected call;
- the numerical fixed-algebraic checker; and
- a now-linear theorem handoff for the cells whose ordinary source theorems
  are needed by the existing Flyspeck tree glue.

The 73.6-second numerical phase is therefore the next measured target for
arithmetic/evaluator work. The complete-inequality integration should first
establish the end-to-end baseline, however, rather than redesigning arithmetic
from this 32-cell sample alone.
