## Why the earlier width table was incomplete

The v3.70 profile covered interval operands, products, additions, quotient
operands/results, and converted inputs.  A later checked-128 smoke probe still
failed on job 0 after the known scale-squared recomposition was widened.  The
missing operations were the scalar Taylor accumulations surrounding the
interval graph:

- radius-weighted dot products;
- radius-squared Hessian accumulation;
- `2 * scale * linear + quadratic` error assembly;
- scale-squared center recomposition; and
- scaled gradient-bound assembly.

This packet rewrites those expressions into the same explicitly sequenced
integer operations and records the magnitude at every intermediate.  It does
not change association, rounding, bounds, or accepted results.

This is not a rare cold-path effect.  The case16594 batch executes:

150,228 completions, and 1,802,736 gradient-bound endpoints.  Preparation is
not being mistaken for recurring arithmetic here.

## Architectural consequence

The data now supports one bounded mixed-width prototype rather than another
guess:

1. retain checked 128-bit persistent endpoints and ordinary interval
   products/additions;
2. use an explicitly typed checked 192-bit accumulator for weighted Hessian
   sums, Taylor error assembly, center recomposition, and their directed
   quotient;
3. narrow only after the directed result has been checked to fit the endpoint
   type; and
4. return overflow as data and use the existing exact path as fallback.

The 192-bit complete-backend experiment showed no benefit because every one
of the tens of millions of small operations still paid the wider
multiprecision cost.  The proposed split instead keeps the hot 64--104-bit
interval operations in the narrower backend and pays for 192 bits only at the
measured accumulator boundary.

Observed widths do not constitute a universal proof.  The native prototype
must therefore preserve checked overflow and exact fallback, match the
checked-256 result records byte-for-byte on case16594, retain all acceptance,
and be tested on the complete second family.  Its gate remains total batch
time, including preparation and fallback.  Only a substantial recurring win
would justify a corresponding verified-word design.

This arithmetic work remains complementary to the flatter natural-number
`Kernel.compute` path targeting the separate 12--34-times verified evaluator
gap.
