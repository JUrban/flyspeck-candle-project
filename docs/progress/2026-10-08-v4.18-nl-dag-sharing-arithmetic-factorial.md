## The requested held-axis factorial

The v4.17 exact source DAG is the control graph.  The candidate computes once
per box the common delta center value, gradient, center Hessian, box Hessian,
and Taylor-reconstructed box gradient used by the three authenticated
coordinate-permuted angle blocks.  It then supplies those immutable data to
the existing specialized delta role evaluators.

Within each arithmetic backend the candidate retains the same instruction
graph, rounding boundaries, scalar kernels, Taylor completion, boxes, and
acceptance rule.  The second axis changes only mixed exact 128/192-bit dyadic
arithmetic to the existing padded-hardware discriminator.  The padded lane is
untrusted performance evidence, not a checker candidate.

## Decision

This candidate fails the materiality gate.  It is retained as isolated native
evidence and a possible future plan-lowering cleanup, but it receives no
standalone proof packet or complete checked-word integration.  The direct
dihedral-identity candidate remains bounded for the same reason.

The result separates the two questions cleanly:

1. arithmetic representation and rounding remain a larger cost than this
   particular generic-data duplication on the same graph; and
2. neither factor approaches the historical algorithmic difference exposed
   by the original specialized C++ verifier.

The historical roughly 340-times comparison remains a starting
generic-native/specialized-C++ warning, not a current case16594 residual.  The
current approximately 24-times verified/native boundary is also a different
problem: the DAG candidate has not yet been implemented as a proved Candle
instruction, so unmatched timings must not be divided to invent a new ratio.

## Concrete larger-gap plan

The next native algorithm packet changes a qualitatively larger unit of work:

1. port the historical specialized dihedral/tetrahedron enclosure for each of
   the three source-authenticated coordinate permutations, including its
   face-`U`, derivative, Hessian, and domain logic;
2. derive the permutations from the authenticated `(radicand, derivative)`
   roles and exact source expression, not from basenames or positional
   aliases;
3. first hold exact dyadic arithmetic fixed and compare the complete 875-box
   certificate with the DAG control, reporting time, operation counts,
   enclosure deltas, acceptance, and memory;
4. require all 875 cells and materially lower recurring and complete-batch
   cost before crossing the same specialized algorithm with padded hardware
   arithmetic;
5. compare subdivision/acceptance consequences rather than rewarding a fast
   but loose single-box calculation; and
6. require an independent genuine expression family before starting the
   reusable specialized-instruction soundness proof.

This keeps the current specialization proof effort bounded while continuing
the broader orders-of-magnitude investigation.  If the faithful historical
enclosure is also only incremental on case16594, the native algorithm lane
will have supplied a strong negative result and the main reusable investment
should move to the verified fixed-layout checked-word executor.  Preparation,
fallback, complete certificate compute, theorem handoff, total elapsed time,
and RSS remain the eventual production measures.
