## What was measured

The scan has two fail-closed stages.

1. It rejects a source immediately when the authenticated raw term contains
   a named operation that neither the current direct compatibility rewrite
   set nor the analytic language consumes.  This only avoids expensive work
   for a source that the current path certainly cannot reify.
2. Every surviving source is extracted with Flyspeck's own
   `Break_case_exec.simple_dest_ineq`, passed through the same expression
   definitions and inequality standardization used by the reflected
   fixtures, and structurally checked against the proved analytic language.

The scanner deliberately inspects the formula directly rather than rebuilding
the source's complete transformed domain theorem.  Domain reconstruction is
irrelevant to this language-coverage question and made the first diagnostic
attempt spend minutes before its first record.  No numerical certificate was
executed and no theorem/evidence artifact was changed.

## Interpretation and limitation

This is a **strict current-normalizer lower bound**, not a claim that only 33
Flyspeck formulas are supportable.  In particular, the raw parent of the
already developed case-10173 path contains `dih_x`; Flyspeck's proved
preparation step replaces it with the intended `dihatn_x` expression before
the reflected checker consumes it.  That successful path is therefore
outside the strict raw count.

The result nevertheless answers an important scaling question: full NL cannot
be obtained by merely replaying the present case-10173 reifier over all source
IDs.  The next coverage layer must inventory the **proved preparation output**
and distinguish:

- heads eliminated by reusable historical rewrite theorems;
- heads expressible in the existing universal analytic instruction set after
  such rewrites; and
- genuinely new numerical operations or specialized proved instructions.

The high-overlap `vol_x`/`gchi*`/`dih_x` families are the first useful target
for that prepared-form inventory and for the required second structurally
different production family.  The reusable packed-word/object refinement
also remains mandatory; the exact case-10173 ledger must not be scaled across
the corpus.
