`ad5ea719452deceaa4e7accb26996362fa7caad1` now contains a bounded,
authenticated direct-source workload for the first Flyspeck declaration-open

## Workload boundary

The preparation tool authenticates the exact Candle/Flyspeck manifest and clean
Flyspeck commit, all 13 normalized outputs and their receipt, the prepared
`hard_7.dat` input and receipt, the original strictbuild/Parser_verbose/Debug
sources, and the deterministic `date` and `whoami` inputs.  It then extracts
exactly 3,297 bytes from the normalized `build/strictbuild.hl`, with MD5
`bbc154a0b8e2637ce6f7227e95c73c34`, ending after these ordered actions:

```text
#flyspeck_loadt "general/parser_verbose.hl";;
#flyspeck_loadt "general/debug.hl";;
```

Preparation rejects any prefix containing `#flyspeck_needs`, so the gate cannot
enter the remaining strictbuild dependency graph or the generated 297-entry
full build.

## Compiled acceptance contract

The compiled process must emit, exactly once and in order, the preflight marker
and normalized select/load/complete markers for both actions.  It then requires
both logical source identities to be committed exactly once, no pending source
identity, and successful use of the resulting bindings, including
`Debug.parse_type_verbose "bool" = bool_ty`.  Any parser, inference, evaluation,
source-identity, action-order, digest, pin, or error-marker mismatch fails the
gate.

This is a real corpus-derived Dopen workload: `general/debug.hl` contains
`open Parser_verbose`, followed by unqualified uses of bindings exported by
that module.  It is therefore stronger than the synthetic Dopen smoke while
remaining deliberately bounded.
