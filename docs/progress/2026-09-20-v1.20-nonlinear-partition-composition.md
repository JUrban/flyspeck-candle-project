## Once-proved partition composition

Candle commit `15e0e131bd3ee869ac99e5a29fe9c99eaa52c48c` on
`codex/cv-taylor-bound-v1` adds a generic proof-producing partition theory. Its
tree has four constructors corresponding to the existing nonlinear
reconstruction:

- an analytic leaf;
- a two-child midpoint bisection;
- a fractional split whose left child is recursively partitioned; and
- the corresponding right-recursive fractional split.

The central theorem proves a root predicate from the leaf predicates and the
existing bisection/fraction closure theorems. A second theorem propagates a
structural invariant independently of the analytic facts. This separation is
needed for the real Flyspeck instantiation, where
`LENGTH x = LENGTH d` is required by `bisect_thm` and `ineqm_frac_thm` but is
not repeated in each serialized leaf theorem.

The encoded tree and its ML constructor have no proof authority. The accepted
result is an ordinary kernel theorem obtained from authenticated leaf facts,
the once-proved composition theorem, and the existing split lemmas. A malformed
tree can at worst make reconstruction fail; it cannot assert the root
inequality.

The clean focused test closes both the invariant-free and invariant-carrying
interfaces, checks a mixed bisect/fraction tree, verifies exact node counts,
and returns an assumption-free root theorem. Its marker is
`CANDLE_CV_PARTITION_COMPOSITION_OK`. The preserved clean rerun took 2:12.98
wall / 131.33 user seconds including HOL startup, peaked at 1,090,432 KiB RSS,
and used no swap.

## Exact `ineqm` theorem interface

Flyspeck commit `694f40ed` specializes the generic result to the exact theorem
signatures exported by `Break_case_exec`: `ineqm`, `bisect_left`,
`bisect_right`, `frac_left`, `frac_right`, `bisect_thm`, and
`ineqm_frac_thm`. The resulting theorem preserves the root conclusion and the

A fresh focused fixture with those exact operation and lemma types proves a
mixed-tree root theorem with no assumptions. It passed with marker
`CANDLE_CV_PARTITION_INEQM_OK` in 2:12.93 wall / 131.13 user seconds including
HOL startup, peaked at 1,090,432 KiB RSS, and used no swap. The 1,323,059-byte

`60a5b203e0ec05e8e8cbd3e64acb97815769cff3499d91cba1d53fcf288789a5`.

The fixture caught one real integration hazard before the expensive source
state was used: the invariant's `x` needed an explicit `real list` type.
`LENGTH` alone leaves its element type polymorphic, so an unannotated `x` was
not the same HOL variable as the real-valued `x` constrained by `ineqm`. The
specialization rejected that mismatch; the explicit type annotation is now
covered by the passing interface test.

This fixture validates theorem specialization and handoff, not performance on
the loaded real `Break_case_exec` implementation. That distinction remains a
gate for the next benchmark.

## Proof-producing leaf-to-root reconstruction

Flyspeck commit `20366f44dd67072d5c7f4608f624139fecd35d32` adds a
fail-closed reconstructor at the exact `Iarg`/`ineqm` boundary. The caller
supplies a theorem producer for each exact analytic leaf proposition. For each
constructor, the adapter checks the supplied conclusion, creates the
corresponding `candle_partition_holds` theorem with an ordinary kernel rewrite,
and combines children using `CONJ`. It then applies the proved specialized
composition theorem to return the original root `ineqm` proposition.

No Boolean result, encoded tree, host recursion, or floating-point value is
trusted as a theorem. A wrong leaf conclusion is rejected, and a malformed
tree, fraction, operation type, length theorem, or root conclusion causes
reconstruction to fail. The existing theorem hypotheses remain visible; the
adapter neither turns an assumed leaf into an assumption-free theorem nor
changes the existing theorem interface.

The exact-signature fixture now exercises all four partition constructors in
one tree: leaf, midpoint bisect, left-recursive fraction, and right-recursive
fraction. The resulting theorem has the expected root conclusion and no
assumptions. The preserved fresh run at
`cv-partition-ineqm-interface-v14` passed with marker
`CANDLE_CV_PARTITION_INEQM_OK` in 2:18.53 wall / 133.93 user seconds including
HOL startup, peaked at 1,087,744 KiB RSS, and used no swap. Its 1,349,094-byte
log has SHA-256
`d96c24d8b58b1c6dcdbf5c21831c8ca177b5493ebff91576d61980b784160cfb`.

This closes the synthetic theorem-handoff milestone. It does not yet measure
the 29,957-constructor real corpus: the next benchmark must use the existing
authenticated serialized leaf theorems after the real `Break_case_exec` source
is loaded.

## Plan impact

The previous Taylor experiments showed that returning a long result list or
one Boolean over expanded arithmetic terms is slower than the current
fine-grained path. This milestone validates the revised coarser boundary: the
entire real partition can be represented compactly and governed by one generic
soundness theorem at negligible conversion cost.

The exact `ineqm` specialization and its proof-producing recursive adapter are
now constructed. The next measurement must load them after the real
`Break_case_exec`, then compare leaf-to-root theorem reconstruction against
`prove_iargs` on the same authenticated tree and leaf theorems. No performance
claim will be made until that complete handoff is measured.

If theorem traffic still scales with all 22,941 cases, the next boundary moves
one level higher: a reflected analytic checker must validate compact Taylor and
interval certificate payloads and feed the once-proved partition theorem,
rather than materializing thousands of independent arithmetic result
theorems. The existing serialized leaves remain the equivalence oracle while
that checker is developed.

The queued inclusive LP-terminal comparison remains useful but is not being
restarted while both protected 18-GiB Candle processes are live and swap is
full. Its accepted non-inclusive real-terminal gains remain 9.87x, 4.15x, and
3.66x; a new end-to-end LP benefit is not claimed here.
