## Root cause

This is a checkpoint-lineage defect.  Candle's
`Cakeml.configureSourceIdentities` is deliberately one-shot.  The reused v664
base was created with 218 fast-NL source identities, before the canonical
verifier closure was added.  Loading a later setup/data file cannot extend the
authority already frozen inside that checkpoint.  The static audit validated
the desired 283-entry plan but did not prove that the chosen predecessor was
created from it.

Hazard `LR-018` records this failure.  The new executable check requires:

1. a base receipt reporting all 283 identities;
2. the exact v665 setup and generated data in that base's SHA-256 input
   manifest; and
3. a post-action-49 receipt whose `base_checkpoint` is exactly the checkpoint
   named by that source-configuration receipt.

The obsolete v664 predecessor can therefore never satisfy the gate again.
