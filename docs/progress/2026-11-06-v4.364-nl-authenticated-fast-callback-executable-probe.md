## Bounded failures that changed the implementation

The probe caught three issues before any Candle runtime investment:

1. `basisProg` pulled 44 unrelated generic basis/translator theories merely
   to print a status line.  Replacing output with normal-exit/`Bind` signaling
   and extending the already-built `mlbasicsProg` reduced the dry-run graph to
   exactly two project theories.
2. The first datatype registration used nonexistent `monop`; the actual
   source datatype is `uop`.  This failed in 1m46s.
3. The initially "literal" entry still exposed `from_cv` and then the named
   payload constants to the translator.  Rather than adding those dependencies
   one at a time, the literal boundary was repaired to simplify every payload
   to constructor data and prove identity there.

The first direct compiler invocation also supplied the sexp filename as a
positional argument.  The executable compiler reads stdin and writes stdout,
so it rejected empty stdin in 0.01s.  The corrected redirection succeeded.
