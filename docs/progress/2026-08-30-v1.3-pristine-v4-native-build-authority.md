# Pristine V4 native-build authority checkpoint (2026-08-30)

## Outcome and claim boundary

The V4 branch now has three positive pure leaves for the future isolated
attempt-supervisor build:

1. exact runtime-input role classification and list validation;
2. a capped pure expected-root projection; and
3. an exact classic-BPF build-confinement authority enumerator/validator.

The full isolated-build receipt remains absent/fail-closed.  None of these
leaves authenticates a process, enables a candidate/bundle/pair, or produces
approval, PFT, S2 or S3 evidence.  PFT is categorically rejected from V4 paths.

## Pure expected input root

`enumerate_isolated_native_build_root_v1` validates exact compiler/linker
executable records, a positive native source tree and a positive ordered
runtime-input list.  It derives one collision-free private-root projection:

- compiler/linker resolved paths, with original write bits stripped in the
  retained copy;
- source members below `candle-source`;
- runtime inputs at their declared safe root-relative paths; and
- the one empty writable `candle-output` directory plus the empty read-only
  `.candle-old-root` pivot directory.

PFT and reserved-prefix paths, file/directory and ancestor collisions,
unordered or misclassified runtime inputs, unsafe modes, subclasses, count,
file-size and total-size excess all reject.  Source paths are checked again
after prefixing, so a source path that was independently 4096-byte-valid cannot
overflow the derived-root grammar.

Ancestor expansion is not allowed to consume resources before its cap.  A
component trie checks the 196,608-node and 33,554,432-derived-path-byte budgets
before allocating each new node; only then does an iterative preorder walk
materialize the result.  Hostile tests force both caps on a deeply segmented
valid path.  This closes the independent P1 finding against after-the-fact
prefix materialization at exact `53b075c`.

## Exact build filter

`enumerate_isolated_native_build_filter_v4` constructs, packs and hashes one
Linux x86-64 classic-BPF authority.  `validate_isolated_native_build_filter`
requires exact built-in JSON types and exact canonical equality to that
enumeration.  Its public hostile-value traversal is iterative, capped at
262,144 JSON nodes and depth 64, and normalizes deep and cyclic structures to
`ProtocolError`.  It rejects:

- wrong audit architecture by killing the process;
- every x32 syscall number with ENOSYS before numeric dispatch;
- namespace/ptrace/mount/handle/keyring/network/IPC escape syscalls;
- every low-word clone flag outside exit signal, VM/vfork and child-TID state,
  including PIDFD, shared signal handlers, threads and parent-TID writes;
- legacy AIO, io_uring and userfaultfd mutation routes;
- ioctl and in-kernel sendfile/splice/copy-file-range routes; and
- clone3, pidfd-getfd, BPF/perf and the modern mount API.

The exact latest program has 136 instructions / 1,088 bytes, 66 decoded rules,
bounded jumps, little-endian `<HBBI` packing and complete payload/policy
SHA-256 checks.  The test independently decodes the Base64 payload and checks
the architecture, x32 and terminal return instructions plus the complete
syscall-rule projection.
The public filter leaf is now disjoint schema/kind/policy v4; no earlier
v1--v3 identity is reused after exact bytes or clone policy changed.

## Source-consuming, non-spliceable execution design

The amended build design no longer equates an accessible root with a source
build.  Before a receipt can validate, one outside-parent observation must
join:

- the namespace-creating clone, namespace descriptors/maps and retained empty
  network/IPC inventories;
- all-stop syscall-entry captures of pathname, argv and environment bytes;
- replayed cwd/umask, fd-table, CLOEXEC, VMA, fork/clone/vfork and exec state;
- first compiler exec, at least one later linker exec and every helper exec;
- full successful read/pread coverage of every source byte (mmap extent does
  not count as consumption);
- every synchronous output creation/mutation, final hash and quiescence;
- pre/post walks of one identity-held output root with unique `st_nlink=1`
  ordinary-file identities; and
- exact successful zero exit, pipes, terminal wait and complete descendant
  drain with signal/group/vfork-done/nonleader-exec control events.

Raw pointer words and caller-selected object indexes are not evidence.  Entry
bytes are copied while all shared-address-space peers are stopped and joined
to descriptor-relative root identities.  Async kernel-worker writes are
filtered rather than modeled.  The execution observation is still design-only
and remains blocking until exact hostile acceptance and implementation.
