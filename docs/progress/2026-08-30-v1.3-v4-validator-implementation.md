Setup event edges dispatch in literal `V4_BUILD_SETUP_SEQUENCE` order.  The
four root steps must equal the pure
`enumerate_isolated_native_build_setup_root_edge_v1` result and the remaining

## Complete mount-graph leaf

`validate_v4_build_mount_graph` now validates either complete parent or
builder graph containers.  It decodes canonical base64 for the complete held
mountinfo payload, bounds it by the enclosing native-receipt cap, and checks
the exact byte count and SHA-256 before parsing every mountinfo line.  Every
closed row must equal its observed mount ID/parent/device/raw escaped
root/mountpoint/source, filesystem, ordered mount/super/optional tokens and
derived propagation record.  IDs and scalar fields are exact bounded non-bool
integers.  The validator requires one normalized index-zero root whose raw
parent is absent, nonroot raw/normalized parent equality, parent-before-child
topology, and the deterministic available-parent/raw-mountpoint/mount-ID
order.  Source graphs reject `nsfs`, proc-namespace roots and namespace-file
mountpoints beneath every observed proc mount.  For a proc mount whose decoded
root is not `/`, namespace-file detection reconstructs the effective proc path
from that root plus the candidate mountpoint suffix; a `/123` proc subroot at
`/p` therefore cannot hide a `/p/ns/net` splice.

`validate_v4_build_mount_namespace_clone` validates the complete
`mount-namespace-create` relation over independently validated parent and
builder graphs.  The complete source and child mount-ID sets must be disjoint;
its source-to-child mount-ID map is then total and bijective,
parents translate through that map, both namespace identities/generations
join exactly, and root/mountpoint identities, devices, raw fields,
filesystem, mount flags, super options and non-propagation optional fields are
preserved.  Private/slave/unbindable propagation is preserved; shared and
shared-slave rows become a slave of the source shared group.  Root raw-parent
IDs remain separately observed rather than being falsely translated.

## Parent FD/OFD prerequisite

`validate_v4_build_parent_fd_state` validates the complete parent descriptor
table and every referenced open description without enabling the enclosing
initial-state seed.  Table and entry indexes, IDs and generations are exact
non-bool integers; fd numbers are strictly increasing and bounded by the
pinned 4,096-descriptor limit.  Every fd selects one present OFD with the same
closed access mode, every OFD is selected, object-edge indexes are total, and
OFD IDs are globally unique.  The exact descriptor alias count equals
`descriptor_ref_count`.  IDs, generations, offsets and flag words use bounded
unsigned scalar domains.  Normal descriptors derive read-only, write-only or
read-write from exact `O_ACCMODE` values 0, 1 or 2 and reject access bits 3.
Read-search-only is a disjoint `O_PATH` form with zero access bits and only
`O_DIRECTORY`/`O_NOFOLLOW` companions; `O_CLOEXEC` remains the separate fd
field and is forbidden in every OFD status word.  Aliases may independently
set or clear their fd-level `cloexec` boolean while continuing to share that
same OFD.  Both list digests are recomputed.  The inherited-fd
selector is the canonical complete sequence of fd-entry indexes, so it can
neither omit nor replay a descriptor.  The public result is a detached
canonical snapshot rather than mutable caller storage.

## Parent address-space/VMA prerequisite

`validate_v4_build_parent_address_space` independently validates the source
address-space identity/generation, its canonical complete mapping-index list,
the bounded mapping container and its ordered digest.  VMA indexes are
consecutive and address ordered; ranges and file offsets are page aligned,
ranges do not overlap or overflow uint64, protection has no bit outside
read/write/execute, and exactly one of the shared/private mapping-class bits is
set.  A file-backed row selects a present, stable, descriptor-relative
`bootstrap-runtime` edge with a safe non-PFT path and cannot carry the
anonymous flag.  Conversely, every null-edge row must carry `MAP_ANONYMOUS`
and has zero file offset, so a missing file edge cannot be relabeled anonymous.
The one gate selector joins the one `gate_mapping` row, whose normalized VMA
is exactly one page, read/write and `MAP_SHARED|MAP_ANONYMOUS`.  The public
result is again a detached canonical snapshot.  Neither prerequisite is wired
to a positive initial-state-seed consumer yet.

The leaf independently recomputes the bounded ordinary-file byte sum, compact

Before any of those semantic operations, it resource-preflights compiler,

entire graph a second time, and requires both detached captures to have the
same bounded size and digest.  No mutable caller graph is canonically encoded.
All enumeration, validation and the returned snapshot then use only the second
frozen graph, so a caller mutation cannot create a mixed snapshot.  Literal
limits cover executable-version bytes, JSON depth, nodes,
container members, strings, keys, integer digits, each canonical stream
fragment, the complete five-input graph and the final returned graph; every
text/fragment bound is checked before its encoding allocation.

Compiler, linker, source-member, runtime-input and output-root indexes and
counts are derived from the enumerated selectors, including exact non-bool
index arrays in source member/input order.  Its result is that detached
canonical snapshot of all four raw authorities and the caller projection, so
future consumers must revalidate those inputs rather than trust a forgeable
context object.  This leaf remains structural and non-evidentiary until the
root-walk join exists.  Complete
`input_closure` validation and initial-state-seed validation remain absent

functional tree `a5ee86f90ce3b59c6329fd19399fe00b850b0293`, add the first native
outside-parent prerequisite without adding a V2 schema, receipt or authority
consumer.  `native/v4_output_root_walk.c` opens the literal output anchor only
with `openat2`: flags are
`O_PATH|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, and the resolution policy is
`RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|RESOLVE_NO_MAGICLINKS`.  There is no
`openat`, `opendir`, `readdir`, `nftw` or lexical-path fallback in the
primitive.  Descendant object and readable-directory opens add
`RESOLVE_NO_XDEV`, so a separately mounted output anchor is admitted once but
an unlisted mount below it is not.

The long-lived caller retains two descriptors made from one initial open:
the primary anchor and an `F_DUPFD_CLOEXEC` guard.  Each snapshot records
`F_GETFD`, `F_GETFL`, `fstat`, `statx(AT_EMPTY_PATH|AT_SYMLINK_NOFOLLOW|`

`pos`, `flags`, `mnt_id`, and `ino` `/proc/self/fdinfo` projection.  The
overlapping fields are cross-checked.  Revalidation checks both descriptor
projections and uses same-process `kcmp(KCMP_FILE)` to prove that primary and
guard still share the retained open file description; reopening the same
inode into a reused descriptor number therefore rejects.

All `fd_generation`, `logical_ofd_id`, and
`logical_ofd_generation` values are monotone process-local ledger values.
They describe opens and duplicates performed by this primitive.  They are
not represented as kernel OFD IDs or kernel descriptor, namespace or inode
generation numbers.  Returned walk descriptor rows are explicitly
historical: the primitive closes every ephemeral descriptor before return.
The anchor pair alone remains live.  Failed anchor construction returns a
disarmed structure rather than closed descriptor numbers that could later be
reused, and strict fdinfo integer parsing rejects signs and non-base digits.

The walk obtains one fresh readable directory OFD per visited directory,
consumes `getdents64` through exactly one zero-length EOF return, validates
every bounded printable-ASCII component, sorts names by unsigned ASCII bytes,
and emits deterministic directory-before-descendant preorder.  Every object
and every ephemeral readable-directory descriptor is reopened below the
retained anchor using `openat2`, then receives the same cross-checked
kernel/fdinfo projection.  Symlinks, devices, sockets, FIFOs,
other special objects, regular files with link count other than one, and
nested mounts reject.  Entry count, relative/component length, aggregate path
bytes, per-directory name bytes and pending-work bytes are capped before their
corresponding allocations.

The focused native harness runs inside a fresh unprivileged user and mount
namespace with a private 16 MiB tmpfs.  It covers empty and populated
preorder walks, exact EOF counts, stable pre/post anchor revalidation, logical
generation order, exhausted-ledger rejection, per-FD guard-flag tampering,
same-inode descriptor-number substitution, and symlink, FIFO, hard-link and
nested-tmpfs attacks.  The Python wrapper compiles the primitive and harness

## Native held-builder boundary prerequisite

Functional commit `640218cd86e883bf1c68d90d4939ec74ec9ff58a`, tree
`f3941e54d9a1832204146725f1e189239e71f3c1`, builds directly on accepted
native-walk checkpoint `0ea0c50c9765bbc13bde372887b0190e3fa9f666`.
It adds an opaque, process-local held-builder lifecycle primitive without
adding a V2 object, receipt, validator or authority consumer.

The native parent creates one four-byte lock-free
`MAP_SHARED|MAP_ANONYMOUS` atomic gate with value zero, then creates the child
through raw `clone(SIGCHLD)` rather than a libc child stub.  The child path
loads only that gate and executes the x86 pause instruction while its value is
zero.  Its first designed syscall after release is `exit`; it performs no
compiler exec, namespace setup, map write, descriptor setup or protocol
operation in this slice.

The parent captures the positive PID and `/proc/<pid>/stat` start-ticks value
twice around a live `pidfd_send_signal(...,0)` check.  It retains the pidfd
and a private `F_DUPFD_CLOEXEC` guard, fixes both fcntl projections and uses
same-process `KCMP_FILE` on every held-state verification.  Descriptor-number
reuse with a new pidfd OFD therefore rejects.  These are process-local
observations and a retained OFD, not a claimed kernel pidfd or task-generation
number.

The compile-time fixed ptrace mask is exactly `0x0010007f`, the ordered V4
set `PTRACE_O_TRACESYSGOOD`, `PTRACE_O_TRACEFORK`,
`PTRACE_O_TRACEVFORK`, `PTRACE_O_TRACECLONE`,
`PTRACE_O_TRACEVFORKDONE`, `PTRACE_O_TRACEEXEC`,
`PTRACE_O_TRACEEXIT`, `PTRACE_O_EXITKILL`.  The parent performs one
`PTRACE_SEIZE`, one `PTRACE_INTERRUPT`, and first observes the resulting stop
non-destructively through `waitid(P_PIDFD,...,WSTOPPED|WNOWAIT)`.  Linux
reports the exact status `(PTRACE_EVENT_STOP<<8)|SIGTRAP`, 32773.  One
pid-specific `waitpid(__WALL|WNOHANG)` then consumes that same event and no
second initial stop is accepted.

While held, repeated verification rejoins the PID/start ticks, live guarded
pidfd, exact raw wait status and one/one/one operation counters.  Proc status
must say tracing-stop with `TracerPid` equal to the native parent;
`PTRACE_GETSIGINFO` must remain identical; `PTRACE_GETREGSET` must return the
complete x86-64 register projection; and `PTRACE_GET_SYSCALL_INFO` must be
`NONE` with x86-64 audit architecture and the same instruction/stack pointers.
The gate must remain zero and `waitpid(__WALL|WNOHANG)` must expose no
additional event.

`v4_hb_builder_run_empty_prewalk` performs those held checks immediately
before and after calling the independently accepted output-anchor primitive.
Only an exact zero-entry, one-EOF, one-readable-root-descriptor walk advances
the lifecycle to `EMPTY_PREWALK_COMPLETE`.  The release API rejects at every
earlier state and is the sole writer of gate value one.  Normal release then
requires the exact `PTRACE_EVENT_EXIT`, zero event message, unchanged task
identity, exact zero final exit, exhausted wait set and terminal pidfd before
closing both pidfds and unmapping the gate.  All event waits have a bounded
five-second polling budget; no missing kernel event can block the outside
parent indefinitely.  Abort uses the guard pidfd to deliver SIGKILL, consumes
and resumes bounded ptrace stops, exhausts the wait set, verifies terminal
pidfd readiness and closes the same resources.

The real integration harness runs in a fresh unprivileged user/mount
namespace on private tmpfs and combines the held state with the accepted
empty walk.  Hostile cases cover early gate release, repeated seize, PID,
start-ticks, raw-wait-status and pidfd-number splices, primary-pidfd OFD
substitution, an unexpected SIGUSR1 delivery stop and an unexpected SIGKILL
exit.  Ordinary and combined ASan/UBSan builds run the complete lifecycle and
attack matrix; a third source-policy test pins SEIZE/INTERRUPT/raw-clone and
the absence of TRACEME, ATTACH, fork, exec and schema surfaces.  The held-
builder suite is 3/3 and the accepted output-walk suite remains 3/3.  Protocol
31/31, generator 6/6, parser 32/32 and direct release 30/30 remain unchanged,
for 105/105 relevant tests.  GCC `-fanalyzer`, strict C compilation,
`py_compile` and `git diff --check` pass.

The hostile error-provenance audit splits every ptrace syscall result from
its successful-result projection check: real syscall failures retain captured
errno, whereas GETSIGINFO signal, GETREGSET size and GETEVENTMSG value
mismatches deterministically report `EINVAL`.  The same audit covers fcntl,
pidfd, wait and poll branches rather than relying on stale errno.

This is a functional prerequisite awaiting independent review, not producer
or authority evidence.  It remains Linux x86-64 and depends fail-closed on
procfs, pidfd, pidfd waitid, ptrace syscall-info, KCMP, user namespaces and

seed, execution-observation, receipt and outer authority consumer remain
