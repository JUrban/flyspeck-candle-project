## Result

Candle commit `0609ff96` adds a canonical raw-data boundary for the
variable-certificate Taylor checker. It is pushed on
`codex/cv-nonlinear-disjunctive-v1`.

The boundary accepts nested exact-rational certificate jobs as ordinary
`cval` data. Its proved decoder/canonicalizer contract establishes that an
accepted raw object is exactly the existing logical job encoding. The
existing general numerical-acceptance theorem then yields the unchanged
logical theorem interface. This removes host construction of one
representation theorem per rational endpoint or list constructor.

The commit also contains:

- a proof-producing raw batch adapter;
- a reusable exact plan for genuine disjunctive member 16594;
- a bounded 28-chunk numerical runner; and
- a proved direct well-formedness checker retained as a measured alternative,

## Bounded representation failures

Four attempts to retain the entire 875-cell raw syntax failed by silent
nonzero runtime exit during host term construction:

1. one monolithic encoded term;
2. the same encoder with a 64 MiB live stack;
3. a single-pass recursive encoder without the intermediate mapped list; and
4. 28 separately encoded terms retained at once.

No attempt reached a HOL rejection, and available machine memory remained
large. These results rule out an 8 MiB stack limit, the intermediate
`map` result, and one unusually deep term as sufficient explanations. They do
not establish a more specific runtime cause. The bounded runner therefore
encodes, checks, records a digest, and discards each 32-cell chunk before
proceeding.

## Canonicality discriminator

The architecture note suggested avoiding computed intermediate results that
are not needed by the verdict. A direct structural well-formedness checker
was therefore proved equivalent to canonical rebuild-and-equality. Its full
generic theorem suite loaded and sealed successfully, including the
acceptance theorem and characteristic equations used by `Kernel.compute`.

On the same genuine 32-cell input, however, the direct checker took
**816.219 seconds** for the numerical computation. The canonical
rebuild-and-equality route took **506.102 seconds**, so the proposed direct
scan was **1.61x slower**. Both stayed near 2.2 GiB RSS.

The direct-checker run completed all 1/8/32 numerical computations, theorem
handoffs, no-hypothesis/no-new-axiom validation, and both malformed-input
rejections. It printed the unchanged 1- and 8-cell digests, then exited
silently while converting the 32-cell theorem to text for its final digest.
There was no HOL exception or numerical rejection. This is preserved as a
post-validation publication/stringification failure, not a green batch:

## Architecture implications

This strengthens several conclusions from the 2026-09-28 architecture
review:

- moving certificate representation proofs behind one raw-data contract is
  sound and practical;
- repeated evaluator initialization is not the main remaining cost;
- apparently simpler recursive validation can be slower than constructing a
  canonical value and using the kernel's equality path;
- very large returned theorem/data syntax can fail outside the trusted
  numerical verdict, so a compact result boundary matters independently of
  arithmetic speed; and
- the dominant cost still lies in per-cell interval/Taylor evaluation and
  exact arithmetic, not in this canonicality check.

The next proof boundary should consume a compact postorder certificate with
leaf jobs and exact split commands, prove the command machine sound once, and
return one root theorem. That can avoid retaining 875 flat certificate terms
or stringifying a large batch theorem. It will not by itself reduce the
roughly per-cell numerical cost, so rational/interval representation work
remains a separate measured priority.
