> Superseded for the cross-runtime coverage boundary by
> `2026-08-30-v1.3-pristine-reference-boundary-audit.md` and the role-correct
> comparison-v2 protocol at project commit `8dadedc`.  This report remains the

## Scope

Project commits `bec8c91` and `9136e14` repair the pure, non-CLI, unapproved
three-candidate comparison fixture introduced at `0da47c9`.  Commit `44e7e6d`
attempted to add a compiled-candidate construction bridge; hostile review found
that its public pure builder could label structurally forged fixture data as an
authenticated candidate.  Commit `71a5909` removes that builder and moves
production descriptor emission into the raw-artifact consumer.  Review then
identified its private pure assembler as a reuse hazard; commit `8f57baa`
removes that helper too and inlines descriptor construction at the validated
CLI call site.  Commit `cd5b3ab` adds an AST/control-flow regression over that
inline-only security boundary without reintroducing a callable assembler.

None of these commits authenticates a real candidate, runs either reference
collector, approves S2/S3, or authorizes a release.

## Addressed review findings

The earlier fixture accepted six detached caller assertions: expected plan,
compiled and reference candidate records, and two lists of semantic and
coverage projections.  That allowed candidate-specific nonces, plans,
projections, and authorities to be supplied independently.  It also used
Python equality after validating only the report side, so JSON `true` and
`1.0` could compare equal to integer content lengths in unvalidated expected
records.

The repaired API accepts exactly three indivisible authenticated descriptors:
one `compiled-direct-schema6` descriptor and two ordered
`pristine-clean-reference` descriptors.  Each descriptor strictly binds:

- its candidate content record;
- its role-specific authenticated nonce;
- the authenticated plan content record;
- the semantic and coverage projections;
- candidate-specific authenticator commits, entrypoint, and source inventory;
- an exact false `pft_used` field.

The comparison report is derived against those grouped inputs.  Every content
record and authority is strictly validated on both sides, and equality uses
canonical JSON bytes, eliminating Python bool/integer/float aliasing.  The
comparison-level authority now includes exact reviewer, compiled-producer, and
reference-producer entrypoints; all three must be present in their respective
source inventories and have pairwise-distinct content identities.  The
candidate-specific authorities must equal those recorded producer commits,
runtime commits, entrypoints, and inventories.  Both nonce-distinct reference
descriptors must use the same recorded pristine validator/runtime authority.

## Authenticator-bound compiled descriptor

The pure protocol module no longer exposes
`build_authenticated_compiled_comparison_descriptor`.  Its schema-6 adapter
also rejects a receipt unless it records an exact fresh replay from action
zero, a held cooperative build lock, the expected mutation model, no process
checkpoint, and the exact runtime-environment policy.  These checks are
defense in depth: the pure adapter still does not authenticate raw artifacts.

The explicit `--evidence-schema 6 --comparison-candidate` mode of
`check-published-direct-result.py` is now the only implemented compiled
descriptor emitter.  The mode is rejected for schema 5.  Descriptor assembly
is inline and occurs only after the existing consumer has validated the
receipt, log, executable,
snapshot, archived link, plan, closed result tree, repository heads, named
directory identities, final source bytes, and held runtime lock.  The consumer
derives, rather than accepts, the candidate authority:

- the project commit is the authenticated consumer project head;
- the runtime commit is the authenticated Candle head;
- the entrypoint is the exact committed consumer source;
- the canonical source inventory contains the exact committed consumer and
  protocol bytes.

The descriptor's candidate record, nonce, plan record, and two projections are
derived from the capture built inside that same validation.  The CLI retains
the old capture output unless the explicit comparison mode is requested.
A standalone descriptor never authenticates itself; a production comparator
must replay this exact pinned CLI against the retained raw result bundle.

## Checks and remaining gates

At `cd5b3ab`, the direct protocol suite passes 24/24 and the direct-result
consumer suite passes 18/18.  The new regressions reject non-fresh,
checkpointed, unlocked, wrong-mutation-policy, and wrong-environment-policy
schema-6 inputs; require schema 6 for compiled comparison mode; require the
consumer entrypoint to occur in the authenticated source inventory; and verify
that neither the protocol nor consumer exposes a detached descriptor builder.
The control-flow gate checks that inline descriptor construction is inside the
schema-6 and held-lock regions, follows final source reauthentication and the
last held-lock check, derives the exact authority/candidate/nonce/plan/
projection fields, remains PFT-false, and invokes the strict descriptor
validator.  Python byte compilation and `git diff --check` also pass.

Independent hostile re-review at exact head `ebe18d7` reproduced the earlier
attacks and returned PASS with no P0, P1, or P2 finding.  In particular,
expected-only integer `1` versus JSON `true`/`1.0`, identical entrypoint content
under distinct paths, compiled/reference authority drift, and divergent
reference validator authorities all reject at their intended checks.

The first hostile review of `44e7e6d` returned one P1: a receipt with
`fresh_process_replay_from_action_zero=false` and a forged checkpoint could
mint the authenticated descriptor kind, and candidate authority was
caller-supplied.  That review is the reason for the `71a5909` boundary change.
A re-review of `71a5909` found no production-path P0/P1 bypass but showed that
its private pure assembler remained directly reusable with forged inputs.
That P2 is the reason the assembler is absent at `8f57baa`.  A final
independent exact-blob re-review of `cd5b3ab` returned PASS with no P0, P1, or
P2 finding.  It confirmed that the protocol builder and private consumer
assembler are absent, the only consumer descriptor-kind reference is inside
the postflight branch, and both focused suites and commit diff check pass.
