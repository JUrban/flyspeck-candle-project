## Development-runtime shortcut tested

The already proved Candle kernel prefix is serialized independently of the
unchanged compiler and REPL tail.  A tempting shorter development route is
therefore to replace the old kernel declaration in an existing complete
compiler S-expression, compile the result with the existing executable
`cake`, and use the resulting REPL while the ordinary downstream proof build
continues.

A fail-closed preflight tested that route before applying it to the much
larger in-progress ledger.  The prior kernel prefix and the existing complete
tail combined into a syntactically valid 10,597,580-byte S-expression.  The
executable compiler accepted it, emitted assembly, and the system linker
produced an ELF executable.

That executable did not reach the Candle REPL banner.  It terminated by
signal 4 with the default direct-compiler flags.  Adding the full-program
self-hosting flags produced an executable that terminated by signal 11.

## Baseline discriminator

The same tests were then repeated without any splice, using the unchanged
complete baseline S-expression as compiler input.  They failed in the same
way:

| Complete-program compile | Result when started with `--candle` |
| --- | --- |
| allocator 0 plus empty-FFI emission | signal 11 before the REPL banner |
| normal allocator plus empty-FFI emission | signal 11 before the REPL banner |

The normal-allocator baseline compilation took **3m45.66s** and reserved
**16,700,544 KiB** peak RSS.  The allocator-0 baseline took **1m24.26s** and
reserved **16,700,544 KiB**.  Both compilation and native linking exited
successfully; the failure occurred only when the resulting complete dynamic
REPL executable started.

This discriminator means the observed failure is not evidence that the
kernel-prefix splice changed program semantics.  It establishes instead that
this executable compiler plus the available complete S-expression/configuration
artifacts is not a validated way to materialize a Candle dynamic REPL.  Small
standalone checker programs remain valid for the established direct-`cake`
development loop, but that result cannot be extrapolated to a self-hosted
complete Candle runtime.

## Decision

The splice shortcut is dropped.  It will not be patched, treated as theorem
evidence, or used to bypass the ordinary compiler/REPL build.  Once the live
kernel translation finishes, the next steps remain:

1. build the focused kernel-permission and downstream semantic theories;
2. materialize the complete Candle runtime through the ordinary CakeML
   theory/bootstrap route; and
3. run the prepared registered-result adapter to the literal original
   case-10173 theorem.

The long-running HOL translation was isolated on its own core throughout the
preflight and was neither interrupted nor modified.  It remains at about
22.5 GiB resident memory with no proof error.
