## Research-note findings

The source-based performance note now has two measured explanations and one
negative result.

1. **Rational normalization/GCD remains the primary measured arithmetic
   cost.**  The earlier 64-box action-296 comparison measured 13.101 s for the
   fixed backend versus 105.143 s for the rational backend, with 130/130
   complete outputs equal.

2. **Repeated evaluator entry is a material secondary cost.**  Candle commit
   `d82f90dc` adds a bounded timing-only internal batch over the same 16 genuine
   boxes.  In one session:

   - 16 separate compact checker calls took 3.809 s of computed-check time;
   - one evaluator call returning all 16 compact `(verdict, upper)` results
     took 1.680 s;
   - batching therefore improved this numerical phase by **2.27x**.

3. **Discarding the already compact upper results did not help measurably.**
   A second internal call returning only the aggregate acceptance count took
   1.706 s.  Within run noise, this is the same as returning all 16 compact
   results.  The expensive unnecessary-output concern applies to full
   intermediate jets, which the strict checker already hides, not to these
   small final results.

The aggregate acceptance count is deliberately timing-only.  The 16
individually certified results remain the theorem authority until a general
proved batch/certificate boundary is added.

The note's remaining constant/sparse and Hessian-only suggestions remain
plausible, but neither is now as urgent as using the proved fixed backend and
amortized evaluator entry on larger real workloads.  Proof-producing work in
untrusted preparation should likewise be removed when encountered, but it is
not part of the measured hot path in this genuine polynomial batch.
