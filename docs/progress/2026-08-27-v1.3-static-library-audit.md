five/seven member sets.  No required member has a complete, currently linked
Candle binding.  The bounded result is:

- `Str.first_chars` can be a direct wrapper over existing verified string
  support;
- the selected `Str.global_replace` behavior is small pure compatibility code;
- `Str.regexp`, `Str.split`, and `Str.string_match` should initially be
  normalized to the finite selected pattern shapes, with OCaml differential
  oracles.  CakeML has a verified regexp engine, but it is not an existing
  `Str` implementation and its syntax and whole-string semantics differ;
- exact OCaml behavior for `Unix.gettimeofday`, `mkdir`, and the process pairs
  needs new platform/FFI semantics.  For the S3 release route, source
  normalization is preferable wherever timing, build metadata, certificate
  generation, or shell pipelines are not theorem-producing dependencies;
- `Unix.putenv` should not mutate the ambient host environment.  The loader
  already provides the correct selected-route substitution: a manifest-owned
  `Sys` environment allowlist;
- `open_process_in "date"` must be replaced by deterministic manifest build
  metadata.  It is the only selected `open_process_in` occurrence and executes
  while `strictbuild.hl` loads.

The six `#load` directives must remain fail-closed until these static bindings
and substitutions are implemented and tested.  Treating the directives as
generic no-ops is still unsound.

## Existing verified assets and gaps

### Pure strings and regular languages

- `basis/StringProgScript.sml` translates `sub`, `substring`, `explode`,
  `implode`, `translate`, and `tokens`; its side theorems include
  `translate_aux_side_thm` and `tokens_alt_aux_side_thm`.
- The HOL regular-language stack provides
  `examples/formal-languages/regular/regexp_compilerScript.sml:2143`
  (`regexp_matcher_correct`) and parser definition
  `regexp_parserScript.sml:314` (`parse_regexp_def`).
- CakeML `examples/grepProgScript.sml` translates that parser/compiler and
  proves `compile_regexp_with_limit_sound` and
  `regexp_matcher_with_limit_sound`; the x64 composition is
  `examples/compilation/x64/proofs/grepProofScript.sml:33`
  (`grep_compiled_thm`).

These regexp assets are reusable proof infrastructure, not a drop-in `Str`:
HOL/CakeML uses `|` and ordinary parentheses for alternation/grouping, while
OCaml Str uses `\|` and `\(...\)`; CakeML's verified matcher recognizes whole
strings, whereas `Str.string_match r s start` accepts a matching substring
starting at `start`.  `Str.split` also needs match boundaries and leftmost
delimiter behavior, not merely a boolean language recognizer.  An adapter
therefore needs its own syntax translation and semantic proof.

### Files, channels, and extension FFIs

- `basis/fsFFIScript.sml:191-291` defines the verified `open_in`, `open_out`,
  `read`, `write`, and `close` FFI model.
- `basis/TextIOProgScript.sml` implements the translated channels;
  `basis/TextIOProofScript.sml` provides `openIn_spec`, `closeIn_spec`,
  `closeOut_spec`, `output_spec`, and `inputLine_spec_lines`.
- `basis/basis_ffiScript.sml:69` proves `basis_ffi_oracle_ext`, so a formally
  specified extension oracle can receive non-Basis calls.

This support is insufficient for processes.  `fsFFIScript.sml:159-166`
requires `closeFD` to close a `File` inode; it does not model arbitrary new
subprocess pipes.  The committed Candle C-glue patch recognizes only `chdir`,
`getcwd`, and synchronous `system` in `candle/basis_ffi.c.patch:6-36`.  A
process implementation would require a new logical process/pipe state and
TextIO refinement, not just another C branch.

## OCaml 4.14.1 oracle facts and semantic traps

Local reference observations establish useful regression anchors:

- `Str.split (regexp " +") "  a  b " = ["a"; "b"]`;
- `Str.split (regexp " ") "a  b" = ["a"; ""; "b"]`, while edge delimiters
  are dropped;
- `Str.split (regexp "[^b]+") "abbbc" = ["bbb"]`;
- `Str.string_match (regexp "Ocaml 4.") "Ocaml 4x" 0 = true` because dot is
  a non-newline wildcard, but starting with an extra `x` is false;
- `regexp (".*" ^ "f.o")` matches `"xxfaozz"`; appending `"["` raises
  `Failure "[ class not closed by ]"`, so dynamic search strings are not
  literals;
- deleting `_` from `"_a__b_"` yields `"ab"`;
- `Str.first_chars "abc"` accepts lengths 0 through 3 and raises
  `Invalid_argument` for -1 or 4;
- an `open_process_in` child exiting 7 returns `Unix.WEXITED 7` from
  `close_process_in`; bidirectional `open_process` requires flushing output
  before dependent reads.

Additional traps are wall clock versus monotonic time, clock rollback and
double precision; `mkdir 0o777` being filtered by umask; global environment
mutation and child inheritance; `/bin/sh` interpretation, PATH and quoting;
pipe buffering/deadlock and SIGPIPE; wait/close ordering; signal statuses; and
exception compatibility.  All platform operations need deterministic failure
behavior and sandbox/trust statements consistent with the existing open G4
obligations.
