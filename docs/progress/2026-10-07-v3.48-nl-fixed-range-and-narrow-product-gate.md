## Whole-graph range audit

A compile-time-only diagnostic measured the exact fixed-point range used by
the current dyadic-shift plus fused-add lane over all 4,173 genuine boxes. The
ordinary timing binary contains none of this range instrumentation.

| Value class | Maximum magnitude bits | Values outside signed 64 bits |
|---|---:|---:|
| Rounded quotient results | 45 | 0 |
| Interval multiplication operands | 45 | 0 |
| Interval-addition results | 44 | 0 |
| Exact rational inputs after scaling | 26 | 0 |
| Raw interval products | 68 | not applicable |
| Quotient numerators / Taylor raw values | 83 | not applicable |
| Quotient denominators | 48 | not applicable |

Thus every observed normalized endpoint fits signed 64 bits with substantial
headroom. Raw products and Taylor numerators genuinely require a wider type.
This is complete-fixture development evidence, not a general range theorem.

## Narrow-product proxy

The cheapest split-width proxy leaves every stored endpoint and accumulator
as signed 128 bits, but converts each interval-product operand to signed 64
bits before forming the exact signed-128 product. Three complete lanes were
measured over 20 rotated repetitions:

| Lane | Preparation | Evaluation | Complete batch | Accepted |
|---|---:|---:|---:|---:|
| Wide 128-bit products | 0.339794020 s | 0.278570053 s | 0.618364073 s | 4,173 |
| 64-bit operands with dynamic checks | 0.342377178 s | 0.282200035 s | 0.624577213 s | 4,173 |
| 64-bit operands without repeated checks | 0.340322956 s | 0.274445421 s | 0.614768377 s | 4,173 |

Both candidate result streams are byte-identical to the wide control. Dynamic
checks make evaluation 1.3% slower. Removing those checks in the explicitly
untrusted diagnostic improves evaluation by only 1.015 times and leaves it
3.327 times the historical specialized C++ batch. This is far below the gate
for a container refactor or proof investment.

The paired timing table has SHA-256
`f114fc7069929d166bf44b294c6eb5106104276db77f7b4f63f6763fe08e06cf`
in `nl-native-case10173-narrow-products-paired-v1-dev-001`.

## Decision

The normalized-width hypothesis is true on this complete fixture, but endpoint
multiplication width explains little of the residual time. A split-width
refactor and its range proof are rejected as the next project. The diagnostic
code remains opt-in and must not be treated as a production arithmetic path.

Together with the corrected stage profile, this points away from another
scalar typedef or isolated primitive. The next native gate must reduce work
across a substantial authenticated source block or complete box while
preserving enclosure quality. Candidate designs must also account for the
23.5% exact job-geometry conversion separately: it can be reusable
preparation across multiple expressions on the same boxes, but merely moving
it between timing phases is not a speedup.
