# Independent direct-result consumer — 2026-08-30

## Result

`scripts/check-published-direct-result.py` now independently revalidates a
completed schema-5 cumulative Flyspeck result before that result may schedule a
later ordinary boundary.  A pass remains categorically nonpromotable: the gate
always emits `promotion=false` and `s2_s3_evidence=false`.  It emits
`scheduling_authority=true` only for one of the eight ordinary cumulative
boundaries; both diagnostic cutpoints emit `scheduling_authority=false`.

No current direct result exists, so this is a tested release gate rather than
an execution result.  End-to-end use remains blocked on the cold replay,
canonical bootstrap, ordinary schema-6 link, and parser gates.

## Independent authority reconstruction

The consumer authenticates its own committed project blob and the six exact
Candle controller blobs, rejects special Git index flags, replacement refs,
grafts, or dirty worktrees, and executes the Candle helpers from captured source
bytes under private module names.  Its process must start exactly as
`/usr/bin/python3 -I -S` with `PATH=/usr/bin:/bin` and `LC_ALL=C.UTF-8`; this is
required to reproduce the direct controller's pinned `utf8_mode=0` startup
identity.  The compiled runtime environment is separately required to be
`LC_ALL=C`, the same `PATH`, and only explicitly supplied decimal
`CML_HEAP_SIZE`/`CML_STACK_SIZE` additions.

The CLI requires exact project, Candle, CakeML, HOL4, and Flyspeck heads, the
exact plan SHA-256, selected boundary, result root, and all wall/CPU/address-
space/output limits.  It then:

1. pins the plan and result directory inodes and holds the shared Candle build
   lock, requiring the receipt's lock record to equal the held descriptor;
2. validates the ordinary schema-6 linked record and its exact CakeML/HOL4
   revisions;
3. reconstructs the complete current stratum plan and exact descriptor-pinned
   plan tree, including all ten prefixes and no extra path;
4. reconstructs the live six-source controller execution and commit binding;
5. duplicate-aware decodes and canonical-byte checks the receipt, attempt,
   snapshot, linked record, bootstrap provenance, and bootstrap preflight;
6. binds the archived link, bootstrap record/preflight/log, linked CakeML
   executable, and ELF closure byte-for-byte to the current linked authority;
7. reconstructs the producer's complete ordered snapshot inventory from the
   current source, harness, normalization, generated-input, process-input,
   linked-output, runtime-ELF, prefix, Python, and host-tool authorities;
8. requires the exact closed result tree and modes: top/control records `0444`,
   all retained subdirectories `0555`, snapshot files `0444`, and only the
   snapshot CakeML executable `0555`;
9. applies Candle's public snapshot and schema-5 evidence validators to the
   bound log, action ledger, logical/physical source closures, dependency
   history, semantic coverage, and uncompared fingerprints; and
10. repeats linked, controller, plan, snapshot-inventory, archived-authority,
    tree, Git, directory-inode, and lock-inode validation before returning.

The direct log is rejected above 512 MiB before any in-memory semantic parser
is invoked.  This consumer cap is below the producer's general per-file ceiling
and is an operational acceptance constraint, not a claim that the producer
could not retain a larger failed diagnostic log.

reviewed consumer SHA-256 is

The focused suite contains 13 tests covering duplicate JSON, bounded reads,
exact runtime/CML environment, private-source module collision, plan/result
inode replacement, lock-directory replacement, exact plan closure and digest,
exact result modes and symlink/hard-link rejection, reconstructed snapshot mutation,
malformed input envelopes, and diagnostic/ordinary scheduling separation.
All 13 pass.  Together with the 139 unchanged project tests, the current
combined project regression set is 152 passing tests.
