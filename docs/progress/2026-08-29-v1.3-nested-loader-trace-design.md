# Loader-owned nested source trace design — 2026-08-29

## Conclusion

The current direct runner can observe its custom outer actions, but it cannot
prove whether loader-owned nested `needs`, `loads`, or `#use` requests were
evaluated or skipped by Candle's private physical-path cache.  A post-bootstrap
ML wrapper cannot close this gap: `candle/prover/candle_boot.ml` captures the
scanner handlers and its `loadedFiles` state inside a private closure.
`hol_loader.ml` exposes only the load path and the project's separate logical
outer-action ledger.

The smallest honest fix is a loader-owned, nonce-bound event protocol in
CakeML's `candle/prover/candle_boot.ml`, followed by a disjoint direct-evidence
schema 4 host validator.  This is handwritten runtime-source instrumentation,
not a change to compiler semantics: `repl_moduleProgScript.sml` reads
`candle_boot.ml` at runtime.  No new compiler theorem is intrinsically required.
Release policy nevertheless binds this boot source as a canonical input, so a
new CakeML commit still requires a fresh canonical bootstrap and exact-head
link.  An old artifact or diagnostic transition is not promotable.

This change should be batched with the planned parser-only
`caml_parser$run` CLI before that next expensive bootstrap.

## Why wrappers and current logs are insufficient

Redefining `needs`, `loads`, or `Cakeml` after boot does not replace the
functions already captured by the scanner.  Source before/after sentinels show
only that instrumented code reached a point; a cache-skipped file runs no
sentinel, and instrumenting every source changes normalized bytes and the cache
keys being measured.

The existing `- Loading`, `- Already loaded`, and `- Finished loading` output is
loader-originated, but it is not release evidence.  It lacks a session nonce,
directive kind, exact logical/original/selected identity, digest binding,
parent/request id, and protected protocol namespace.

## Boot-side protocol

Add one-shot `configureSourceTrace` and `finishSourceTrace` APIs to
`candle_boot.ml`.  Generated stdin configures the trace after runtime config and
before stratum setup.  The authenticated table maps every permitted resolved
path spelling to its logical source key, original SHA-256/MD5, selected
physical cache slot, and optional normalization id/output digests.

For every real loader directive:

1. Emit a nonce-bound request after path resolution but before cache/read
   handling, with a contiguous request id and parent id.
2. Carry that id in the existing nested load stack.
3. Emit `evaluated` only when the source's `T_done` is processed after
   `checkError`; reading or queueing bytes is not evaluation.
4. Emit `cache-skip` immediately only for an actual `D_need` cache hit.  For
   `loads`, `#use`, and `#flyspeck_loadt`, record evaluation plus prior cache
   presence rather than pretending that repeated loads are skips.
5. Permanently latch read, parse, evaluation, neutralization, and REPL failures.
   An incomplete request or failed latch makes a success terminal impossible.
6. Call `finishSourceTrace` only after the postlude returns and stdin reaches the
   declared endpoint; require an empty load stack.

The claim vocabulary remains narrow:

- request: a real directive was recognized and resolved to an authenticated
  binding;
- read/enqueue: selected bytes entered the evaluator stream;
- evaluated: all top-level phrases returned without a reported evaluator
  error; and
- cache-skip: no evaluation occurred because the private selected-path cache
  already contained the key.

None of these proves theorem equivalence, dependency-history identity, or the
correctness of a normalization.  Those remain separate snapshot, fingerprint,
reference-approval, and finalization gates.

## Host-side schema 4

The host parser must require exact-line records with the exact nonce,
contiguous ids, correct parent nesting, one outcome per request, and one final
terminal.  It rejects unknown, duplicated, missing, reordered, or malformed
trace-namespace lines.  It independently reconstructs expected roots and each
evaluated source's ordered standalone directive inventory from the manifest
and normalization contracts, and it rehashes the boot/runtime snapshot after
execution.

The receipt stores the canonical observed-event digest and separate evaluated
and cache-skipped identity projections.  Its claim is only
`loader-observed-successful-evaluation-or-cache-outcome`; schema 4 still does
not self-approve semantic identity or S2/S3 release.

At current scale the validator covers 400 manifest nodes, 414 resolved
dependency targets, 204 repeated target edges, and 18 normalized sources.  Use
an explicit stack/state machine rather than reducing the evidence to a set.

## Newly exposed path and classification blockers

Current identity/overlay tables use canonical paths, but Candle preserves some
lexical load-path spellings.  The first affected outer action is 126,
`../jHOLLight/caml/ssreflect.hl`; `../formal_lp` begins at action 145.  Values
such as `jHOLLight/../jHOLLight/...` will not match the configured canonical
identity, and normalized formal-LP paths will miss the overlay.  Generate and
validate every exact lexical alias or add an authenticated trace-mode resolver
before any long direct run.

Schema 3 also needs honest role classification.  `flyspeck_full_build.ml` is a
derivation input for the instrumented prefix, not executed source.  Conversely,
generated controls such as `candle/build/insulate.ml` and
`candle/flyspeck_source_digests.ml` are executed but were omitted from its
expected source projection.  Distinguish observed outer sources, expected
nested sources, generated executed controls, and derivation-only inputs.

## Minimum adversarial qualification

Tests must cover nested order, first load versus real cache skip, repeated
`loads`, `#use`, normalized selection, lexical `..` aliases, empty files, read
failure, nested evaluation failure, neutralization failure, incomplete
requests, forged/reordered/duplicate records, wrong nonce/digests/parents,
unregistered sources, terminal-before-EOF, snapshot mutation, relocation, and
a cache skip whose logical identity has no preceding successful evaluation.

The irreducible boundary still includes the handwritten boot loader/event
implementation, verified compiler/runtime and HOL kernel envelope, host
validator/finalizer, reviewed normalizations, operating system/C runtime and
hardware, and the cooperative-filesystem mutation model.  The new trace closes
one precise question: whether the exact selected source evaluated successfully
or was skipped by the loader's actual cache.
