It records code and test closure through Candle commit

## False-green found and closed

The first full-`hol.ml` float differential waited only for a later REPL prompt.
When the old linked compiler rejected `Kernel.EQ_MP`, the session remained
alive and the float probes ran in the partially loaded environment.  That was
a false green.

The candidate gate now sends `#use "hol.ml"` followed by a declaration that
calls `check_axioms ()`.  It independently requires both Candle's explicit
`Finished loading hol.ml` EOF witness and
`val candle_hol_load_complete = true` before any float probe.  It also invokes
the linked-artifact validator before launch, so a dirty tree, stale record,
schema-1 record, wrong executable, or mismatched compiler identity cannot
produce a Candle-side PASS.

The compiled half has not yet passed this strengthened gate.  The old binary
correctly fails it at the qualified-uppercase parser regression; promotion
awaits the new compiler bootstrap and link.

## Decimal compatibility claim

CakeML lowers each retained decimal literal through
`Option.valOf (Double.fromString lexeme)`.  The compatibility insulation keeps
only those two generated global dependencies, and the later Metis `Option`
replacement preserves `valOf`.

The evidence claim is deliberately limited to ten exact positive spellings,
covering decimal points, exponents, separator underscores, zero, and a small
normal value.  OCaml 4.14.1 supplies the pinned IEEE-754 word oracle.  Six
malformed spellings must remain rejected and one hexadecimal form is outside
the selected decimal grammar.

Host `strtod` reports `ERANGE` for `1e309` and `1e-4000`; the current CakeML
basis maps that result to `None`, while OCaml produces infinity and zero.  The
gate now first proves `Double.fromString` returns `None` for each string, then
separately proves that the corresponding source literal raises through the
lowered `Option.valOf`.  These are expected divergences outside the ten-case
claim, not generic Candle successes.  Broader non-ERANGE support remains
implementation intent until direct corpus execution exercises it.

Conversion still occurs at expression evaluation time.  Load-time benchmarks
do not close the hot-loop performance question; nonlinear and LP strata must
provide scale evidence, or a separate hot-loop gate must be accepted.

## Schema-2 linked runtime provenance

The linked record now:

- reads only the four-byte ELF magic rather than loading the roughly 1.2 GiB
  executable into Python memory;
- fixes `LC_ALL=C` and `/usr/bin:/bin`, forwards only validated decimal CakeML
  heap/stack sizes, and rejects `LD_*`, `GLIBC_TUNABLES`, `BASH_ENV`, and `ENV`
  for collection, validation, and execution;
- rejects RPATH/RUNPATH, unresolved objects, unexpected dependency roles, and
  any virtual object other than `linux-vdso.so.1`;
- requires exactly the x86-64 loader, `libc.so.6`, and `libm.so.6`, with exact
  `ldd` role-to-canonical-path bindings, absolute paths, byte counts, and
  SHA-256 hashes; and
- changes the linked record to schema 2 so every older record fails closed.

The direct stratum runner no longer executes the unpinned `/usr/bin/time`
wrapper; its existing `getrusage` accounting records child resources.  It
validates the exact snapshot copy of `cake`, not only the original build-path
ELF, before and after execution. Every attempt archives the complete linked
record, its bootstrap record, the successful bootstrap log, and the
loader/libc/libm bytes into its read-only, content-addressed snapshot. Snapshot
validation requires exact equality with the recorded regular-file and
directory sets and rejects every symlink, special file, and unrecorded entry.
Preflight and postflight also require that the original and archived records
remain identical.

The ordinary repository launcher uses privileged-mode Bash and absolute
isolated Python, validates schema 2 before every session, and requires its
ignored root boot/config paths to be the exact relative symlinks resolving to
the recorded build outputs.  This closes a later rereview finding in which
arbitrary readable root symlinks could otherwise pass a build-directory-only
check. It executes CakeML with only the fixed path and locale plus validated
decimal CakeML heap/stack sizes. The authenticated local linker likewise uses
privileged-mode Bash, isolated build commands, and absolute provenance tools.
The upstream download script is now explicitly documented as a legacy
development reference that cannot create a promotable artifact.

This is an ELF dependency closure, not a complete runtime-image claim.  It
does not pin the kernel, vDSO implementation, CPU/IFUNC selection, NSS/gconv
inputs, or later `dlopen` objects.  A fixed runtime image remains the stronger
release option if any of those affect semantic observations.
