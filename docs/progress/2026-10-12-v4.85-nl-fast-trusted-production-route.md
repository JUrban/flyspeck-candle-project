## Decision

The fast route is now a concrete production lane.  It will not obtain a
verdict from the directly compiled checker and then repeat the complete
generic checker through `Kernel.compute`.  Instead, Candle's verified compute
primitive will gain a narrowly registered fast evaluator for the frozen
case-10173 certificate checker.

The registered path will:

1. authenticate the exact registered characteristic equation and closed call;
2. decode the call into the already translated bounded-word representation;
3. execute the specialized checker directly inside the compiled Candle
   kernel;
4. use a HOL4 refinement theorem showing that this result is the result of
   the authenticated object-level checker; and
5. return the ordinary assumption-free Candle equality theorem used by the
   existing analytic soundness and topology proofs.

Thus the fast code is not an oracle and observed stdout is not theorem
authority.  A successful call still produces an LCF theorem.  The generic
`exec` route remains the fail-closed fallback for every unregistered equation
set, term shape, or input.

This requires a rebuilt, verified Candle kernel for the production result.
Direct `./cake` remains appropriate for the bounded implementation loop;
bootstrap and the end-to-end compiler theorem are required when the program
and registration bytes are frozen.

## Smallest complete checker extension

The existing word implementation already supplies most of the expensive
numerical core:

- `bounded_historical_dihedral_first64` checks the center value/gradient path,
  including its square-root and reciprocal certificates;
- `bounded_historical_dihedral_second64` checks the whole-box
  value/gradient/Hessian path, including its nine reciprocal certificates;
- the bounded Taylor library supplies checked fixed-width interval operations
  and final Taylor-state machinery; and
- the packed parsers and translated CakeML programs supply a measured,
  streaming 4,173-cell execution route.

The smallest new word-level production function is one
`bounded_case10173_checked_cell64` plus a streaming batch fold.  A cell must
consume and check:

1. the six original box intervals and the derived center/radius data;
2. all four positive square-root records used by the production wrapper;
3. the five center and nine box reciprocal certificates;
4. the center first-order and box second-order historical computations;
5. every current production guard: positive products, positive `u126/u135`,
   restricted arctangent quotient, and nonnegative source coordinates;
6. the authenticated source-patch/suffix fields needed to tie the fixed
   historical operation to the original job; and
7. the complete Taylor verdict for that final cell.

The source-program identity is batch-global and should be paid once.  It must
still be represented in the closed call and matched exactly by the registered
evaluator.  Per-cell patch/suffix data remain checked where they vary.  The
existing topology proof can then consume the accepted final-cell set; the
word checker need not re-prove tree coverage numerically.

The development packed files currently contain expected center/box outputs
because they are exact-output regression checkers.  The production payload
will instead contain the original numerical inputs and certificates needed by
the verdict.  Expected intermediate jets are optional diagnostics, not
theorem authority.

## The theorem bridge without generic replay

The implementation point is in Candle's verified `compute` path, before its
generic `exec` call.  A recognizer must return `SOME result` only for the exact
registered equation/term schema.  Its central HOL4 obligation is:

```text
registered_case10173_eval equations closed_term = SOME result
  ==> ordinary_compute_semantics equations closed_term result
```

The existing `compute_thm` proof can then use this refinement result and its
unchanged theorem constructor to return:

```text
|- complete_case10173_check source jobs roots = Cexp_num 1
```

without running the generic AST evaluator.  The already developed Candle
theorems subsequently turn that equality into final-cell negativity and then
the original inequality theorem.

Reusable machinery:

- bounded word arithmetic, roots, reciprocals, historical center and box
  functions, and their CakeML translations;
- the growing word-level soundness ledger;
- Candle's existing equation authentication, closed-term checks, theorem
  construction, and generic fallback;
- the current production analytic contract and universal dihedral/Taylor
  theorem; and
- the authenticated 4,173-cell fixtures and topology handoff.

New proof/implementation obligations:

- the complete word-level cell and batch function;
- a canonical cval-to-bounded-word decoder and result encoder;
- exact registration/term-shape authentication;
- word-checker-to-object-checker refinement for the registered schema;
- preservation of `compute_thm` and kernel permission/runtime proofs after
  adding the shortcut; and
- the frozen-kernel compiler/bootstrap evidence.

## First proof-producing experiment

Before completing every field, the mechanism will be tested on one genuine
case-10173 cell using the existing historical second-order checker:

1. register one exact closed certificate-check equation and call shape;
2. run the specialized bounded-word evaluator inside Candle;
3. obtain an assumption-free equality theorem from the kernel shortcut;
4. compare its conclusion byte-for-byte with the current generic
   `Kernel.compute` theorem for the same closed call; and
5. apply a small soundness lemma to obtain a genuine analytic enclosure
   theorem, not merely print `accepted`.

This experiment is the feasibility gate for the registered route.  It is
small enough to isolate decoder, registration, kernel-proof, and theorem
handoff costs while using real inputs and real numerical code.

If it succeeds, the next measurement is a prepared batch over distinct real
cells.  Timings will be reported separately for:

- one-time translation/kernel build and proof loading;
- batch-global source/program authentication;
- recurring input decoding;
- specialized numerical execution;
- equality-theorem construction;
- analytic/theorem handoff; and
- total warm batch elapsed time and peak memory.

The batch must agree with the generic checker on every cell and retain the
existing adversarial rejections.  The target is not merely to beat 211.54
seconds: recurring production cost should remain near the compiled bounded
checker plus decoding and a compact theorem handoff.

## Explicit uncertainties and stop conditions

The largest open proof is the refinement lemma between the registered
bounded-word call and the authenticated object-level checker.  The current
word soundness and analytic correspondence results cover much of its
mathematics, but they do not yet prove this execution-level equality.

Input decoding may also be material.  The matched control measured about
11.22 seconds for the current complete cval input through generic compute,
whereas the packed executable runs its smaller workload in about 2.1 seconds.
The first batch must therefore measure decoding rather than assume it is
free.  A canonical compact input representation is allowed only if Candle
proves or cheaply checks its correspondence to the original jobs.

If the one-cell registered evaluator needs a broad new kernel architecture,
or if a warm batch still spends tens of seconds in decoding/theorem creation,
the implementation pauses at that gate.  The fallback experiment is a compact
execution certificate checked by the unchanged kernel.  It is not the primary
route because its performance is less certain, but it preserves the same
analytic theorem interface and requires no trusted stdout.

## Implementation update: verified kernel dispatch boundary

The first kernel-side part of the fast route is now implemented on CakeML
branch `codex/nl-historical-word-sound-v1`:

- `d003d99e0` adds an internal `compute_with` dispatch point while preserving
  public `compute` as the generic evaluator with a permanently empty hook;
- `5a7981a33` proves the generalized dispatch sound and recovers the original
  public `compute_thm` as a corollary; and
- `75c8bce2c` strengthens the useful production contract: a registered fast
  result must refine the existing verified `exec` result for the same parsed
  characteristic equations and closed compute expression.

The final formulation is deliberately not a theorem-producing callback and
does not trust a compiled verdict.  Its essential obligation is:

```text
fast_eval equations expression = SOME result
  ==> exec (build_funs equations) [] compute_default_clock
        (to_ce equations [] expression) state
      = (M_success result,state)
```

The generalized kernel proof uses that static refinement theorem plus the
existing `compute_eval_thm` to construct the ordinary assumption-free Candle
equality.  It does **not** execute `exec` after the fast result is returned.
All pre-existing initialization, characteristic-equation authentication,
closedness, distinct-name, constant, term-type, and theorem-construction
checks remain on the fast branch.  A hook miss uses the unchanged generic
path.  The new generalized and original public soundness theorems both pass
their clean HOL4 batch build.

This also makes the remaining FAST-NL-1 obligations more precise.  The next
case-specific entry is not a general native callback.  It consists of:

1. an exact recognizer and canonical decoder for the registered
   case-10173 equation set and call schema;
2. the smallest complete word checker covering center and box arithmetic,
   four roots, reciprocal certificates, every production guard, authenticated
   patches/suffix, and the Taylor verdict;
3. a theorem that this registered word result equals the generic cval
   evaluator result above; and
4. a closed wrapper `compute_case10173` whose soundness is an immediate
   instance of the generalized kernel theorem.

The one-cell gate will freeze one genuine call and require both the generic
and registered wrappers to produce the same assumption-free conclusion.  It
will then apply the already completed analytic invariant to obtain the genuine
enclosure theorem.  Only after that gate will the same recognizer/decoder be
used for a multi-cell batch measurement.

The exact same-complete-checker timing remains open.  The measured
**211.538069-second** reflected call includes the complete contract, whereas
the **2.07-second** compiled prototype still covers the smaller historical
box/jet contract.  The new dispatch removes the need for a second generic
runtime evaluation, but it does not by itself prove or time the missing
complete word-level work.  Decoder cost, combined-program translation, and
the word-to-cval refinement theorem therefore remain explicit uncertainties,
not assumed speedups.
