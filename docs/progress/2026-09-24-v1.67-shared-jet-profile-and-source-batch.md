## The one-program route is the real integration path

The same genuine Flyspeck formula and all 16 boxes from its live adaptive
certificate continue to pass through the shared-jet evaluator as **one
87-instruction program**. The live-verifier adapter returns each ordinary
`m_cell_list_pass` theorem, follows the original 15-node split/glue tree, and
performs Flyspeck's unchanged final theorem assembly.

The exact end-to-end result remains:

```text
programs=1 instructions=87 leaves=16 glues=15
theorem_md5=30400817689af3c5045adfef46e010d9
```

The final theorem is assumption-free, its conclusion and printed digest match
the legacy driver, and the global axiom set is unchanged.

This resolves the earlier 43-program ambiguity. That experiment explicitly
expanded one value, six gradient, and 36 Hessian expressions to compare the
older derivative-by-derivative architecture. It is not required by the
shared-jet route. `candle_q_dim_poly_jet_whole_box_accept_sound` already
connects the one compiled source program's value, gradient, and Hessian jets
to the original source for every expression in the supported language.

Smart symbolic differentiation therefore remains deferred. It would optimize
the superseded comparison rather than repair a missing connection in the
working integration path.

## The expensive support checkpoint is already at the editing boundary

The clean checkpoint

```text
/project/flyspeck-candle-runs/cv-nonlinear-reflected-driver-checkpoint-v2
```

is preserved after the stable analytic/reflected libraries and authenticated
genuine Flyspeck source reconstruction, but before the changing prover,
adapter, and behavioral regression. Every experiment in this report restored
a fresh disposable copy, authenticated the checkpoint and stable inputs, then
hash-recorded and overlaid the exact changing fragments. Fresh-input
acknowledgement and post-ack result-marker checks remained mandatory.

The restart wrapper now has an explicit `CANDLE_FRAGMENT_SKIP_ALL_NEEDS=1`
mode for this boundary. It suppresses redundant source requests only in the
overlay text; it does not weaken the base manifest checks or the independent
hash record for each overlay.

This is deliberately not yet moved past expression preparation. Preparation
is expression-specific, and the batch below shows that its value as a new
checkpoint boundary depends strongly on program size and reuse count. A richer
per-expression checkpoint is justified when one large prepared source will be
reused during repeated behavioral experiments; the stable post-support
checkpoint remains the compatible fallback when expression or prover bytes
change.

## Complete source-proof profile

An opt-in event profile measured every phase of all 16 source proofs in a
fresh v2-checkpoint copy. The complete command took 50.17 seconds; the
prepare-to-replay interval was 26.581 seconds. Aggregate recurring phases
across all leaves were:

| Source-proof phase | Aggregate wall time |
|---|---:|
| whole-box jet computation | 4.593 s |
| checker evaluation link | 4.282 s |
| abstract verdict derivation | 2.846 s |
| representation abstraction | 2.193 s |
| Taylor upper computation | 2.117 s |
| computed finish | 1.142 s |
| numerical acceptance | 1.059 s |
| center environment | 0.966 s |
| box representation | 0.689 s |
| center jet | 0.557 s |

The remaining small theorem instantiations, source rewrite, endpoint
transport, cell handoff, and profile overhead make up the balance. This split
is important: roughly half the recurring cost is evaluator work and half is
theorem/representation plumbing. There is no evidence that generating 43
source programs would remove either half.

## Bounded probes and retained correction

Two intentionally bounded alternatives were rejected:

1. A monolithic call that attempted to put the complete high-level checker
   under one `Kernel.compute` boundary failed first with
   `Kernel.compute: rhs is not a cexp` and, after mechanically exposing the
   wrapper definitions, with `Kernel.compute: term is not a compute_exp`.
   The current staged calls are therefore imposed by the present Candle
   translator boundary, not merely historical structure. No monolithic probe
   code was retained.
2. An early flag-projection theorem bridge passed end to end and reproduced
   the exact final theorem, but replay took about 26.277 seconds and total
   time 50.41 seconds. It was within noise and slightly worse than the simpler
   bridge, so it too was removed.

One low-risk correction was retained: the prover now removes `LET_END_DEF`
from the shared compute equations once when the prover loads, instead of
remapping the same equations for every one of 96 `Kernel.compute` calls.

Two clean exact-byte repeats gave:

| Measurement | Profile baseline | Repeat 1 | Repeat 2 |
|---|---:|---:|---:|
| 16-leaf/15-glue replay | 26.581 s | 25.881 s | 25.904 s |
| Complete timed command | 50.17 s | 49.75 s | 49.60 s |
| User CPU | 38.83 s | 38.13 s | 38.25 s |
| Peak RSS | 2,252,544 KiB | 2,252,544 KiB | 2,252,544 KiB |

The improvement is modest but repeatable: approximately 0.68 seconds per 16
leaves, or 42 ms per leaf. Both repeats produced the unchanged
1-program/16-leaf/15-glue result and final theorem digest.

## Three genuine source expressions in one prepared session

The first authenticated nonlinear target contains three distinct genuine
source disjuncts. A new focused batch prepared all three in one restored
session using the theorem-producing shared-jet reifier. It did not claim that
the two expressions unselected by the genuine certificate prove the target.

All three are supported without derivative expansion:

| Genuine source expression | One-program instructions | Preparation wall time |
|---|---:|---:|
| `cayleyR6u` disjunct | 1,554 | 142.482 s |
| selected `unit6 + deltaL_x` disjunct | 87 | 0.897 s |
| `deltaL_x4` disjunct | 40 | 0.420 s |

Each preparation returned assumption-free validity, source-correspondence,
compilation, and program-representation theorems. The batch made no new
axioms. External timestamps were required because Candle's in-process elapsed
values rounded these intervals to zero.

The complete timed command used 152.56 user seconds, 11.20 system seconds,
2:41.72 wall time, and 2,252,544 KiB peak RSS. The 16.58 seconds before the
first item was checkpoint restart and current overlay loading, paid once for
the batch.

This measurement changes the optimization priority slightly. The one-program
architecture scales to a substantially larger real polynomial source, but
its theorem-producing preparation is nonlinear enough to become material at
1,554 instructions. It should be charged once per source and reused across
boxes and certificates wherever source identity permits. It does not justify
smart derivative expansion; it motivates profiling the existing compact-AST
reification/source-correspondence path on the large program.

The next authenticated source-family boundary is action 296. Its source uses
square-root functions and `dihatn_x`, so it is outside the current polynomial
language. That is the appropriate evidence-driven point for extending the
reflected language and universal soundness theorem. A full 1,061-leaf legacy
replay is not needed merely to localize that source-support boundary.

## Timing interpretation and next experiment

After current-source preparation, reflected replay plus final assembly now
takes about 31.0 seconds; including the selected expression's one-time
preparation gives about 32.5 seconds. The previously measured legacy proof was
about 34 seconds from a richer close checkpoint. These figures are promising
but are not a matched speedup claim because their checkpoint contents and
measurement boundaries differ.

The next performance comparison should run legacy and reflected proofs from
the same authenticated live state over the same already-built certificate,
reporting separately:

1. shared source/certificate preparation;
2. legacy leaf proofs and composition;
3. reflected leaf proofs and unchanged composition; and
4. final theorem assembly and theorem-identity checks.

That colocated comparison should precede another evaluator redesign. In
parallel, the large 1,554-instruction source is now a concrete preparation
profiling target, and action 296 supplies the first real non-polynomial
language-coverage target.
