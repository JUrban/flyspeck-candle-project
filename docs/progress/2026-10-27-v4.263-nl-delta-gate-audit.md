## Audit result

The pre-proof dependency audit found that the two optimized delta executors
currently have successful-result well-formedness theorems and exact source
program identities, but no general object-rational semantic refinement of the
kind now proved for the nine ordinary instruction families.  The earlier plan
wording that their existing general contracts should directly discharge this
gate was too optimistic.  This is a proof-scope finding, not a numerical
failure and not evidence about the genuine certificate's validity.

The case-16594 program uses only six such instructions: three 39-operation
negative-delta-derivative programs and three 85-operation four-coordinate
delta programs.  A fallback to ordinary polynomial execution is therefore a
plausible architectural alternative if it retains acceptable bounds and
throughput.

## Bounded discriminator results

The unchanged generic compiled checker was first given a source in which each
of those six programs had a semantics-preserving zero/add suffix.  This
correctly defeated exact specialization, but the genuine certificate rejected
after 7.03 seconds.  The result is not a fair generic-polynomial benchmark:
the extra Taylor addition changes interval completion and can loosen bounds.

A proper development-only compiler variant was then prepared to retain the
source and certificate bytes while skipping recognition.  Two launcher
attempts stopped after 69.85 and 65.10 seconds before translation because the
proxy held cache metadata but not the required loadable parent theory
artifacts.  No timeout was raised and no parent/runtime rebuild was started.
`LR-125` now requires concrete ancestor artifact checks before another
translation child is linked.

The bypass experiment is therefore **inconclusive** and stopped.  It is not
being represented as evidence that specialization is required or unnecessary.
