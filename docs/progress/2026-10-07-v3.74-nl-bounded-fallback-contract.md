## Bounded scope of this specialization

This proof effort remains deliberately narrow.  The next bounded step is to
lift the same success/overflow distinction over a complete fixed-scale Taylor
completion, without changing the existing analytic theorem or certificate
acceptance.  It is not worth independently proving every arithmetic helper
before an executor can exploit the contract.

A fast implementation still needs a verified execution refinement from the
bounded logical operation to checked word arithmetic.  Any overflow must be
returned as data and trigger the exact path; the observed 135-bit maximum is
test evidence, not a universal theorem.  This separates safety proof work
from the much larger performance decision.

## Correction after auditing the complete control

The existing 225.8-second case16594 control already encodes all 875 jobs as
one prepared input, calls `Kernel.compute` once, keeps numerical intermediates
inside the evaluator, and returns one `Cexp_num 1` verdict.  Therefore a new
"flat one-call" experiment would repeat an experiment already completed.  In
particular, host-side per-cell invocation and large result handoff do not
explain the roughly 92-times reflected/native mixed-width ratio.

The two controlled native axes are already sufficiently separated on real
complete batches:

- holding the generic case16594 graph fixed, MPZ execution takes about 18.72
  seconds and exact mixed 128/192 execution takes 2.447 seconds, exposing a
  roughly 7.65-times representation cost; and
- holding exact MPZ arithmetic and the graph fixed, the compact one-call
  reflected control takes 225.8 seconds, exposing a separate roughly
  12.1-times encoded-executor cost.

Their product accounts for the measured approximately 92-times boundary.
The earlier case10173 work independently changed the derivative graph while
holding arithmetic fixed, and changed arithmetic while holding its optimized
graph fixed.  Another native micro-specialization is therefore not the next
large-gap experiment.

## Concrete larger-gap programme

The next implementation boundary is the verified compute executor, not batch
wrapping.  The staged plan is:

1. preserve the current `Num`/`Pair` executor and exact checker as the
   regression and overflow fallback;
2. add a total bounded scalar result carrying either a signed two-/three-limb
   value or overflow, with checked 128-bit endpoint and 192-bit accumulator
   operations and exact directed dyadic rounding;
3. prove a refinement from every successful bounded operation to the current
   natural-number operation, then lift it over one complete Taylor completion;
4. execute the unchanged 875-cell case16594 call through that experimental
   path and require byte-identical outputs plus 875/875 acceptance; and
5. require the 4,173-cell case10173 family to pass before broadening the
   instruction set or proof surface.

Preparation, evaluator time, fallback rate, theorem construction, total
elapsed time, and peak RSS remain separate measurements.  If the first
complete path does not materially narrow both the 7.65-times arithmetic and
12.1-times executor components, the extension stops before production
integration.  Complete-certificate time and exact acceptance remain the gate;
a faster isolated operation is insufficient.
