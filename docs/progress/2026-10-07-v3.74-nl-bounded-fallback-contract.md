isolated Candle branch at commit

It introduces:

- explicit exclusive endpoint and accumulator limits, `2^128` and `2^192`;
- a total checked result carrying either success plus the exact value or
  failure plus a fixed zero;
- a proved dispatcher which returns the checked value on success and the
  existing exact result on failure; and
- canonical fixed-scale addition and multiplication instances whose fallback
  results are proved equal to their existing exact definitions.

The generic fallback theorem, and the add and multiply instances, have no
hypotheses.  The focused computation test covers an in-range value and an
endpoint exactly at the exclusive limit.  The latter fails the bounded check
and returns the unchanged exact value through the proved fallback.  This is a
logical contract only: the current definition receives the exact value before
checking its range, so it does **not** yet claim or measure accelerated word

## Bounded scope of this specialization

This proof effort remains deliberately narrow.  The next bounded step is to
lift the same success/overflow distinction over a complete fixed-scale Taylor
completion, without changing the existing analytic theorem or certificate
acceptance.  It is not worth independently proving every arithmetic helper
before an executor can exploit the contract.

A fast implementation still needs a verified execution refinement from the
bounded logical operation to checked word arithmetic.  Any overflow must be
returned as data and trigger the exact path; the observed 135-bit maximum is
test evidence, not a universal theorem.  This separates safety proof work
from the much larger performance decision.

## Concrete larger-gap experiment

The next cheap experiment should hold the mathematical graph, exact natural
arithmetic, directed rounding, fixtures, and certificate acceptance fixed,
while changing only batch representation and evaluator invocation:

1. encode the full case16594 875-cell workload as one flat prepared input;
2. execute it through one `Kernel.compute` call rather than repeated
   per-cell/per-stage setup;
3. return only the compact acceptance data needed for theorem handoff; and
4. compare preparation, evaluator execution, result decoding, theorem
   assembly, total elapsed time, peak RSS, output identity, and 875/875
   acceptance with the current 225.8-second reflected control.

This isolates evaluator/setup and intermediate-result traffic while leaving
arithmetic representation unchanged.  It complements rather than replaces
the mixed-width native result: native 128/192 execution is 2.447 seconds on
the same family, leaving a roughly 92-times reflected/native target.  If the
flat natural batch recovers a substantial portion, the proof effort belongs
in a reusable batch interpreter theorem.  If it does not, the dominant next
project is the verified word-compute extension, informed by the already
positive two-family native gate.

After the one-family discriminator, the same representation must pass the
4,173-cell case10173 family before any broad proof port.  Complete-batch time
and exact certificate acceptance remain the gate; a faster isolated operation
is insufficient.
