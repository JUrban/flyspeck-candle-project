## Result

A reflected signed fixed-scale backend now executes the two dominant genuine
action-296 polynomial blocks entirely inside `Kernel.compute`.

The backend keeps every stored interval endpoint as a signed integer scaled by
`10^12`.  Products and Taylor accumulations use signed raw numerators, and the
only divisions are the directed floor/ceiling operations required at completed
Taylor-model node boundaries.  It performs no general rational normalization
or GCD computation in the hot polynomial path.

This is the in-Candle follow-up to the ordinary-ML discriminator in v1.94.  It
is explicitly non-release code: the performance and equality result establishes
that the representation is worth proving, but the new backend cannot authorize
a Flyspeck theorem until its general representation and soundness bridge is
complete.

## What this says about the research note

The source-based rational-normalization hypothesis is now measured and
material.  Removing general rational normalization from this genuine
polynomial workload produces a substantial speedup inside Candle itself, not
only in an untrusted host evaluator.

The other observations separate as follows:

- Repeated setup is worth amortizing, but it is not the main numerical gap.
  Source preparation is paid once, and the 64-box result remains 8.01--8.03x
  faster after both paths receive the same prepared inputs.
- Returning unnecessary intermediates is material.  The compact 64-box
  boundary improved the fixed path relative to the earlier full-output
  experiment.  The production checker should keep interval/jet intermediates
  inside the generally proved checker and return only the data required by its
  soundness theorem.
- External certificate preparation remains untrusted.  Nothing here moves
  theorem authority into host ML: Candle must check prepared expressions,
  boxes, programs, and certificates before using the compact verdict.
- The fixed-scale path preserved every tested bound exactly.  It therefore did
  not buy speed by loosening Hessian bounds or increasing the subdivision tree.

## Proof and integration boundary

The next proof stage is general, not per expression:

1. Define the ordinary signed-scaled semantics and prove the cval
   representation theorems for addition, negation, multiplication, comparison,
   and directed division.
2. Prove outward-rounding and interval-containment lemmas for the fixed-scale
   interval operations.
3. Lift those lemmas through first jets, Hessians, Taylor reconstruction, and
   the polynomial postfix interpreter.
4. Connect the resulting polynomial checker beneath the existing universal
   analytic/Taylor theorem.  A supported expression then needs only mechanical
   reification/source correspondence, not a bespoke calculus proof.
5. Replace the diagnostic equality oracle with the proved adapter, then run a
   complete genuine-leaf theorem and an amortized representative batch against
   the legacy path.

The exact-output evidence justifies this proof investment.  It does not yet
authorize use of the new backend in an S3 release claim.
