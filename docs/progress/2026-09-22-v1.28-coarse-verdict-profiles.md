## Result 1: the real LP slowdown is now separated by phase

The first complete phase profile used terminal 15 of the real
`hard_2.dat` certificate.  It returned the expected contradiction theorem for
402 constraint rows, 282 selected auxiliary rows, 424 variables, and 106
hypotheses.

| Phase | CPU seconds |
|---|---:|
| certificate decode | 0.05 |
| inequality initialization | 47.88 |
| prototype load | 18.83 |
| legacy complete terminal | 14.05 |
| reflected row selection | 0.51 |
| terminal number conversion | <0.01 |
| source normalization / variable discovery | 0.97 |
| dense source-number conversion / row reification | 142.09 |
| pre-compute proof preparation | 24.22 |
| `Kernel.compute` | 80.28 |
| theorem reconstruction | 9.03 |
| publication | 0.10 |
| final contradiction handoff | <0.01 |
| reflected complete terminal | 256.69 |

Approximately 69% of the reflected terminal is surrounding representation and
proof work; approximately 31% is verified evaluator execution.  The 16.48x
overall slowdown is therefore not an unavoidable `Kernel.compute` cost and
cannot be fixed by evaluator tuning alone.  The 142.09-second dense 402x424
row encoding is the largest target.

The next LP design is correspondingly narrower and coarser:

1. use sparse logical rows rather than rebuilding a dense variable vector for
   every source inequality;
2. prepare and authenticate immutable source-row correspondence once where it
   can be reused across terminals;
3. have the computed checker validate the complete numerical infeasibility
   certificate; and
4. apply one general soundness theorem to obtain the final contradiction,
   without reconstructing intermediate arithmetic proofs.

The 80.28-second computed fold remains a secondary optimization target; sparse
encoding and a verdict-oriented fold should reduce both dominant components.

## Result 2: one-shot nonlinear polynomial checking is effective

Candle now has a generic one-shot soundness theorem for a complete staged
nonnegative polynomial program.  The host prepares an untrusted plan;
`Kernel.compute` separately verifies the full plan's validity and evaluates
it; one generic theorem connects the symbolic input polynomial directly to the
computed upper bound.  The returned theorem is assumption-free and has the
same conclusion as the existing staged proof path.

The Flyspeck adapter passed exact conclusion comparison on both the
six-monomial first-derivative fixture and the 21-monomial/78-factor Hessian
fixture.  In the same checkpoint-isolated process:

| Path / workload | CPU seconds |
|---|---:|
| both legacy staged calls | 17.85 |
| both coarse reflected calls | 0.15 |
| reflected first derivative | 0.03 accounted |
| reflected Hessian | 0.11 accounted |

This is approximately **119x** for the two-call aggregate.  Compared with the
earlier Hessian breakdown of about 15.91 seconds, the 0.11-second coarse call
is approximately **145x** faster.  Its phases were 0.02 seconds source
planning, 0.03 seconds representation proof, evaluator time below the
0.01-second clock resolution, and 0.06 seconds theorem handoff.

This is a concrete validation of coarse proof-producing computation for the
isolated nonlinear numerical workload.  It is not yet a complete nonlinear
leaf result: domain logic, subdivision/partition reconstruction, and the exact
verifier handoff still need measurement.
