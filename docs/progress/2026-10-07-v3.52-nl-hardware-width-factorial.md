## Architectural decision

The current evidence separates three effects:

1. quotient normalization is about an 8% recurring cost on either hardware
   width, not a multi-fold explanation;
2. reducing the scalar width and layout from `long double` to `double` is a
   real 1.49-times effect;
3. even the unsafe `double` lower bound leaves about a 2.1-times
   whole-checker/dataflow gap to the specialized C++ implementation.

There will be no standalone proof for the center-tangent, additive-leaf, or
historical-formula branches. They remain reusable implementation pieces only.
Nor will the formal checker depend on unproved host floating-point behavior.

The next bounded proof-performance gate is representation feasibility inside
the actual reflected path:

1. establish whether `Kernel.compute` can efficiently execute a closed,
   assumption-free word-sized endpoint microkernel with signed shifts and a
   checked 64-by-64-to-wide product/accumulator;
2. use the measured range contract: normalized endpoints/results need at most
   45 bits, raw products 68 bits, and quotient/Taylor numerators 83 bits;
3. compare that microkernel with the existing arbitrary-integer dyadic
   implementation, charging encoding, `Kernel.compute`, theorem handoff, and
   any reusable range/correspondence proof separately;
4. only if the reflected word path wins materially, implement one generally
   proved outward dyadic interval engine and the complete-box checker over it.

This is not a new per-expression calculus layer. The existing universal
analytic theorem remains the bridge. External preparation may supply indexed
rows, fixed encodings, and numerical plans, but Candle must cheaply verify
their correspondence before the reusable checker theorem is instantiated.

If the word microkernel does not win in `Kernel.compute`, the `double` result
remains diagnostic and the next experiment must target the remaining
whole-checker layout/control directly rather than recreating hardware floats
over slow arbitrary integers. Multi-certificate throughput, with preparation
amortized only when actually shared, remains the selection gate.
