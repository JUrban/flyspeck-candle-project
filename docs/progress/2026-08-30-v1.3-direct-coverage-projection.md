# Direct nonce-free coverage projection (2026-08-30)

## Result

Project commit `320d18cf63b94384ec972795abe804040b7d249a` adds the
second pure value protocol required by the corrected direct S2/S3 release
design.  `scripts/direct_release_protocol.py` now validates strict,
nonce-free direct semantic and coverage projections.  It does not authenticate
a raw runtime result and exposes no approval operation.

The coverage projection requires the exact final boundary and all 297 ordered
actions; a distinct logical-source schema; loader-owned physical-source event
closure; exactly 43 generated inputs with the pinned class multiset; all 39 LP
certificates with positive consumption evidence in manifest runtime order; the
four final theorem/dependency requests; and categorical PFT rejection.  It
also cross-checks logical and physical source keys and reserves the runtime
control namespace, preventing independently valid sections from being
spliced into a false closure.

Schema 5 remains permanently insufficient: its certificate records
authenticate presence, not consumption.  The project adapter
`coverage_projection_from_schema5` therefore always fails closed.  A future
disjoint Candle producer/validator must authenticate consumption before a
production coverage projection can be built.

## Hostile review and checks

The focused test suite passes 16/16 under isolated Python and covers boundary,
action, source, generated-input, consumption, PFT, type, canonical-JSON, and
control-character mutations.  During hostile review, accepted findings closed:

- PFT-labelled paths and source keys despite false `pft_used` fields;
- collapsed generated-input classes;
- reordered or aliased consumption records;
- logical/physical source splicing;
- reserved-control collisions and arbitrary derivation relabelling;
- raw-schema/projected-schema ambiguity; and
- NUL, tab, newline, or DEL path components.

## Remaining boundary

S2 execution approval, direct S3 coverage approval, or release-level v1.3 S3.
Next, Candle needs a disjoint authenticated certificate-consumption schema,
followed by a descriptor-bound project extraction/consumer path and pristine
