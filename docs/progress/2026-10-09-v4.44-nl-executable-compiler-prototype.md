## The executable compiler is the correct prototype route

The bounded historical-delta program no longer uses a fresh verified x64
`CompileTheory` in its ordinary experiment loop.  Its already translated
CakeML AST is serialized with `astToSexprLib`, then passed directly to the
existing executable compiler:

```text
cake --sexp=true --exclude_prelude=true --skip_type_inference=true
```

This preserves the proved HOL-to-CakeML translation boundary while avoiding
re-evaluation of the compiler correctness development for every checker
revision.  It does **not** create a per-program compilation theorem, so the
result is suitable for development measurements only.  A verified compile is
retained as a later release-evidence step after the checker architecture and
program bytes are frozen.

The executable compiler reports CakeML source identity
`4e312c0f7e18b9c5789c8ac4e0af257bff895cf5`, which is an ancestor of the
current checked-executor worktree.  Its executable SHA-256 is
`d361be3839f31811328d5a0da1ecea15a8a73f369c77e34a288355f16bb930d3`.

## Decision and next use

The direct executable-compiler route is now the default for bounded-word
checker development.  The next matched experiment can therefore expand from
the 128-cell transfer gate to the complete 4,173-cell historical batch without
paying a compiler-proof replay after each coherent program edit.  It must
still preserve exact output equality, complete certificate acceptance,
fail-closed input discipline, total elapsed cost, and peak memory.

The verified compile path remains present but paused.  It will be resumed only
at a real integration/release boundary for exact frozen program bytes.
