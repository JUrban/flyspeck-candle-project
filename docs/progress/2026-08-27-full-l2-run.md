# Full L2 run and restart repair — 2026-08-27

The locked full export is running from the tested Flyspeck pin.  Its first
producer generation initialized `Multivariate/flyspeck.ml` and wrote a source
boundary at 8,426,454,932 bytes and 954,146,174 commands.  A forced DMTCP
restart reproduced that offset and all PFT table counters exactly.

That restart exposed a supervisor defect: `dmtcp_restart --coord-port 0`
selected a new coordinator port, but the restored process's subsequent
`dmtcp_command -kc` could not discover it.  Commits `2123ef0` and `912404e`
make each generation publish its coordinator port through the run state,
route only Candle's checkpoint-and-kill command through that port, and retain
monotone generation log numbers after a supervisor restart.  Commit `38a8e74`
also confines DMTCP-generated helper files to the run state on future
supervisor invocations.

An emergency mid-proof DMTCP image restored but once crashed after
`leg/collect_geom2.hl`; it is not treated as a supported recovery boundary or
as logical evidence.  A controlled retry reached the next exporter-managed
source boundary.  The embedded callback then checkpointed and killed the
producer through the published port at source 20:

```text
checkpoint  20  jordan/parse_ext_override_interface.hl  9011001597
            1018557958  103005  243740  30762412
```

The next generation restored this source-safe image with the exact same
offset, command count, and type/term/theorem counters, changed status to
`resumed`, and continued writing.  Source 30 subsequently reached another
safe boundary at 9,116,150,054 bytes and 1,029,416,896 commands.  These are
interim operational results only: the export, four-target compiled replay,
axiom audit, and final resource record must all finish before Gates 2, 8, 9,
or 11 can be closed.

The installed DMTCP defaults to gzip images.  At the measured producer size,
each checkpoint took about four minutes to compress and two minutes to
restore.  The remaining 266 source files, 39 LP shards, and 812 nonlinear
cases imply roughly 99 further image cycles, so compression alone would cost
about ten hours.  An isolated process was launched with `DMTCP_GZIP=0`,
checkpointed, restored, and checkpointed again; both images were uncompressed
and valid.  Setting the variable only at restart did not change an image
originally launched with gzip, so no live runtime mutation was attempted.

The gzip run has therefore been stopped at its exact source-30 trace boundary,
with its finalized image retained as a fallback.  A separate full run now
uses a state-locked `checkpoint_gzip=0` while retaining the same logical repo
heads and LP/nonlinear hashes.  The supervisor defaults fresh runs to this
mode, adopts an older state's recorded mode on resume, retries failed restored
generations only after truncating to their recorded PFT boundary, and samples
resource use every ten seconds.  This trades one fresh foundation build and a
larger single retained image for substantially lower total CPU time; it does
not alter the PFT stream or the final compiled-checker trust boundary.
