## The remaining fail-closed hole

The authoritative Candle integration contains `build-local-cakeml.sh` and
`candle/test_dopen_runtime.sh`, but no `candle/build/cake`, root
`config_enc_str.txt`, or root `candle_boot.ml`.  The selected CakeML checkout
also currently lacks the ignored generated inputs
`compiler/bootstrap/compilation/x64/64/cake.S` and `config_enc_str.txt`.
Consequently a build or smoke attempt is blocked today, as it should be.
The two low-cost negative checks returned exit 1 with, respectively,
`missing bootstrapped CakeML input: .../x64/64/cake.S` and
`missing generated Candle runtime input: .../config_enc_str.txt`.

The gate would become unsound if those missing files were merely supplied and
the existing scripts were then treated as provenance evidence:

1. `build-local-cakeml.sh` checks the CakeML Git HEAD and tracked diff, but
   copies ignored `cake.S` and `config_enc_str.txt` without an authenticated
   generation record.  An ignored output from an earlier source revision can
   coexist with HEAD `936219bbc`.
2. It does not check the HOL checkout revision used to generate those outputs.
3. It prints output hashes after linking but stores no machine-readable record
   binding input hashes, CakeML/HOL revisions, patch identity, and executable
   hash.
4. `test_dopen_runtime.sh` accepts an arbitrary launcher.  It neither resolves
   and hashes the invoked executable nor checks the compiler's embedded
   `CakeML:` and `HOL4:` version lines.
5. The synthetic smoke checks useful value/constructor/shadowing behavior, but
   it is not the manifest-required real corpus-derived open-dependent slice or
   the pinned OCaml/HOL Light fingerprint comparison.

The separately installed compiler at
`/project/repos/candle/candle/build/cake` has SHA-256
`d361be3839f31811328d5a0da1ecea15a8a73f369c77e34a288355f16bb930d3`
and reports CakeML source
`4e312c0f7e18b9c5789c8ac4e0af257bff895cf5` and HOL4
`63f2eb9c146352dfd0bab8c5604a096d1e554d03`.  It predates the Dopen stack and
is explicitly ineligible for this gate, even when its observations remain

## Narrow mechanical gate

Before any compiled result can advance G1/G2, require one machine-readable
build record and make the runtime runner consume it:

1. Regenerate the named proof and x64 bootstrap targets from clean exact
   CakeML/HOL worktrees.  Record the two Git revisions, build command, target
   list, completion status, and SHA-256 of every copied bootstrap input.
2. Before linking Candle, reject a missing record, a dirty or mismatched
   worktree, a missing input, or any input hash mismatch.  Checking HEAD alone
   is insufficient for ignored generated files.
3. After linking, require `cake --version` to report CakeML `936219bbc...` and
   HOL4 `a390cbab...`; record the executable, patched assembly, Basis FFI,
   `candle_boot.ml`, and configuration hashes.
4. Before the Dopen smoke or corpus runner starts, resolve the launcher's
   executable and fail unless its SHA-256 and embedded revisions exactly match
   that build record.  Write those identities into the observation.
5. Keep the manifest activation status pending after the synthetic smoke.
   Promote it only after a manifest-selected, corpus-derived open-dependent
   slice matches independently pinned OCaml/HOL Light fingerprints.

The stable project regression name for steps 1–4 is
`PROJECT-DOPEN-ARTIFACT-PROVENANCE-GATE`; the existing synthetic test is
`CANDLE-DOPEN-RUNTIME-SMOKE`.  Neither is marked passed in the project ledger.
