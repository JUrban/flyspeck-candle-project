## Result

actual Candle `Kernel` module, before that module is closed.  The public
`Kernel.compute` implementation is the proved chain

```text
authenticated specialized packet evaluator
  -> general pure evaluator on a miss
  -> existing verified exec evaluator on a second miss
```

The successful specialized branch performs the canonical fail-closed packet
decode, center and box calculations, square-root and reciprocal certificate

lineage problem.  It does not yet close the live runtime theorem, original
Flyspeck theorem, or varied-certificate batch milestones.

## Trusted theorem mechanism

The fast result is not trusted stdout.  Its authority is the existing
`compute_fast_eval_ok` contract:

```text
fast_eval ceqs cexp = SOME result
  ==> verified compute_eval ceqs cexp = result
```

The registered evaluator authenticates the exact characteristic-equation
bundle and closed call, accepts only after the complete packet checker
returns its canonical verdict, and has a HOL4 proof of that refinement.
`compute_with_thm` uses the refinement theorem statically and constructs the
ordinary assumption-free equality with the kernel's `mk_eq`; it does not
replay `compute_eval` at runtime.  Misses and malformed data remain
fail-closed through the existing fallbacks.

The genuine cell-0 path is proved at four levels:

1. the packet checker returns `SOME (Num 1)`;
2. the registered evaluator returns the exact registered result;
3. the evaluator satisfies `compute_fast_eval_ok`, and its `compute_with`
   wrapper satisfies the kernel theorem contract; and
4. the packet-first chain is translated as the public production
   `compute_v`, whose translation theorem is preserved.

## What remains for the fast production result

The current registered experiment deliberately freezes one genuine packet.
It proves the mechanism and measures the complete cell calculation, but it
is not yet a general batch interface.  The shortest remaining path is:

1. finish the downstream Candle value, permission, kernel-function, and
   prover-semantics proofs for the exact new `compute_v` bytes;
2. invoke the exact registered call through a running Candle runtime and
   record the returned assumption-free equality, separating equation checks,
   fast execution, equality construction, and theorem handoff;
3. apply the existing universal analytic/source contract to that equality and
   obtain the original case-10173 Flyspeck theorem;
4. replace the frozen one-cell registration with authenticated varying packet
   data under the same logical equation/program role, without weakening the
   strict decoder or call identity; and
5. run a small varied genuine batch, charging shared preparation once and
   measuring decode, numerical execution, theorem handoff, total elapsed
   time, acceptance, and peak memory.

The main uncertainty has moved from numerical execution to integration:
whether the downstream permission/runtime proofs and original-theorem adapter
remain compact, and how much time theorem construction adds to the measured
1.4 ms/check numerical slope.  No further broad profiling project is needed
before resolving those concrete boundaries.
