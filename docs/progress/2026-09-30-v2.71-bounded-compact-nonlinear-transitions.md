## Implementation

The compact adapter now exposes a proof-producing transition result containing:

1. the exact unconsumed decoded-job suffix;
2. a theorem that this suffix is accepted for the original reflected source;
   and
3. the updated compact root stack with its universal pass invariant.

This is derived from the existing general `compact_run_sound` theorem. No new
axiom or unchecked theorem conversion is introduced. The prior all-consuming
API remains as a wrapper and still rejects a nonempty remainder.

The complete case-16594 prover splits each batch's postorder token segment into
pieces of at most two tokens. Each transition consumes the authenticated
remainder from its predecessor and returns the theorem needed by its successor.
The batch is accepted only when the final remainder is empty.

An initial real-data test failed closed at `MATCH_MP`. That exposed one stale
assumption from the old API: the soundness theorem was still instantiated with
an empty remainder even when the evaluator returned a nonempty suffix. The
narrow correction instantiates it with the evaluator's exact reduced remainder.
No numerical checker, certificate data, analytic theorem, or source expression
was changed.

## Architectural assessment

This result rescues the compact-invariant design from the maximal-segment
failure reported in v2.70. The plan-wide scan found original segments as large
as 12 tokens; the production prover now imposes a uniform two-token bound
independent of those shapes. Large decoded acceptance theorems are not appended
or accumulated: only the exact remaining suffix theorem and compact stack
invariant are threaded.

This does not yet prove complete-case scalability. The complete 875-cell run is
still required, particularly across and beyond the old failure at chunk 140.
The reflected whole-certificate architecture remains a useful longer-term
direction if repeated theorem transitions still dominate, but it is no longer
necessary to abandon the current compact path before that full measurement.
