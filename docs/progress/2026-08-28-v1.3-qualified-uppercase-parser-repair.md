## Root cause and repair

Dopen commit `29c4d2c94` correctly broadened module identifiers to
`identModule`.  The former value-path grammar parsed an optional greedy module
path followed by a value name.  It could therefore consume all of
`Kernel.EQ_MP` or `Meson.POLY_ASSUME_TAC` as a module path and then fail for
lack of a terminal value.

The repair mirrors CakeML's established qualified-constructor solution:

```text
value-path ::= module-name "." value-path | value-name
```

The parse-tree converter likewise recurses on the remainder and prepends the
single converted module name.  The resulting AST is unchanged; for example,
`Kernel.EQ_MP` remains
`Var (Long «Kernel» (Short «EQ_MP»))`.  No Candle/Flyspeck source-open
workaround is present.

The commit changes only:

- `compiler/parsing/ocaml/camlPEGScript.sml`;
- `compiler/parsing/ocaml/camlPtreeConversionScript.sml`; and
- `compiler/parsing/ocaml/camlTestsScript.sml`.

The three added regressions cover a multi-component uppercase terminal
(`Aa.B_b.POLY_ASSUME_TAC`), the exact first Candle expression
(`Kernel.EQ_MP`), and a complete `let f = Kernel.EQ_MP` definition.  Existing
lower-terminal value paths, constructor paths, dotted opens, and module
definitions remain in the same test theory.
