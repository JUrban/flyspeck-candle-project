## Intended analytic-bridge scope

The destination is one reusable theorem for **every valid expression in the
supported reflected language**, not a separately developed calculus proof for
each Flyspeck expression.  Schematically, for an expression `e` valid for an
`N`-coordinate environment, the generic theorem should establish all of the
following at once:

```text
denote e x                    = value(e,x)
partial (i+1) (denote e) x    = gradient(e,x)[i]
partial2 (j+1) (i+1)
  (denote e) x                = hessian(e,x)[j,i]
diff2c_domain box (denote e)
```

Together with sound interval evaluation of `value`, `gradient`, and `hessian`,
Flyspeck's existing Taylor theorem should then yield a checker theorem of the
form:

```text
valid e N /\ domain_ok e box /\ computed_accept e box
==> !x. x IN box ==> denote e x < 0
```

The exact final statement will retain Flyspeck's native `partial`, `partial2`,
`diff2c_domain`, interval, and inequality interfaces.  The display above is a
scope contract rather than a claim that this final theorem has already been
proved.

Per-expression obligations should consequently be mechanical only:

1. reify the original Flyspeck formula to an authenticated AST and prove the
   source formula equals its denotation;
2. prove syntactic validity and any operator-domain certificate;
3. supply the original box and exact numerical certificate; and
4. evaluate the generic checker.

There should be no handwritten derivative or Taylor-remainder proof for each
of thousands of expressions.  Extending the supported language will require
one constructor-level calculus and domain proof for each new operator family,
not one proof for every expression using that operator.

## Executable symbolic-derivative milestone

Candle commit `24d19f6` adds structural symbolic differentiation over the
dimension-parametric polynomial AST:

```text

candle_poly_diff2 : coordinate -> coordinate -> expression -> expression
```

The kernel proves universally that the generated ASTs denote the already
proved analytic gradient and Hessian components.  It also proves that compiling
those generated ASTs produces the exact real derivative values, and that the
existing reflected interval evaluator encloses them:

```text

candle_poly_diff2_value_fun
candle_poly_diff_compile_real_program
candle_poly_diff2_compile_real_program
candle_poly_diff_interval_sound
```

All exported theorems have empty hypothesis lists.  A six-variable fixture
`x1*x6 + x3^2` produced a 15-instruction first-derivative program and a
31-instruction mixed-second-derivative program.  This establishes a sound,
immediately executable baseline: a six-variable whole-box checker can run one
value, six gradient, and 36 Hessian programs.  It does **not** yet claim the
more efficient one-pass shared jet implementation.
