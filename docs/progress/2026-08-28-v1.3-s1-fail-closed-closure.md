# Great100 S1 fail-closed closure machinery — 2026-08-28

The live 65-target Great100 baseline remains useful load, timing, failure, and
resource evidence, but it cannot be promoted retroactively to roadmap level
S1.  Its pinned runner, `110a18d485557ae877d0cb47bb9172e6558ddf61`, does
not request theorem fingerprints.  Each S1 target must therefore be rerun in a
fresh Candle process after an independently approved reference identity exists.

## Exact current boundary

- The manifest has 65 targets over 66 source files and requests 97 theorem
  values.
- Sixty-three theorem mappings are source-audited.  `100/cantor` and
  `100/fourier` remain manual review.
- Approved expected identity coverage is 0/65.  Existing isolated observations
  are `observed_uncompared`, not matches.
- A target load pass is not an S1 theorem-identity pass.

## Implemented acceptance policy

Candle commit `8a0aef45f791a150f2ea1ffea9022681e9842ee5`
(`regression: fail closed on S1 identities`) adds exact expected-identity
comparison and an explicit suite closure summary.  The comparison requires:

- an audited mapping and a pinned fingerprint serializer SHA-256;
- the exact ordered theorem list with theorem, hypotheses, conclusion, and
  global-axiom SHA-256 identities and hypothesis/axiom counts; and
- complete equality between the approved reference record and the observation.

Missing expected records remain `observed_uncompared`.  A serializer mismatch,
manual-review mapping, malformed expected object, or any observed identity
mismatch fails closed.  The JSON report exposes matched, incomparable, and
missing-or-failed counts; `suite_closed` is impossible unless all 65 targets
match and no mapping remains manual review.

The checked-in `candle/S1_CLOSURE_CHECKLIST.md` records the independent
reference procedure, rerun and invalidation rules, per-target invariants, and
the 65/65 suite closure condition.  In particular, observed Candle hashes must
never be copied into their own expected values.

A subsequent source audit, integrated as Candle commit
`77d4e1142d5c347d75e30fc6724e9e0ab477549d`, resolves two former manual
boundaries.  `100/piseries` explicitly labels `EULER_HARMONIC_SUM` as its most
famous special case, and the final `100/quartic` rebinding changes only the
proof of a byte-identical theorem statement.  `100/cantor` remains ambiguous
because a historical cardinality theorem is shadowed by a distinct
no-surjection formulation; `100/fourier` remains ambiguous because it presents
four non-equivalent headline results without selecting a canonical boundary.
Both unresolved targets continue to fail closed.

## Validation and next work

After the current integration, the complete Candle Python host suite passes 82 tests, the
correct timeout module passes 10 tests, Python compilation succeeds, and the
generated Great100 manifest check reports exactly 65 targets, 66 files, and
one explicit exclusion.  An earlier focused invocation misspelled the timeout
module as singular; it failed only to import that nonexistent name, and the
correct pluralized module subsequently passed.

This commit adds no S1 matches by itself.  Closure still requires resolving the
two manual mappings, producing reviewed identities from the pinned HOL Light
reference, finishing compatibility repairs, and rerunning every target under
the pinned compiled Candle artifact.  The current baseline is deliberately
left untouched while it completes.
