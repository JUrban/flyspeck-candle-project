## Intended scale of the analytic bridge

The destination is one theorem for **every valid expression in the supported
language**, not a separate calculus development for each Flyspeck expression.
The Taylor contract is a useful intermediate interface, but it must itself be
obtained from a language-wide connection between the reflected jet evaluator
and the denotational semantics.

In schematic form, the central reusable theorem should be:

```text
UNIVERSAL_JET_ANALYTIC_CORRECT:
  valid n e /\ domain_ok box e
  ==>
    diff2c_domain box (denote e) /\
    (!x i.
       x IN box /\ i < n
       ==> jet_value (eval_jet e x) = denote e x /\
           jet_grad (eval_jet e x) i =
             partial (i + 1) (denote e) x) /\
    (!x i j.
       x IN box /\ i < n /\ j < n
       ==> jet_hessian (eval_jet e x) i j =
             partial2 (j + 1) (i + 1) (denote e) x)
```

The exact final statement will use the reflected interval evaluator rather
than the schematic exact-real `eval_jet` above, so its conclusions will be
sound enclosure relations.  A generic Taylor theorem and the one generic
computed-checker soundness theorem will then yield:

```text
SOURCE_WHOLE_BOX_ACCEPT_SOUND:
  valid n e /\
  domain_ok box e /\
  source = denote e /\
  computed_checker_accepts e box certificate
  ==>
  !x. x IN box ==> source x < 0
```

These quantifiers are the important scaling property: `e` is universally
quantified.  The calculus, derivative/Hessian correspondence, Taylor
remainder argument, and computed-checker soundness are paid once per language
constructor, not once per expression.

## Genuinely per-expression obligations

A concrete Flyspeck formula should contribute only:

1. a mechanically generated, kernel-checked theorem `source = denote e`;
2. a mechanically checked `valid n e` result;
3. for partial primitives, a computed domain certificate for the chosen box;
4. the box and numerical certificate data; and
5. a `Kernel.compute` acceptance result.

Items 1 and 2 already exist for the polynomial language.  They are theorem
instances generated by a strict reifier, not hand-developed calculus proofs.
Polynomials need no domain premise beyond valid variable indices and exact
constant encodings.  When the language is extended with division, square
root, inverse trigonometric functions, or other partial primitives, each
constructor will receive one reusable analytic theorem and an explicit
computed `domain_ok` condition.

## Proof route and remaining hypotheses

The staged route is:

1. **Polynomial structural calculus.**  Lift the new indexed components to
   `real^N` and prove, by one induction over the AST, `diff2c`, `partial`, and
   `partial2` correspondence for every valid expression.
2. **Dimension-parametric interval jet.**  Evaluate value, gradient, and
   Hessian interval data as ordinary reflected lists.  Prove one enclosure
   theorem by the same AST induction.
3. **Generic Taylor handoff.**  Instantiate Flyspeck's existing Taylor theorem
   from the universal analytic theorem and the computed jet enclosures.
4. **First real target.**  Reify the authenticated `cayleyR6u`, `unit6 +
   deltaL_x`, and `deltaL_x4` source functions and check all 16 leaves from
   original expressions and boxes.
5. **Language growth driven by real targets.**  Add a primitive only when a
   subsequent certificate needs it, with one constructor theorem and one
   explicit domain-checking rule.

The remaining general hypotheses are therefore visible rather than hidden:
well-scoped variables, sound exact constants, box membership, and domain
safety for partial primitives.  Polynomial expressions discharge the last
condition trivially.  There is no planned per-expression smoothness,
derivative, Hessian, or Taylor-remainder proof.
