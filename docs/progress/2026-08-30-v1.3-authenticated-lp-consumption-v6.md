## Result

Candle branch `codex/flyspeck-v13-direct-consumption` now has a disjoint
direct-evidence schema 6 through commit `5e75cb9`.  Schema 5 remains the
default and retains its exact field set.  Schema 6 is explicit and adds a
nonce-bound contract for the 39 authenticated runtime LP certificates, one
HOL-side `CONSUMED` event after each successful certificate deserialization,
and an exact terminal closure before the loader-owned source-trace terminal.

The contract fixes the class multiset at 38 ordinary certificates plus the
one prepared `hard_7.dat`, fixes basename-lexicographic runtime order, binds
root-independent identities to the semantic evidence plan, and rejects PFT
tokens categorically in both relative and absolute paths.  The receipt remains
an unapproved raw observation: it sets no S2/S3 eligibility or approval and
does not use PFT.

The runtime CLI accepts `--evidence-schema {5,6}`.  V6 execution and public
artifact validation are restricted to the exact non-diagnostic cumulative
boundaries and counts:

- `05-lp_support-through-184`: 185 actions;
- `06-text_formalization-through-290`: 291 actions;
- `07-final_assembly-through-296`: 297 actions.

Every consumption event must lie strictly between the attempt preflight and
boundary-success records.  More precisely, all 39 events must lie after the
authenticated action-183 marker and before the action-184 marker emitted after
the exact LP-support action completes.  The LP terminal must lie strictly after
the boundary and before the physical source-trace terminal.  This prevents an
otherwise internally valid consumption namespace from being relocated into a
different action or phase of the authenticated log.

The terminal is additionally bound to the exact generated-postlude predecessor:
the structural-fingerprint terminal at boundaries 05/06 and the ordered
dependency-history terminal at boundary 07.  It therefore cannot be moved
ahead of those observations while remaining inside the broader interval.

## Project-side projection

Project commit `3a1a925` adds
`coverage_projection_from_schema6(receipt, authenticated_plan)`.  The pure
adapter is intentionally not a raw-result authenticator; its caller must first
run Candle's schema-6 receipt/log/snapshot validator.  It nevertheless rebinds
the canonical `plan.json` bytes to the plan file record inside the receipt,
because the exact 43-input inventory is carried by that plan.

The adapter produces the existing strict nonce-free coverage projection.  It
removes attempt nonces, absolute runtime paths, and physical binding IDs while
preserving all 297 action outcomes, logical and physical source closure, the
43 generated inputs, and 39 exactly-once consumption records.  It exposes no
approval operation.  Schema 5 continues to fail closed for this projection.

Project commit `908295b` extends the descriptor-held direct result consumer
without changing its default schema-5 scheduling behavior.  With explicit
`--evidence-schema 6`, the consumer authenticates the projection module from
the exact project commit, applies Candle's v6 receipt/log/snapshot validator
while holding the pinned plan/result descriptors and shared runtime lock,
rechecks all authorities, and returns an unapproved content-bound capture.

The capture binds canonical receipt and plan byte records, both nonce-free
projections, and the exact project, Candle, CakeML, HOL4, and Flyspeck commits.
Its validator requires the original receipt and plan together and rederives
both projections; a detached capture JSON object cannot validate itself or act
as approval evidence.  The capture sets `approval_included`, `pft_used`, and
`s2_s3_evidence` categorically false.
