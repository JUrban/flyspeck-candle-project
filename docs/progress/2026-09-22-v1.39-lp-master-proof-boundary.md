## Internal clocks cannot profile Candle proof subcalls

An exact five-terminal run added timers around the master proof constructors.
All five final theorem conclusions, hypothesis sets, theorem digests, and
axiom gates passed, but every internal duration was zero. This is expected:
the selected Candle runtime deliberately implements both `Sys.time` and
`Unix.gettimeofday` as deterministic zero rather than exposing a clock FFI.
The run is preserved as a failed measurement method, not interpreted as a
zero-cost result.

The external observer still measured the complete authenticated-row phase at
171.90 seconds, consistent with the 171.35-second numeral-cache run. The
profiling-only branch is `codex/cv-lp-master-subphase-profile-v1`, commit
`4076187`, and is not a production candidate.

## Externally timed cumulative stages isolate the cost

A replacement run selected every fourth sorted source conclusion: 416 rows
spread over the exact 1,662-row master, retaining the complete 610-variable
basis. Each cumulative stage used a fresh checked context and an explicitly
cleared numeral cache. The final master-size and global-axiom gates passed.

| 416-row stage | wall time (s) |
|---|---:|
| cached numeral standardization only | 0.05 |
| proof construction through decoded entry lists | 36.63 |
| through generic `lin_f` denotation | 36.49 |
| complete reusable master rows | 43.39 |

The tiny negative difference between the middle stages is run noise: adding
the generic denotation theorem has no separately measurable cost at this
scale. Concrete coefficient/selector/list correspondence consumes about
84.4% of complete sampled master construction. Linear extrapolation gives
about 173.3 seconds for the full master, closely matching the independently
measured 172.31 seconds. The evenly spaced sample is therefore representative
for this decision.

This corrects the emphasis of the previous next-step description. The
remaining cost is not 1,662 expensive arithmetic denotation theorems; it is
the concrete proof that each sparse entry list corresponds to the exact
authenticated Flyspeck coefficient/variable list. A coarser checker must
remove or aggregate that proof boundary while still linking the exact source
terms—it is not enough merely to wrap the already-cheap denotation theorem.

## One-pass rewriting is rejected

The same 416 rows were then checked in one run with two fresh contexts. The
current list/pair congruence chain took 36.55 seconds. A candidate that used
one `REWRITE_RULE` per entry to apply the coefficient, selector, and tail
theorems took 59.96 seconds, **64.0% slower**. Both paths had exactly 859
numeral-cache hits and 70 misses; the candidate checked every resulting
theorem's exact conclusion and empty hypothesis set, and the global axiom set
was unchanged.

The rewrite candidate is rejected. The current constructor is already the
better local proof method, so further independent per-row rewrites are not a
promising direction. The next LP prototype should instead aggregate the
source-entry correspondence behind one reusable relation/soundness theorem,
with the source-term link and malformed-plan rejection explicit.
