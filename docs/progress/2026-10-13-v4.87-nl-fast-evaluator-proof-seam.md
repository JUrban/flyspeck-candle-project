## What the new timing means

The 46.5-second run is reusable/offline theorem preparation for the genuine
registered call.  It is not intended to recur for every production theorem.
It improves substantially on the unsuccessful direct simplifier attempts,
which did not finish in 14--50 minutes, and it gives a practical way to prove
the first gate while the general refinement is developed.

It is **not** the still-open matched execution comparison.  The 46.5-second
run executes the original 271-equation generic wrapper through a CV-translated
first-order evaluator.  The approximately 1.37-ms compiled run executes the
specialized fixed-word cell checker.  The numerical algorithms are related,
but not identical executable programs.  Consequently neither figure should
be presented as the current Candle/compiled ratio for the same checker.

The important result here is that the theorem handoff itself no longer
requires a roughly 200-second generic replay once the fast evaluator's
refinement theorem is available.

## Intended production path

The production path is now:

1. Authenticate the complete source/program, certificate, and topology data.
2. Decode them to the fixed-word checker representation.
3. Execute the complete specialized checker in translated/compiled CakeML.
4. Use a proved refinement theorem to show that an accepted fast result is the
   result of `compute_eval` for the authenticated wrapper call.
5. Let `compute_with` return the ordinary assumption-free equality theorem.
6. Reuse the universal source, analytic, Taylor, and topology theorems to
   obtain the original Flyspeck inequality theorem.

The exact cell-0 registration proves steps 4--5 for one genuine call.  The
existing analytic results and live-wrapper capture establish the required
shape of steps 1 and 6.  The next reusable obligation is to replace the exact
one-call evaluation proof with a general decoder/checker refinement theorem.

## Smallest remaining checker extension

The numerical cell checker itself does not need another arithmetic layer for
the first complete-cell result.  The smallest extension is at its boundary:

- a canonical decoder from the authenticated wrapper data to the word-level
  center, box, certificates, and program inputs;
- inclusion of compact certificate topology and job-consumption checks for a
  multi-cell certificate;
- a result encoder matching the wrapper's `cval` result; and
- one general refinement theorem connecting those operations to the existing
  complete-wrapper semantics.

Source/equation-bundle authentication should be paid once per checker/batch,
not once per leaf.  Per-leaf work should be decoding the changing box and
certificate data, the word checker, and a compact verdict.

## Remaining uncertainties

- Translation/code-size and GC cost when the specialized checker is embedded
  in the kernel rather than built as a standalone CakeML program.
- The cost of authenticating the 271-equation source identity.  The design
  should cache that proven identity for the batch while continuing to reject
  changed equations or calls.
- How much of the fixed-word decoder/refinement proof can be shared across
  expression families rather than being case-10173-specific.
- The final live-verifier adapter from the returned equality to the exact
  original Flyspeck inequality theorem.  The reusable analytic theorem exists,
  but this exact integrated theorem has not yet been produced by the fast
  kernel route.

The fast route is therefore proof-connected and implementable, but not yet a
production claim.  The first actual fast-kernel theorem and the same-checker
batch measurement remain the next acceptance criteria.
