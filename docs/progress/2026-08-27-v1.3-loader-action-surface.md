## Required semantic distinctions

- `needs` loads only a new source; a duplicate is skipped.
- `loads`, `loadt`, and `reneeds` re-evaluate rather than inheriting `needs`
  duplicate behavior.
- `#use` evaluates text without claiming it as an ordinary tracked `needs`
  load.
- `flyspeck_needs` evaluates a new source in place and neutralizes proof state
  exactly once after successful evaluation.  A duplicate neither evaluates
  nor neutralizes; a failure never neutralizes.
- generated `#flyspeck_needs` additionally enforces index, stratum, selected
  source key, source hash, and exact root order.
- `#load` activates only an exact allowlisted, statically linked library.

Blanket erasure, a successful no-op, and treating every action as ordinary
`needs` are forbidden.

## Recognition correction

The baseline CakeML boot scanner treats any level-zero `needs`, `loads`, or
`#use` token as a directive.  It can therefore consume `let needs s = ...` or
`foo needs "bar.ml"` as loader actions.  Requiring physical line start would
fix neither embedded conditionals nor all definitions.

The accepted shape is the complete standalone top-level phrase with exact
literal grammar.  Anything in a definition, conditional, function body,
argument, or larger expression remains ordinary source syntax.  Embedded
loads need verified evaluation or an exact hash-bound normalization; the boot
scanner must not execute them lexically.
