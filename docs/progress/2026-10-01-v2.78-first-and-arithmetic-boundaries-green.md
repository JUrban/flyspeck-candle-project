## Repairs in this batch

`trig1.hl` and `trig2.hl` contained five standalone effect expressions whose
unit results CakeML does not accept as module structure items. They now use the
equivalent explicit discarded-result form, `let _ = ...`. The complete files,
including all their proofs, passed as actions 30 and 31. This batch is committed
and pushed as Flyspeck commit `dcac369b`.

The first action-35 attempt exposed a prerequisite-ledger defect rather than a
proof failure. `strictbuild` had already evaluated the authenticated
`general/prove_by_refinement.hl` bytes through ordinary `needs`, but that route
did not add the source's logical identity to `loaded_files`. Consequently,
`euler_main_theorem.hl` did not recognize the prerequisite as loaded and tried
the deliberately disabled dynamic loader.

The durable source correction changes that one prerequisite action to the
existing authenticated `#flyspeck_loadt` route. It is committed and pushed as
Flyspeck commit `2ba85413`.

For focused validation without rebuilding the expensive post-`strictbuild`
checkpoint, the v375 run used a bounded compatibility shim. It verified the
exact basename and MD5 of the already-evaluated prerequisite, required zero
prior actions and matching current/previous ledger baselines, and added only
that identity to both baselines. It neither read a replacement source nor
evaluated source bytes. This faithfully supplies the sole postcondition missing
from the pre-fix checkpoint. The full 38-action success, including action 35,
then validates the source correction's required behavior.
