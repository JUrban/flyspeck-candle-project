## Likely normalization mechanism and plan impact

The prime-box transition materially changes the next optimization target.
The degree-five prime result has 232/217-bit numerator/denominator components;
degree six jumps to 3,720/3,703 bits, and degree seven becomes extremely slow
before the handoff exits.

The current proved rational normalizer uses a **128-step** reflected Euclidean
candidate search.  If the search exhausts its fuel, it safely returns a
sign-normalized but unreduced rational.  Every proposed reduction is checked
before use, so this behavior does not threaten soundness, but repeated
fallbacks can cause exactly the observed numerator/denominator explosion.

The fuel-exhaustion explanation is presently an inference from the code and
the sharp denominator-sensitive transition; this benchmark did not return an
explicit exhaustion counter.  The next bounded performance step should
therefore be:

1. add a proof-preserving diagnostic result that counts or flags bounded-GCD
   exhaustion while projecting to the existing rational result;
2. rerun the degree-six prime case and a small set of representative captured
   Flyspeck boxes;
3. if confirmed, compare a larger/adaptive verified Euclidean pass with a
   checked externally supplied common-divisor candidate; and
4. keep expression preparation reusable and preserve the current universal
   source, derivative, whole-box, and acceptance theorems.

This investigation now ranks ahead of symmetric-Hessian micro-optimization:
on well-behaved binary inputs the full-box traversal scales acceptably, while
normalization fallback can increase center time by more than an order of
magnitude and prevent the final handoff altogether.  The genuine captured
leaf and legacy comparison remain the decisive integration tests once the
authenticated verifier suffix is green.
