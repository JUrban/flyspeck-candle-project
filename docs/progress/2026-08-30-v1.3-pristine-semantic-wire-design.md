# Pristine direct-reference semantic wire design (2026-08-30)

## Decision and evidence limit

The pristine reference output must use a new nonce-bound semantic subprotocol;
the existing bare `CANDLE_FINGERPRINT_V2` and
`CANDLE_STATE_FINGERPRINT_V2` lines are not sufficient as retained run
evidence.  They carry no run nonce or boundary, and the existing reusable
parsers do not require the four theorem records to occur in transcript order.

This design does not authenticate a process, source tree, serializer, parser,
or protocol module.  At this layer the parser establishes only internal wire
consistency and equality to claimed raw-plan/native records.  It creates no
candidate or comparison descriptor and does not approve S2, S3, PFT, or
release.  Parser integration is prohibited until the exact-source authority
defects found in the hostile review of project commit `fd9be93` are repaired
and independently rereviewed.

## One exact marker namespace

The schema-v3 request owns the marker name
`CANDLE_PRISTINE_DIRECT_SEMANTIC_V3`.  Every line in the semantic session uses
that same name, is tab delimited, contains the plan's 64-lowercase-hex session
nonce, and has one of four exact record tags.  Metavariables below are shown in
angle brackets; angle brackets are not present on the wire.

```text
CANDLE_PRISTINE_DIRECT_SEMANTIC_V3\tTHEOREM\t<nonce>\t<index>\t<name-hex>\t<theorem-hex>\t<hypotheses-hex>\t<conclusion-hex>\t<global-axioms-hex>\t<hypothesis-count>\t<global-axiom-count>
CANDLE_PRISTINE_DIRECT_SEMANTIC_V3\tPOST_STATE\t<nonce>\t<kernel-state-hex>\t<type-constants-hex>\t<term-constants-hex>\t<definitions-hex>\t<global-axioms-hex>\t<type-count>\t<term-count>\t<definition-count>\t<global-axiom-count>
CANDLE_PRISTINE_DIRECT_SEMANTIC_V3\tDEPENDENCY\t<nonce>\t<index>\t<name-hex>\t<full-digest-md5>
CANDLE_PRISTINE_DIRECT_SEMANTIC_V3\tCOMPLETE\t<nonce>\t<boundary>\t<theorem-count>\t<dependency-count>
```

All hexadecimal fields are lowercase.  Serialized identity fields contain an
even, nonzero number of hexadecimal digits, names decode as strict ASCII,
SHA-256 is computed over the decoded serialized bytes, and
`full-digest-md5` is exactly 32 lowercase hexadecimal digits.  Decimals use
only `0|[1-9][0-9]*`, are at most 19 digits, and are converted only after that
lexical check.  The exact final boundary literal is
`07-final_assembly-through-296`.

The intended producer request emits the theorem and post-state payloads
directly from the functions in its claimed `candle/fingerprint.ml` source
rather than first emitting and then relabelling bare Great-100 marker lines.
The intended dependency values are returned by the claimed original
`Serialization.full_digest_thm` implementation.  The raw parser does not
establish either execution claim; the later held-process collector must do so.
The parser does not accept pre-hashed theorem or post-state identities: it
hashes the retained decoded payload bytes itself.

## Exact order and cardinality

There are exactly ten semantic lines, in this order:

1. four `THEOREM` records with indices 0 through 3 and the exact names
   `Linear_programming_results.linear_programming_results_th`,
   `Mk_all_ineq.the_nonlinear_inequalities`,
   `The_kepler_conjecture.tame_nonlinear_imp_kepler_conjecture`, and
   `Candle_flyspeck_l2.tame_imp_kepler_conjecture`;
2. one `POST_STATE` record;
3. four `DEPENDENCY` records with the same indices and theorem names; and
4. one `COMPLETE` record binding the exact final boundary and counts 4 and 4.

The semantic session occurs after all 297 action completions and after the
two terminal post-action native-load observations for the final target and
serializer.  It occurs before the existing reference-session completion
marker.  No native-load, action, LP, ordinary diagnostic, semantic, generic
success, or failure line may interrupt those ten lines.  No semantic marker
may occur elsewhere.  The reference-session completion marker remains the
last stdout line and is accepted only after the semantic terminal.

This positioning proves an observed ordering fact; it does not by itself
authenticate that the named sources were the executed sources.  The later
collector must independently authenticate the fixed parser, protocol,
request, serializer, Flyspeck source, runtime, and retained stdout bytes under
its held-lock execution protocol.

## Derived values

The immutable parser derives, rather than accepts:

- four theorem records by SHA-256 hashing the decoded theorem, hypothesis,
  conclusion, and global-axiom serializations;
- one structural post-state record by SHA-256 hashing its five decoded
  serializations;
- the invariant that every theorem and the post-state have exactly the same
  global-axiom identity and count three;
- four ordered dependency records;
- the ordered-request and ordered-dependency-record SHA-256 values using
  `direct_release_protocol.canonical_sha256`, namely UTF-8 JSON with sorted
  keys, separators `,` and `:`, and non-finite numbers forbidden;
- the common nonce-free semantic projection; and
- one exact raw semantic-completion observation bound to that projection.

The run-bound completion observation has this closed shape:

```text
{
  "schema": 1,
  "kind": "candle-flyspeck-pristine-direct-semantic-completion-observation-v1",
  "status": "complete-observed-unapproved",
  "role": "pristine-clean-reference",
  "reference_ordinal": <exact integer 1 or 2>,
  "nonce_kind": "reference-session-nonce-v1",
  "session_nonce": <the plan's 64-lowercase-hex nonce>,
  "boundary_id": "07-final_assembly-through-296",
  "plan": <canonical content record of the validated plan>,
  "request": <canonical content record of the validated request>,
  "transcript": <canonical content record of the rederived transcript>,
  "theorem_count": 4,
  "dependency_count": 4,
  "ordered_theorem_name_sha256": <direct_release_protocol.canonical_sha256(list(FINAL_THEOREM_NAMES))>,
  "semantic_projection": <canonical content record of the derived projection>,
  "approved_reference_present": false,
  "dependency_history_is_kernel_trace": false,
  "pft_used": false,
  "s2_s3_evidence": false
}
```

Here a canonical content record is exactly the existing
`pristine_direct_reference_protocol.content_record` result with fields
`bytes` and `sha256`.  The parser rederivation envelope carries both the
derived semantic projection and this run-bound observation.  The observation
is not a common projection and must never be consumed outside its exact
plan/request/transcript/rederivation closure.  It keeps
`cross_runtime_coverage = null`; the exact coverage status is
`not-derived-requires-authenticated-inventory-and-generated-inputs`.

This separation is necessary rather than merely conservative.  The five pure
parser inputs are stdout, stderr, the exact process result, the raw plan and
the request.  The plan binds the 400-source inventory and 43 generated inputs
only by named content records, so those payloads cannot be reconstructed from
their hashes.  Current cross-runtime coverage-v2 has no partial-coverage type
and requires the full inventory, generated inputs and inventory-backed logical
closure.  A held collector must open the separately retained canonical bytes,
match them to the plan records, validate their full public shapes, and only
then combine them with the parser result to construct and validate full
cross-runtime coverage-v2.  No parser-level source-closure or full-coverage
claim is permitted.

The parser implements the exact byte framing of `candle_s1_field`: a canonical
decimal byte length, one colon, and exactly that many payload bytes.  Before
integer conversion, every framed length and child-count token must match
`0|[1-9][0-9]*`, contain at most nine digits, denote a value no greater than
536,870,912, and, for a payload length, be no greater than the bytes remaining
in the already bounded field.  Conversion failures become protocol errors.
The parser never loops or allocates from an unchecked declared count.
Immediately after decoding a node's child count and before iteration or
allocation, it also requires
`child_count <= remaining_serialized_bytes // 2`, because even an empty
canonical child frame occupies two bytes (`0:`).  An outer `candle_s1_node` is
one framed tag, one framed canonical child count,
exactly that many framed children, and no trailing byte.  It must then enforce:

- each theorem composite is byte-for-byte
  `candle_s1_node "theorem" [hypotheses; conclusion]` reconstructed from the
  separately retained component fields;
- the kernel-state composite is byte-for-byte
  `candle_s1_node "kernel-state"
  [type_constants; term_constants; definitions; global_axioms]` reconstructed
  from the separately retained component fields;
- each hypotheses/type-constant/term-constant/definition/global-axiom
  component is an exact outer `candle_s1_node "list" [...]` whose declared
  child count equals both its actual number of framed children and the
  corresponding decimal count on the marker; and
- every theorem's global-axiom payload is raw-byte-identical to the post-state
  global-axiom payload, not merely equal after hashing.

Every theorem has zero hypotheses and the exact decoded empty-hypothesis wire
`4:list1:0`; its global-axiom count is three.  The post-state type, constant,
and definition counts are nonnegative canonical decimals and its global-axiom
count is three.  The serializer record is copied from the claimed raw-plan
authority only after the raw native closure has observed an equal content
record as its final post-action source.  This is internal raw-bundle equality,
not source or process authentication.

`Serialization.full_digest_thm` is an MD5 over sorted theorem-history MD5
strings.  It is neither collision-resistant evidence nor a kernel proof trace.
The derived dependency observation therefore keeps
`dependency_history_is_kernel_trace = false`, remains unauthenticated, and
cannot approve semantics without the later process authentication and
three-way comparison.

The parser result remains `authentication_status = not-authenticated`, has no
candidate, and keeps approval, promotion, PFT, S2, and S3 fields false.  A
later collector may promote these derived values into a raw candidate only
after replaying the complete retained bundle and reauthenticating every
authority record before and after the run.

## Rejection matrix

Hostile tests must reject at least:

- bare Great-100 fingerprint/state lines, old semantic versions, unknown
  semantic tags, extra fields, empty fields, spaces as delimiters, CRLF,
  missing final LF, non-ASCII bytes, and noncanonical decimals;
- missing, duplicate, reordered, interrupted, or post-terminal semantic
  records, wrong counts/boundary, and a semantic session before either
  terminal native-load observation;
- nonce drift in every record class, index gaps, theorem-name substitution,
  name aliases, non-ASCII name bytes, odd/uppercase/nonhex payloads, signed or
  padded counts, and overlong decimals;
- nonempty theorem hypotheses, a noncanonical empty-hypothesis serialization,
  a global-axiom count other than three, theorem-to-theorem axiom drift, and
  theorem-to-post-state axiom drift;
- theorem-only or kernel-composite-only splices, malformed/noncanonical length
  frames, list child-count mismatches, marker/list count mismatches, trailing
  serialized bytes, and shared-axiom payloads that differ before hashing;
- missing, duplicate, reordered, uppercase, or malformed dependency digests
  and a shared semantic `COMPLETE` record copied from another nonce or
  boundary;
- plan/serializer content drift, parser/protocol source drift, stale bytecode,
  `__file__` relabelling, PFT tokens, and any semantic/candidate/approval field
  accepted as producer input; and
- stdout larger than the exact plan/request cap 536,870,912 bytes before an
  in-memory semantic decode begins, nonempty stderr, a bool or drifted cap,
  and a nine-digit child count greater than `remaining_bytes // 2` before any
  child loop or allocation.

A same-shape substitution of one 32-hex dependency digest is intentionally not
claimed to be detectable by this passive grammar.  It changes the retained
stdout and derived projection.  The later held-process authenticator must
establish that the exact request computed the value, and the comparison must
require equality with the other authenticated runs.  Adding a producer-owned
terminal digest would provide only internal consistency because an attacker
able to rewrite the record can rewrite that digest too.

The semantic/output-cap extension is a disjoint raw-protocol migration.  All
five closed top-level artifacts move from schema 2 / `*-v2` kinds to schema 3 /
`*-v3` kinds, the source-rederivation envelope moves to `*-v3`, and the exact
marker protocol and its marker names move from `V2` to `V3`.  Schema-v2 values
and V2 markers then reject; embedded LP inventory/success subprotocols remain
their separately named schema 1.  The migration is required even though no v2
production bundle exists, so the two exact shapes never share one durable
schema identity.

The schema-v3 raw plan and request each add exactly two top-level fields named
`retained_stdout_max_bytes` and `retained_stderr_max_bytes`.  Their values have
exact Python type `int`, not `bool`, and are respectively exactly `536870912`
and `0`; request validation also requires exact value equality with both plan
fields.  They are not nested under authority, the marker contract or resource
limits.

The pure five-input parser has no publication descriptor and makes no file-
capture claim.  Before UTF-8 decoding, line splitting, hexadecimal decoding or
semantic framing, it requires exact immutable `bytes` and
`len(stdout) <= plan["retained_stdout_max_bytes"]`; it also requires the
already validated request caps to equal the plan caps.  Before hashing or
otherwise consuming stderr it likewise requires exact immutable `bytes` and
`len(stderr) <= plan["retained_stderr_max_bytes"]`, hence exact emptiness for a
successful run.  Its transcript, native closure and source-rederivation
envelope record content derived from those bytes but contain no `fresh_file`,
`nofollow`, path-identity or descriptor-stability fact.

The later collector anchors an absolute no-follow descriptor walk at `/`,
holds every directory descriptor and parent/child edge through validation, and
creates the stdout and stderr basenames relative to the held final parent with
`O_CREAT|O_EXCL|O_NOFOLLOW`.  Both descriptors must be ordinary files by
`fstat`.  It performs bounded binary reads of at most 536,870,913 stdout bytes
and one stderr byte, rechecks the stable descriptors and every named edge, and
rejects oversize output before invoking the pure parser.  Before any raw
candidate can exist it must publish a separate closed
`candle-flyspeck-pristine-direct-capture-envelope-v1` receipt.  That receipt
has exactly these top-level fields:

```text
{
  "schema": 1,
  "kind": "candle-flyspeck-pristine-direct-capture-envelope-v1",
  "status": "captured-unapproved",
  "plan": <canonical content record>,
  "request": <canonical content record>,
  "process_result": {"exit_code": 0, "timed_out": false},
  "capture_namespace": <closed anchored namespace record>,
  "stdout_capture": <stdout capture record below>,
  "stderr_capture": <stderr capture record below>,
  "source_inventory_capture": <canonical-input capture record>,
  "generated_inputs_capture": <canonical-input capture record>,
  "source_rederivation": <canonical content record>,
  "candidate_included": false,
  "approval_included": false,
  "pft_used": false,
  "s2_s3_evidence": false
}
```

The namespace record has exactly `policy`, `anchor_path`, `anchor_identity`,
`anchor_opened_metadata`, `anchor_post_metadata`, `edge_count`,
`ordered_edge_sha256`, and `edges`.  Its policy is
`root-anchored-nofollow-openat-exclusive-publications-v1`; `anchor_path` is
`/`; and its identity and metadata are taken from the held root descriptor,
with opened and post metadata exactly equal.  A descriptor identity has
exactly integer `st_dev`, `st_ino`, and `st_mode`; a descriptor metadata record
has exactly integer `st_size`, `st_mtime_ns`, and `st_ctime_ns`.  Every edge
record has exactly `index`, `parent_index`, `basename`, `object_kind`,
`open_operation`, `opened_descriptor_identity`, `opened_descriptor_metadata`,
`pre_named_identity`, `post_named_identity`, `post_descriptor_identity`, and
`post_descriptor_metadata`.  Directory edges walk every canonical absolute
component.  Terminal ordinary-file edges cover the exclusively created stdout
and stderr basenames and the no-follow-opened source-inventory and generated-
input files.  Each basename is one nonempty path component other than `.` or
`..`; parent index `-1` selects the anchor and every nonnegative parent index
selects an earlier directory edge; all four identities on an edge are exactly
equal; `object_kind` is exactly `directory` or `ordinary-file`; directory and
existing-input opened/post metadata are exactly equal; `open_operation` is
exactly `open-existing-nofollow-directory`,
`open-existing-nofollow-ordinary`, or
`create-exclusive-nofollow-ordinary` as appropriate; and the ordered digest is
`direct_release_protocol.canonical_sha256(edges)`.  Re-stat uses
`follow_symlinks=False` relative to the still-held parent.  These metadata
checks mean that a swap restored before the final edge check still rejects.

The closed stdout and stderr capture records each have exactly `path`,
`namespace_edge_index`, `bytes`, `sha256`, `retained_max_bytes`,
`bounded_read_max_bytes`, `descriptor_metadata_before_read`,
`descriptor_metadata_after_read`, and `oversize_rejected_before_decode`.
Paths are exact safe absolute publication paths and resolve lexically through
the recorded edges; each edge index selects the corresponding terminal
ordinary-file edge; pre/post-read metadata are exactly equal and equal the
edge's final metadata; byte count equals both the length read and descriptor
`st_size`; SHA-256 is computed from those same bytes; and the oversize fact is
exact `true`.  Stdout limits are 536870912 and
536870913.  Stderr limits are 0 and 1, so any successful nonempty stderr
capture rejects without reading more than one byte.

Each canonical-input capture record has exactly `path`,
`namespace_edge_index`, `bytes`, `sha256`, `expected_plan_bytes`,
`bounded_read_max_bytes`, `descriptor_metadata_before_read`, and
`descriptor_metadata_after_read`.  Its edge is a no-follow-opened ordinary
input file; `expected_plan_bytes` equals the named plan record's exact positive
byte count; the read limit is exactly one more; pre/post-read metadata are
exactly equal and equal both the opened and final edge metadata; the byte count
equals the expected count and descriptor size; SHA-256 is computed from the
same bytes and equals the named plan record.  The decoded values must be
canonical objects that pass their full public validators before their content
records can enter coverage assembly.

The process result has exactly fields `exit_code` and `timed_out`, with exact
types `int` and `bool` (excluding bool-as-int), and exact values `0` and
`false`; it is one of the five parser inputs.  An
independent envelope validator must rerun the exact trusted parser from the
retained stdout/stderr bytes, process result, plan and request, then require
canonical byte equality between that result and the retained schema-v3
source-rederivation object named by `source_rederivation`; candidate assembly
may consume only the freshly rerun result.  The envelope is validated before
coverage assembly.  Authenticating the collector source and process remains a
separate prerequisite; neither this receipt nor the pure parser pre-claims
that authentication.

Positive tests must build canonical length-framed theorem/list/kernel payloads
from independently constructed component bytes, rederive all hashes, require
exact ten-line order, and compare the result with the existing strict direct
semantic projection validator.  They must not seed the parser with the
expected semantic projection.  A separate limitation test substitutes one
well-formed dependency digest and confirms that only the unauthenticated
derived projection changes; it must not mislabel lexical parsing as content
authentication.

## First hostile design review

Independent review of commit `55d66f5` failed the first design with no P0,
two P1 findings, and three P2 claim/precision findings.  The P1 findings were
the missing composite/list reconstruction above and the impossible claim that
a passive grammar could reject an otherwise well-formed substituted
dependency digest.  The P2 findings required the explicit non-kernel/non-
collision-resistant dependency limitation, exact canonical-JSON encoding and
output cap, exact boundary literal, and weaker raw-parser authority wording.

This revision incorporates every finding.  It is still a design prerequisite,
not implementation evidence, and requires a fresh exact-commit rereview.

Rereview of `ad3d0e8` found no P0/P1 and confirmed all original findings
closed.  Its remaining P2 precision requests were a pre-conversion bound on
inner frame decimals, a disjoint migration for the new closed shapes, the
exact shared semantic `COMPLETE` name, and an ordinary fresh-publication file
requirement.  The present revision incorporates those requests and again
requires exact-commit rereview before implementation.

Final hostile rereview of exact design commit `0608b10` returned PASS with no
P0, P1, or P2 finding.  It verified the inner-frame pre-conversion/allocation
bounds, composite/list/axiom checks, complete v3 migration, exact four-form
semantic marker, cap-plus-one fresh-file read protocol, dependency limitation,
and nonpromotion boundary.  Implementation must include the reviewer's
explicit regression for a nine-digit child count larger than the bytes
remaining in its frame, proving that the parser rejects before an unchecked
loop.

An implementation-sufficiency audit then found that the five-input parser
cannot derive full coverage-v2 from plan content hashes alone.  Commit
`8c0f858` correctly separated the nonce-free semantic projection from later
coverage assembly, but its fresh hostile review failed with two P1 and three
P2 capture-contract findings: the capture receipt omitted the process result
and replayed parser result; pathname facts were unanchored booleans rather than
retained namespace identities; the completion observation was not run-bound;
the child count lacked its explicit remaining-byte pre-loop bound; and stderr
had no collector bound.  The present design incorporates all five findings
with the run-bound observation, zero-byte stderr policy, anchored namespace
records, exact process/rederivation closure, mandatory parser replay, and
pre-loop `remaining_bytes // 2` check.  It requires another exact-commit
rereview before implementation.

## Implementation sequence

1. Close and rereview the fixed parser/protocol source authority, exact JSON
   type, and immutable-bytes defects from the `fd9be93` review.
2. Apply the disjoint schema/kind/marker v3 migration, including the exact
   top-level plan/request stdout/stderr caps, and add pure semantic-line
   decoding plus hostile unit fixtures without enabling raw-candidate
   production.
3. Integrate the ten-line state machine into the immutable stdout parser and
   rederive the common semantic projection plus the exact raw semantic-
   completion observation from bytes.  Keep full cross-runtime coverage null.
4. Extend the request generator so pristine OCaml emits the exact wrapper
   lines from the loaded serializer and `Serialization.full_digest_thm`.
5. Specify and implement the held collector capture envelope, authenticate
   the plan-bound source-inventory and generated-input payload bytes, then
   assemble and validate full cross-runtime coverage-v2.  Obtain an
   independent hostile rereview before any live pilot or raw candidate.

No current run or artifact is made promotable by this design.
