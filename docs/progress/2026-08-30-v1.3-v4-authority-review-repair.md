## Closed task, credential and mount derivations

The authority now gives literal per-profile clone derivations and one literal
exec derivation for signal dispositions/masks/pending state/alternate stack,
FS/GS, clear-child-tid, robust-list, rseq and personality.  In particular the
VM+VFORK alternate stack is copied, VM makes rseq unregistered, exec preserves
only SIG_IGN handlers while clearing action metadata, and the pinned static
x86-64 personality is exact zero.

Credential scalars have closed JSON types, domains and stopped-task capture
joins.  `credential-update` and `capability-sets-update` name their target
members and explicitly retain idempotent successful updates, so ambient clear,
capset and setresuid/setresgid cannot disappear merely because a target value
already matched.

Mount graph containers now retain the complete bounded mountinfo byte record
and digest.  Entry/clone rows have exact fields for IDs/topology, descriptor
identities, device, raw path/source bytes, option lists, propagation and
the complete visible graph.  Canonical order is root first and parent before
child.  The namespace copy rule includes Linux v6.8 `CL_SHARED_TO_SLAVE`;
namespace-file source mounts reject rather than
being incorrectly treated as one-to-one copies.  Private, shared, slave,
shared-slave, unbindable and root-parent cases each have a literal rule.

Primary kernel semantics were checked against Linux v6.8
`fs/namespace.c`, `kernel/fork.c`, `kernel/signal.c`, and the rseq/futex
headers in the pinned local 6.8 header tree.

## Second review repair

Independent review of `fb5b3d494f079e0ac45b6621f2860e01079517bd`
found four further integration defects, all repaired in the successor:

- the unused and independently unobservable `max_fds` member is removed from
  the authenticated fd-table schema;
- securebits is exact zero derived from authenticated `CLONE_NEWUSER`, rather
  than an impossible parent prctl/proc join;
- changed query/filter-result semantics use disjoint syscall-disposition v4;
  and
- one exact post-filter clone3 row allows the ptrace entry to resume to the
  installed filter and requires raw `-ENOSYS` with zero effects.

An additional critical pass corrected mountinfo root topology: the namespace
root's raw parent can be outside the visible graph.  Rows now retain raw and
normalized parents separately; exactly index zero has normalized null, while
each nonroot normalized parent selects an earlier row.

The other review also caught that `lock_mnt_tree` depends on hidden mount
expiry-list membership and does not set `MNT_LOCKED` universally.  Internal
lock/expiry state is now excluded rather than forged: exact setup results are
traced, the post-setup filter denies every later mount mutation, and no
authentication decision relies on those hidden bits.  The observation,
initial-state digest, setup replay digest and setup policy identities were
advanced for these incompatible schema/semantic changes.
