## Planning consequence

The earlier symbolic comparison found the fine-grained staged Taylor path
103.66x slower than the legacy path.  The new phase split explains that result:
the evaluator is not slow; the prototype constructs product evaluations,
validity witnesses, addition witnesses, and large ordinary rewrite proofs
before calling it.  Merely optimizing the cval arithmetic representation or
the evaluator will not recover the loss.

The next proof-producing prototype should make the reflected call coarser.  It
should feed authenticated mantissa/exponent data to one proved program that
performs the rounding plan and validity checks internally, then cross the
ordinary theorem boundary once.  This preserves the kernel guarantee while
removing the measured conversion-proof bottleneck.  The exact full-leaf
profile is still needed to quantify the surrounding Taylor and verifier costs,
but it no longer needs to answer where the current staged wrapper spends time.
