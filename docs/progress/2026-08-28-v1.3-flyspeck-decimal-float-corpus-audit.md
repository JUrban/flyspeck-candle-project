Date: 2026-08-28 UTC

## Claim boundary

This is a lexer-faithful host audit and primitive-level differential check. It
is not compiled Candle execution, a completed direct-source stratum, or S2/S3
evidence. Its purpose is to bind the actual Flyspeck decimal corpus and define
the compiled coverage and performance gates still required.

## Lexer-faithful inventory

The scanner implemented the exact CakeML decimal grammar from
`caml_lexScript.sml`, nested comments, escaped strings, and backtick HOL
quotations. It classified 63,940 decimal-shaped text occurrences:

| Lexical context | Occurrences |
|---|---:|
| Parser-eligible OCaml code | 15,775 |
| HOL quotations | 38,654 |
| Comments | 5,408 |
| Strings | 4,103 |

All 15,775 code occurrences are valid float-token shapes. The 3,422 candidates
with an immediate alphabetic or underscore suffix are all in comments or
strings; none is code. There are 1,741 unique code spellings. Canonical audit

Nine selected files contain code floats. The dominant source is
`text_formalization/nonlinear/break_case_log.hl` with 15,462 occurrences and
1,705 unique spellings. `break_case_exec.hl` has another 179 occurrences and
22 unique spellings. Only `formal_lp/glpk/lpproc.ml` and
`break_case_exec.hl` are normalized; their normalization introduces no float
and does not change a spelling or count.

The spelling families are:

- ordinary fractional decimals: 15,656 occurrences, 1,731 unique;
- trailing-point decimals: 110 occurrences, seven unique (`0.`, `4.`, `6.`,
  `7.`, `8.`, `9.`, `25.`);
- exponent decimals: nine occurrences, three unique (`1.0e-12`, `1.0e-8`,
  `1.0e-10`);
- underscore separators: none.

`0.5000` alone occurs 11,640 times. Other important spellings include `4.`
(66), `500.0` (52), `0.7492` (38), `5000.0` (26), `50.0` (24), `8.` (22),
and `6.3504` (20). Long-rounding examples include
`3.1415926535897932385`, `0.55128559843253080794`,
`0.801227801925327499`, and `1.2317544220903216`.

Only `0.0`, with eight occurrences, is present among the ten positive
spellings in the audited curated case file. The other nine curated spellings
do not occur in this corpus. The explicit overflow and underflow divergence
cases `1e309` and `1e-4000` are also absent. A canonical scan found no
hexadecimal float anywhere in the selected sources, including non-code
contexts.

## Primitive differential result

Every one of the 1,741 unique code spellings was evaluated through OCaml
4.14.1 `Int64.bits_of_float` and independently through host libc `strtod`, the
primitive used by CakeML `basis_ffi.c` for `Double.fromString`.

- OCaml results produced: 1,741/1,741
- libc `ERANGE`: 0
- IEEE-754 bit mismatches: 0

This strongly supports the chosen primitive for this pinned host and corpus,
but does not show that the CakeML parser lowering, verified compiler, linked
runtime, or Flyspeck source loader completes those conversions.

## Repeated-conversion frontier

CakeML lowers a float literal to an ordinary expression equivalent to
`Option.valOf (Double.fromString "...")`; it is not represented as an already
converted primitive constant. A literal in a function body is therefore
converted whenever that expression is evaluated.

The final-assembly workload exceeds the existing 100-term load benchmark:

- 463 top-level `add_case` calls in `break_case_log.hl` contain 15,462 load-time
  conversions, including 11,640 conversions of `0.5000`.
- `break_case_exec.hl` leaves `10000.0` and `1.0` inside the recursive
  `mk_decimal10000`/`mk_rec` path and later proof reconstruction.
- `1.0e-10` is inside domain filtering; 36 additional literals remain inside
  explicit case-filtering functions.
- `11.9999` is evaluated by LP feasibility checks and `10.0` by interval-square
  root calls.

Consequently both corpus-wide correctness and call-time conversion cost are
direct-source promotion concerns.
