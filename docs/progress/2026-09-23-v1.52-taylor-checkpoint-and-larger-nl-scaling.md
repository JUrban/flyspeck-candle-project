## Bounded theorem-producing scaling attempt

The complete existing theorem path was first tried on a synthetic
six-coordinate polynomial with 21 weighted quadratic monomials. Source
reification completed in less than one second, but construction,
normalization, and encoding of its 43 value/gradient/Hessian programs did not
finish within a 10.5-minute bound. The first box computation was therefore
never reached. The disposable worker stayed at about 2.16 GiB RSS and one
fully utilized core, with no runtime error or memory growth, before it was
intentionally stopped.

This is a real scaling result rather than a verifier failure: the current path
expands and proves many symbolic derivative/program equalities through host
theorem conversions before `Kernel.compute` begins. Naively applying that path
to larger expressions is not a useful experiment.

## Plan impact

The reflected arithmetic engine is not the present polynomial-scaling
bottleneck, even with thousands of instructions and roughly 16-kilobit exact
rationals. The next reusable proof boundary should therefore avoid expanding
and separately normalizing 43 large derivative programs through host theorem
conversions.

The leading options are now:

1. a verified compact derivative/compiler or jet evaluator operating on the
   authenticated expression AST inside the reflected computation; or
2. externally prepared sparse derivative/program data checked once against
   the AST by a general computed correspondence theorem, then reused across
   many boxes.

The first option is preferable if it remains compact, because it removes the
unlinked external derivative authority altogether. The second remains a
useful fallback consistent with the broader external-preparation design: an
external plan may save work, but Candle must cheaply validate its exact
correspondence before the universal analytic theorem is instantiated.

The genuine captured leaf and legacy comparison remain required integration
tests. The full predecessor will supply them after its support-ready
checkpoint; the synthetic batch only establishes that larger exact numerical
checks themselves have substantial headroom.
