## Question tested

The project-owner research note observed that centered Taylor-model
multiplication constructs a complete proxy product jet and immediately keeps
only its Hessian. The center value and gradient are separately computed by the
first-jet evaluator. This made a direct Hessian formula the strongest remaining
cheap source-level discriminator after v1.87 rejected changes to GCD fuel and
interval endpoint sharing.

The bounded candidate copied the Hessian component of the existing product
jet definition exactly:

```text
f(b) H(a) + grad(a) grad(b)^T
            + grad(b) grad(a)^T + f(a) H(b)
```

It then replaced only the full-product-jet projection in `result_mul`. It did
not change the centered Taylor contract, interval operations, rounding,
guards, certificate format, compiler interface, or theorem handed back to
Flyspeck.

## Decision

The production candidate was **removed**. No Candle source change remains from
this experiment, so no root-theorem integration replay is needed and the last
validated root digest remains:

```text
926f44ab8d5f2303064fe5788cead588
```

This is a useful negative result: syntactically discarded jet components, like
the duplicated-looking endpoint products tested in v1.87, are not reliable
cost predictors for `Kernel.compute`. Source rewrites that add helper calls
must be measured on a sufficiently large genuine batch even when their HOL
equivalence is trivial.

## Updated research-note assessment

The research note has now produced two material outcomes:

1. proof-producing untrusted square-root preparation was a real bottleneck;
   replacing it with exact untrusted `Num` preparation gave the retained
   2.66--2.69-times preparation improvement from v1.86; and
2. several plausible numerical source costs have now been bounded or rejected:
   pair-valued GCD fuel, constant/variable completion as the main cause,
   explicit endpoint-product sharing, and product full-jet projection.

The reusable analytic architecture is already in place: universal centered
Taylor soundness, source reification, certificate erasure, exact split-tree
cover, one computed batch verdict, and compact root handoff have all passed on
the genuine action-296 parent. The current work therefore does not need a new
per-expression analytic proof layer.

The remaining credible performance gap is lower in the numerical stack:

- numerator/denominator magnitude and normalization frequency on genuine
  intermediate Taylor values;
- the cost of the general reflected interpreter versus ordinary execution of
  the same centered, outward-rounded algorithm; and
- eventually, a proved fixed-scale or other bounded-precision backend if the
  first measurement confirms normalization as dominant.

The next targeted experiment should instrument or sample arithmetic magnitude
along the existing 54-instruction action-296 program. It should keep several
distinct boxes in one batch and charge shared preparation once. A native
ordinary-code transcription can be a diagnostic baseline, but cannot
authorize proof results. More helper-level rewrites are not justified without
that evidence.
