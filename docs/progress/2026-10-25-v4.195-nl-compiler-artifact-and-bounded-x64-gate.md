## Investment judgment

This work does **not** establish that the first fast theorem will succeed.
That count remains 0/1 until the exact Candle call produces the original
theorem twice.  The investment is nevertheless supported by substantially
more than a hoped-for final build:

1. the unchanged fast numerical program accepts all 4,173 genuine cells;
2. the general per-record, complete-stream, topology, and original-statement
   soundness chain has been proved;
3. the original target conclusion has already been obtained through the
   slower proof path, with digest
   `48c97d39af116042909b7896d0d83123`, no assumptions, and no axiom growth;
4. the fast evaluator has been translated and installed in the Candle kernel
   program, and its kernel semantics have built; and
5. the corrected verified compiler theory now exists against that exact
   installed program.

The remaining risk is an integration risk: x64 production, runtime loading,
exact registered dispatch, or final theorem composition may still fail.  It
is therefore justified to consume the completed compiler artifact once.  It
would not be justified to begin another full compiler suffix rebuild merely
because a later checkpoint-level test fails.

The earlier 20--24-hour projection was the sum of the measured verified
compiler suffix stages, each with a durable restart boundary.  It was not a
single 24-hour speculative rerun.  After the final proof defect was reduced
and corrected in a five-minute focused reproducer, only the three-hour final
stage was rerun.  Some of the earlier integration iteration was avoidable;
the current policy is stricter: no further long bootstrap is permitted
without a cheaply reproduced runtime-source cause and a focused proof of its
correction.

## Bounded remaining route to the first theorem

1. **x64 consumer and development link (in progress).**  The consumer uses
   the exact pinned compiler artifacts, scopes Holmake to the requested
   project target, and thereby tests that the artifact can actually be
   loaded and consumed.  It has a six-hour hard timeout.  The native
   development link has a separate two-hour timeout.  These are caps, not
   forecasts; no identical full-program timing exists yet.
2. **Reusable runtime checkpoints.**  Save post-strictbuild, post-action-49,
   and post-fast-support states.  Each stage runs once from its nearest clean
   predecessor.  Later theorem debugging must use fresh copies of the
   post-support checkpoint and must not replay these loads.
3. **Exact first-theorem gate.**  From two fresh post-support restores, make
   exactly one 344-equation registered numerical call in each run.  Require
   4,173 cells, the exact target digest, zero assumptions, zero axiom growth,
   identical call identities, and numerical time no greater than 120 seconds
   per run.  This bound excludes the approximately 200-second-per-cell
   generic fallback.
4. **Stop on the first failure.**  Preserve the exact failing phase and use
   the smallest faithful checkpoint or focused proof reproducer.  No
   compiler rebuild follows unless that diagnosis identifies a changed
   compiler/runtime source requirement.
5. **Generalization only after 1/1.**  A second expression family is the next
   coverage gate.  Full-NL scheduling and throughput estimates remain
   premature until that family exposes which source constructors and
   certificate shapes still need implementation.
