# Pristine semantic-v3 request generator (2026-08-30)

## Implemented boundary

`scripts/generate-pristine-direct-reference-request.py` is a pure,
deterministic generator for one schema-v3 pristine `request.ml` and its closed
raw request object.  It validates the existing raw plan, the exact 400-record
original-source inventory and its plan content binding, renders immutable ASCII
source bytes, derives the request-source byte count and SHA-256 from those
bytes, and passes the assembled request through the existing strict protocol
validator.

The generated source:

- requires `FLYSPECK_SERIALIZATION` to be absent;
- emits the nonce-bound session start, observes only stock `loaded_files`
  deltas, and binds each supported `(basename, MD5)` identity to the exact
  inventory record;
- checks the 297 generated target entries against
  `Build.build_sequence_full`, executes actions 0--177, installs the
  successful-return-only `Lp_certificate.read_lp_certificates` wrapper, then
  executes 178--183 and 184--296 in order;
- redirects `Verify_all.cert_dir` to the plan's retained generated-input tree,
  emits 39 exactly-once LP success records, and fails if any planned input is
  missing or repeated;
- loads `candle/flyspeck_l2_target.ml` and `candle/fingerprint.ml` in that
  order and observes each stock-ledger delta as post-action; and
- immediately emits the exact four theorem, one post-state, four dependency
  and one terminal semantic-v3 records, followed by the reference-session
  completion marker.  The theorem and state payloads call the loaded
  `candle_s1_theorem_parts`, `candle_s1_global_axioms` and
  `candle_s1_kernel_state_parts` functions directly.  Dependency values call
  `Serialization.full_digest_thm` directly and must be lowercase 32-hex
  strings before emission.

The source never emits or consumes bare `CANDLE_FINGERPRINT_V2` or
`CANDLE_STATE_FINGERPRINT_V2` lines and never calls the old marker-emitting
helpers, so it has no relabelling path.  Exact generator/protocol constants,
the marker-contract canonical bytes, theorem names, boundary, action and LP
indices, source inventory, action/source equality and final-target authority
are checked before a source byte is returned.

## Evidence limit and open blocker

This step creates only raw request bytes.  It does not write or execute them,
does not authenticate its Python activation, the source tree, process or
output, and does not create source rederivation, coverage, a candidate,
comparison, approval, PFT, S2, S3 or release evidence.  The private injected
protocol module is plumbing for a later authenticated loader, not an
in-process security boundary.  The later collector must bind this generator's
tracked bytes and run it under the fixed-source authority before using its
output.

One already accepted native-closure condition is not realizable by this source
as currently specified.  Pinned HOL Light defines `loaded_files` in
`hol_loader.ml`, and only successful `load_on_path` calls add entries.  Starting
`ocaml-hol -init hol.ml` executes `hol.ml` as the initializer; it does not add
`hol.ml` to that ledger.  The current pristine native-closure validator
nevertheless requires `candle:hol.ml` to appear as an ordered bootstrap ledger
event.  The generator deliberately does not synthesize or mutate such an
event.  The protocol must distinguish authenticated runtime-entrypoint source
from loader-ledger observations, or otherwise repair that requirement, before
any collector or pilot can succeed honestly.

The generated OCaml has not been compiled or run in this bounded step.  The
future collector must also materialize and authenticate the exact retained LP
input tree, use a fresh exclusive process and held request-source descriptor,
and close the accepted descriptor-rooted capture protocol before the raw
request can become evidence.

## Pure verification

The six new tests fix one deterministic source fixture at 153,030 bytes and
SHA-256
`6abb746184b05fecab39f0e99b35e3e5707c542551e7dd50ae625b48578bb85a`.
They cover byte determinism and request content binding; action/LP/native/
session ordering; exact ten-record semantic order; direct serializer and
dependency calls; nonce/ordinal/name handling; OCaml string escaping; source
inventory and marker-contract splices; ambiguous loader identities; forbidden
bare markers and relabelling; and absence of candidate/coverage/promotion
surfaces.

No OCaml, HOL Light, Flyspeck, Holmake, proof replay, collector, bootstrap,
runtime or other expensive workload was started.
