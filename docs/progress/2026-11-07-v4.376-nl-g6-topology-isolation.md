## Numerical phase discriminator

A development-only prefix checker executed the same translated one-cell
fixed-word matcher as the production checker while stopping after a requested
number of cells.  Fixed-heap runs accepted 8, 16, 32, 64, 128, 256 and 512
cells.  A mechanically generated diagnostic 875-cell form then accepted all
875 cells in 145.07 seconds under a fixed 4 GiB CakeML heap.

The earlier full executable failed at almost exactly that elapsed time only
because it proceeded into the subsequent generic topology evaluation.  This
disproves the previous working hypothesis recorded in v4.375 that numerical
packet construction or recursive matcher retention caused the unbounded heap
growth.

## Direct topology implementation

The new total, fail-closed HOL4 functions implement the compact topology data
path directly:

1. cv-list length;
2. coordinate-wise box joining;
3. exact split-boundary validation;
4. one leaf/glue transition;
5. token-stream execution; and
6. final compact result construction.

Closed HOL tests cover a valid two-leaf glue, a valid six-coordinate leaf,
the exact complete-root width, and rejection of a bad split boundary.  The
small theory rebuild takes about five seconds after dependency scanning.

An independent read-only replay of the genuine flat data consumed all
875 jobs and all 1,749 tokens, validated every split boundary, left one root,
and matched the pinned complete root coordinate by coordinate.  This also
found an error in the first G6 executable oracle: it compared the complete
875-leaf call with the historical **cell-0** result.  Cell 0 is the first
partition leaf, not the full subdivision root; that oracle could never have
accepted the complete call.

## Type-clean executable result

The first direct executable was translated into the large whole-checker
environment and compiled with type inference skipped.  It returned `NONE`
even on a one-leaf input that the HOL definition proves successful.  Compiling
the same generated program with type inference enabled exposed an inherited
monomorphic binding collision:

```text
Type mismatch between compute_exec_cv -> compute_exec_cv ->
compute_exec_cv -> compute_exec_cv option and
compute_syntax_compute_exp -> _17
```

That executable is rejected as evidence.  A temporary follow-up main also
demonstrated that quoted helpers are not exported translation-state bindings:
when type inference was skipped, an unbound reused helper produced a startup
segmentation fault.  LR-206 and LR-207 make both failures explicit preflight
hazards.

The replacement light program starts from `basisProg`, registers `cv`, and
translates only the nine flat-parser functions plus the six direct-topology
functions and the closed expected root.  It built in 62 seconds, exported in
7.8 seconds, and passed CakeML type inference.  Its artifacts are:

- S-expression SHA-256
  `6c2e6dd5a5aa04d98c96be77d35b587bfa1de33ae539f587470ff50733e05640`;
- x86-64 assembly SHA-256
  `467e14d3a2588c77531bf7c438ebcaa476530b400a819b455ebd6bd5c4f1bb7e`;
- executable SHA-256
  `01b049b10f9f22a67fc045c1ba7ff747eca2e0969b7d318ad5d4892f56dea020`.

The literal one-leaf control and the complete genuine fixture both print
`accepted`.  Replacing the first token, replacing the first job, dropping the
first token, or dropping the first job each returns `none`.  These are direct
execution tests, not yet the formal refinement or integrated G6 verdict.
