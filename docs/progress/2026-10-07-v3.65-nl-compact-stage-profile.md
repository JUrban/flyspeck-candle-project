genuine jobs, closed `Kernel.compute` calls measured:

Every stage theorem is closed and assumption-free, and the axiom set does not
grow.  The digest for the generic coordinate stage is exactly equal to the
digest for the direct sparse coordinate stage on all 128 jobs.

The direct formula uses the same certificates and derivative intervals as the
generic route but constructs only the one nonzero gradient coordinate and one
nonzero Hessian diagonal of `sqrt(x_i)`.  Its noisy two-run mean is only 1.068
times faster.  The second direct repetition is slower than both generic
repetitions.  Sparse construction is therefore not a material winner and does
not earn a standalone proof.

The profile run also executed the complete compact candidate before the stage
calls.  Those calls took 4.736947592 and 5.768572359 seconds, but the expanded
equation set differs from v3.64 and adds evaluator rewrite-dispatch cost.  They
must not replace the clean v3.64 timing.  Likewise, separate stage digests add
their own traversal and are diagnostic rather than additive components of the
complete verdict.

## Interpretation

The cost distribution is nevertheless decisive enough for the next bounded
test:

- structural checking is not the dominant stage;
- the historical angle result is stable near 1.16 seconds and agrees with the
  earlier separate first/second-order measurements;
- coordinate sqrt processing is much larger inside Candle, whereas the
  prepared exact native coordinate-root stage was only about 0.0141 seconds
  for all 4173 boxes;
- eliminating dense zero derivative propagation does not remove that cost.

The direct sparse path deliberately retained the existing rational
`sqrt` derivative calculation and certificate/domain predicates.  Those
perform normalized interval additions, multiplications, inversions, and
fixed/rational conversions for each root.  They are now the leading local
hypothesis, not because source inspection proves they dominate, but because
the sparse factorial removed the competing dense-zero explanation without a
material win.

This also refines the broader two-gap model.  Native arithmetic width and
generic/direct graph choices contributed only 1.628 and 1.087 times on the
full case-10173 family.  Inside Candle, the same high-level coordinate work is
orders of magnitude farther from its native stage.  The important question is
therefore the encoded rational/fixed boundary and evaluator execution, not a
remaining 340-times optimized-native/C++ numerical gap.

## Next controlled factorial

The next candidate keeps the direct sparse `sqrt(x_i)` graph, genuine
certificates, exact source coefficients, fixed scale, boxes, and final
acceptance fixed while changing one layer at a time:

1. compute `d = 1/(2 sqrt(x_i))` and
   `dd = -1/((2 sqrt(x_i))(2 x_i))` directly with the existing outward fixed
   interval primitives, while retaining the current rational certificate and
   domain check;
2. compare that with the current rational-normalized `d`/`dd` route under
   balanced repeated stage calls;
3. only if derivative arithmetic wins materially, integrate it into the
   128-box complete compact verdict and require every certificate to accept;
4. separately measure a fixed-integer certificate predicate against the
   current rational domain predicate before considering any interface change;
5. require containment or exact equality of numerical outputs as appropriate,
   and reject any variant whose wider bounds lose acceptance.

A large derivative-only win would justify one general coordinate-sqrt
containment theorem.  A domain-only win would instead justify a proved fixed
certificate validator.  If both remain small, the coordinate concentration
is broad evaluator overhead and the next serious project is a compiled or
otherwise lower-overhead execution route, not more source special cases.

The next useful native generality result remains a second genuine expression
family.  More case-10173 native microtuning is not needed to choose this
factorial.
