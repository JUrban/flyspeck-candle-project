The local instruction results are now composed under a single stack
invariant.  For any successful semantic polynomial step, the theorem proves
that the production CakeML evaluator succeeds on the canonical encoded
instruction and returns a stack related to the semantic result stack.  This
is the reusable induction step needed for nested genuine polynomial
programs; it is not yet the whole 167-instruction checker verdict or the
original Flyspeck theorem.

## Proved packet

- a source-decoder theorem proving that successful decoding fixes that exact

Square is included explicitly.  It reuses the already-proved multiplication
operation internally, but remains a distinct source opcode and therefore a
distinct case of the generic theorem.

## Agile validation

The proof was developed against a cached prerequisite state and a single
focused theory target.  The final clean scripted build took **1 minute 4.52
seconds** wall time and **1.82 GB** peak RSS.  No verifier reload, genuine
certificate replay, runtime relink or hour-scale build was used.

The short loop exposed two proof-composition defects immediately: an
ambiguous list-pattern rename could select the characters of the evaluator
name instead of the semantic stack, and the variable-state helper required
its leading length/index conjunctions to be simplified before supplying the
semantic environments.  Both were corrected and all six cases were then
proved interactively before the clean build.

This materially reduces the remaining representation risk.  The theorem has
now checked the exact canonical instruction encodings, evaluator call shape,
runtime stack layout and semantic stack relation for every ordinary opcode.

## Remaining route to the first theorem

1. Lift the one-step theorem by induction to an arbitrary successful
   polynomial-program trace.
2. Validate that lift on short authenticated prefixes of the genuine case
   16594 program, including the first inverse boundary.
3. Compose the full 167-instruction checker verdict and all required guards.
4. Apply the existing analytic/checker soundness chain to obtain the original
   Flyspeck theorem.

The next uncertainty is program-level evaluator sequencing and clock/state
threading, not the meaning or runtime representation of an individual
polynomial instruction.  Prefix probes remain the gate before any expensive
whole-case execution.
