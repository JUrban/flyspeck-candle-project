## General batch boundary

Candle commit `ce8e1d0f` adds a generally proved one-verdict boundary for the
fixed-scale polynomial checker.  One compiled source polynomial and a list of
exact rational boxes are evaluated behind one `Kernel.compute` call.  The
external computed result is a single Boolean.  Kernel theorems establish:

- correctness of the reflected batch checker for arbitrary box lists;
- acceptance of every box named by an accepted batch;
- semantic negativity over any root box covered by accepted member boxes; and
- rejection remains fail-closed through the existing per-box domain, box
  validity, and strict-upper-bound checks.

The source expression, compiled program, and box list are connected by proved
encoding equations.  Untrusted ML can prepare the list but cannot create the
acceptance theorem.

## Measured answer to the performance note

The note's observations separate into already-covered costs, measured live
costs, and useful but presently unmeasured ideas.

### Already covered

- **Large rational intermediate results:** the strict fixed checker retains
  value, gradient, and Hessian intermediates behind the computed boundary and
  returns only a verdict plus one final upper endpoint for a single check.
- **Unnecessary returned values:** on the earlier matched 16-box test, one
  batch returning all compact `(verdict, upper)` pairs took 1.680 s, while an
  aggregate count returning no upper endpoints took 1.706 s.  Removing these
  already-small results did not help.
- **Repeated source preparation:** the genuine test reifies and compiles its
  source expression once, then shares that authenticated program across all
  boxes.

### Confirmed relevant

- **Rational normalization/GCD:** this remains the largest measured arithmetic
  cost.  On 64 genuine action-296 blocks, the fixed backend took 13.101 s
  versus 105.143 s for the rational backend, with 130/130 complete outputs
  equal: an 8.03x numerical improvement.
- **Repeated evaluator setup:** the same 16 genuine fixed boxes took 3.809 s
  as separate computed checks.  The proved one-verdict call took 1.716 s, a
  **2.22x** improvement in the numerical phase.
- **Proof extraction shape matters:** an initial adapter repeatedly normalized
  a membership proposition for each member.  Its theorem handoff took 5.570 s
  and erased the compute gain.  Splitting the already-proved batch conjunction
  once reduced handoff to 0.833 s.  This is close to the 0.786 s individual
  baseline and is a concrete warning against measuring evaluator time alone.

The optimized recurring batch phases were:

| Phase | Time |
|---|---:|
| Prepare and encode 16 boxes | 0.812 s |
| One computed batch verdict | 1.716 s |
| Derive 16 source theorems | 0.833 s |
| Total | **3.371 s** |

The earlier complete individual fixed path took 5.695 s, so the proved batch
improves this same warm 16-box workload by **1.69x** while preserving the same
root theorem.

### Targeted experiments still worth considering

- Sparse/constant-aware operations and Hessian-only representations should be
  tested only on a larger real expression or family where operation counts and
  allocation can discriminate them.  They remain plausible, but the current
  data do not identify them as the next bottleneck.
- Preparation outside Candle is acceptable for indexing and compact data, but
  source/program/box correspondence should continue to be checked by reusable
  encoding theorems.  No large recurring proof-producing preparation was
  observed in this polynomial batch.
- The current integration still materializes 16 source leaf theorems and uses
  15 split-tree glue theorems.  The newly proved semantic batch-cover theorem
  provides the next compact boundary: check or prove the split topology once
  and derive the root result directly, then compare that route with the
  existing glue construction on a larger batch.
