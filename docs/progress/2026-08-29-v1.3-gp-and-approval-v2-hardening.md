## Causal approval repair

Approved identities now use `candle-s1-identity-approval-v2`. Promotion must
attach and validate:

- the exact schema-v7 candidate, plan, request, transcript, and source contract;
- the per-attempt controller `success.json`;
- collector and validator stdout and stderr;
- the exact collection contract and closed aggregate receipt;
- exactly two manifest-ordered sweeps, 65 successes each, with all 130 nonces,
  artifact hashes, target indices, deadlines, and receipt links agreeing.

The Candle approval consumer rejects an open or incomplete aggregate before
loading identities. The project finalizer independently applies the same
causal checks, re-executes and compares `gp --version-short` and the exact
single-thread factor probe, and archives the GP package tree/archive plus the
complete structurally pinned HOL/OCaml runtime files and trees. Fabricated
empty runtime records, extra environment entries such as `LD_PRELOAD`, altered
runtime argv, and self-certified GP output therefore fail closed.

No Ubuntu signature-chain claim is made: the retained `.deb` is described as
an independently reviewed, hash-pinned local package archive. Proving a
distribution signature chain would require separately retaining and checking
the relevant signed repository metadata and extraction derivation.

## Independent rereview correction

A later adversarial rereview invalidated the schema-v7 launch decision. It
demonstrated two independent P1 defects before any 130-run root was created:

1. A reviewer could replace the collection contract's project, controller,
   core-runtime, and external-runtime projections, fabricate aggregate attempt
   rows or controller output, recompute all enclosing hashes, and still obtain
   an accepted final bundle.
2. The collector used an absolute but unauthenticated `/usr/bin/ldd` as the
   oracle that selected the claimed runtime-library closure. The plan retained
   only the rows that oracle reported, and finalization copied those rows
   without independently reconstructing them. An omitted loaded object was
   therefore undetectable.

The first defect is repaired in project commit `4325928`: finalization now
authenticates and archives the committed sweep controller and its Python/Git
tools, checks all four live core-runtime pins, validates the complete 65/66/97
inventory, requires a failure-free single-attempt receipt for every target,
binds artifact paths rather than hashes alone, and checks exact collector and
validator output. New tests preserve the contract, attempt-row, output, and
runtime-rebinding counterexamples.

The second defect requires a new reference-plan schema with authenticated,
replayable ELF-discovery evidence. Consequently schema v7 is candidate-only
diagnostic history and must not be used for the fresh sweep. The runbook's
remaining placeholders will be replaced only after that schema and its
independent finalizer replay pass review.

## Resource policy

Normal work remains below roughly ten CPUs with conservative memory use. The
user-authorized 120 GiB is a ceiling for an observed heavy phase, not a target
or reservation. Before such a phase, the runner must record available memory
and pressure; it must not overlap another measured heavy phase without enough
headroom. At this checkpoint the host had about 167 GiB available and zero
10/60/300-second memory pressure.
