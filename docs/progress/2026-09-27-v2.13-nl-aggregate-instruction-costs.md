## Result

The performance note's main unresolved numerical question now has a measured
answer on authentic action-296 data.  After evaluator-entry overhead is
amortized within each box, the analytic/rational fallback instructions cost
substantially more than the already proved fixed-polynomial instructions.

The experiment captured the exact operand stack presented to all 54
top-level instructions for each of eight distinct accepted genuine boxes.
It partitioned each program into 22 fixed-polynomial steps and 32 remaining
steps (14 additions, 8 multiplications, 7 square roots, 1 inverse,
1 arctangent, and 1 pi/2 constant).  Every partition was evaluated twice by
an internal force-only loop returning one bit and once by an exact loop that
compared every computed stack with the independently captured value.

All **176/176 polynomial** and **256/256 fallback** steps passed both compact
computations and the exact replay.  All eight complete rational and fixed
programs also matched their one-shot executions and passed their certified
checker.  The axiom set was unchanged.

## Timings

The primary discriminator is the force-only pass: it evaluates every result
but inspects only its outer pair constructor, avoiding a traversal of the
large returned Taylor value.

| One pass across eight boxes | Jobs | Wall time | Time/job |
|---|---:|---:|---:|
| Fixed-polynomial steps, pass 1 | 176 | 10.1110 s | 57.45 ms |
| Fixed-polynomial steps, pass 2 | 176 | 10.1614 s | 57.74 ms |
| Rational-fallback steps, pass 1 | 256 | 47.3049 s | 184.79 ms |
| Rational-fallback steps, pass 2 | 256 | 46.5555 s | 181.86 ms |

The fallback partition therefore used about **4.63x** as much total compute
time despite containing only 1.45x as many instructions.  Normalized per
instruction, a fallback step cost about **3.18x** as much as a fixed
polynomial step.  Fallback work accounts for about **82.2%** of the combined
force-only time.

Each total contains eight evaluator entries.  The previously measured fixed
equation-table control was about 62 ms per entry, or roughly 0.50 seconds for
eight calls.  Even treating that as an upper bound and subtracting it equally
would not change the conclusion.  This report does not mechanically subtract
the control because input translation and allocation depend on input shape.

Per-box force-pass medians and ranges were stable:

| Partition | Median | Range |
|---|---:|---:|
| 22 fixed-polynomial steps | 1.175 s | 1.159--1.535 s |
| 32 fallback steps | 5.785 s | 5.721--6.459 s |

Exact result comparison was itself material.  Across eight boxes it raised
the polynomial total from an average 10.136 seconds to 19.071 seconds and the
fallback total from 46.930 seconds to 65.924 seconds.  This is diagnostic
input/output work, not part of the production compact-verdict checker, but it
independently supports keeping large intermediate Taylor values inside
`Kernel.compute`.

## Assessment of the research note

### Already covered

- Repeated evaluator setup is real but is already controlled in the
  production architecture by internal multi-box batches and one compact
  verdict.  Earlier measurements found a 9.14x improvement at eight boxes
  when eight calls became one internal batch.
- Proof-producing square-root hint preparation has already been replaced by
  exact ordinary `Num` preparation, with the old proof-producing conversion
  retained as an oracle.  Compiled point plans reduced the repaired 64-box
  preparation cost by about 63%.
- Full diagnostic results no longer cross the production theorem boundary.
  The exact replay here quantifies why that was important.
- The universal centered-Taylor soundness theorem, certificate erasure,
  fixed-polynomial invariant, fixed batch theorem, exact split-tree cover,
  and compact root theorem handoff are already proved.  The genuine
  action-296 parent theorem remains assumption-free with MD5
  `926f44ab8d5f2303064fe5788cead588`.

### Measured secondary or negative candidates

- Numeric GCD fuel changed a 512-call microbenchmark by only about 1.4 ms.
  Rebuilding the 128-pair fuel value is not a minute-scale explanation.
- Constant/variable completion costs about 6 ms per six-dimensional result.
- Explicit interval endpoint-product sharing was slower, and a proved
  Hessian-only projection produced no stable genuine-batch benefit.  Both
  experimental changes were removed.
- An ordinary instrumented interpreter was 2.59--2.63x slower than
  `Kernel.compute`; merely moving the same algorithm out of the evaluator is
  not promising.

### Still relevant

- Rational arithmetic in the fallback path is now the strongest measured
  recurring numerical target.  The fixed backend's earlier 2.56x 64-box
  compute improvement and this new 3.18x per-step gap agree on that point.
- The present partition does not distinguish rational additions and
  multiplications from square-root/inverse/arctangent Taylor composition.
  If another profiling experiment is needed, that two-way subdivision is the
  narrow useful one; isolated per-opcode `Kernel.compute` calls remain
  misleading because setup dominates them.
- Source/variant preparation, job encoding, and theorem assembly remain
  material end-to-end costs.  The durable direction is still one
  authenticated compiled expression plus changing boxes/certificates as
  checked data, rather than per-leaf theorem/program reconstruction.
- Retaining many full intermediate stacks is itself undesirable.  Attempts
  to retain two or eight boxes' stacks simultaneously exited before the
  measured call; a one-box retention window was stable.  Production already
  avoids this diagnostic representation by returning a compact verdict.

## Consequence for staging

No redesign of the completed analytic soundness proof is indicated.  The
next implementation work should preserve the general theorem and compact
certificate boundary.  The most plausible numerical extension is to move
more of the remaining rational fallback arithmetic to a proved bounded-scale
representation, starting only after a narrow algebraic-versus-nonlinear
partition confirms which side dominates.  In parallel, genuine-leaf
integration should continue to use adaptive one-split closure and local
four-leaf certificate grouping, which the separate coverage experiments
found effective.
