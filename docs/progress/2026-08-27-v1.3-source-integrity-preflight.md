# v1.3 source-integrity preflight

## Outcome

Loader commit `9a161801b00908d4468af0d78fe92e73cde2ee02` makes the
direct loader reject selected-source corruption in-process before it evaluates
`build/strictbuild.hl`.  The manifest generator now emits
`candle/flyspeck_source_digests.ml` with 399 `(repository, path, MD5)` rows.
The JSON manifest pins every node with both SHA-256 and OCaml-compatible MD5,
and pins the generated program itself as
`c3cd0090c7084889de8005afeadfc17d5e7074b251c728e5d00bb79218b84e8a`.
The complete JSON manifest is
`c474c86b10158b4237d0f08e460d47d9de08d4483644ffb4f1f397442b5c091b`.

The generated digest program is an explicit generated dependency rather than
a self-hashed graph node.  Candle loads a small shared integrity checker,
requires exactly 399 rows, resolves each row beneath the manifest-supplied
Candle or Flyspeck root, rejects missing files and unknown repositories, and
compares `Digest.file` values before continuing.

## Evidence

- Nineteen manifest tests pass, including generated-program identity, exact
  graph coverage, MD5/SHA-256 shape, loader placement, and fail-closed source.
- A complete clean-source regeneration passes with 297 roots, 399 source nodes,
  418 dependency edges, and 42 generated mathematical inputs.
- The compiled Candle gate hashes all 399 selected files successfully and then
  rejects an intentionally wrong `hol.ml` digest with the exact mismatch.
- The compiled non-full guard still fails before source loading.
- The integrated full-mode loader passes the new preflight and still stops at
  the known `strictbuild.hl` `#load` compatibility frontier; it does not claim
  full execution.

Adding the checker itself contributes two real `Digest` calls, so the selected
compatibility inventory was correctly expanded from 13 to 15 qualified uses.

## Claim limit

This is a preflight over the selected on-disk graph, not yet a sandboxed file
open primitive.  `hol.ml`, the loader, and the generated digest program begin
loading before all in-process checks can finish; release authentication must
pin the executable and bootstrap sources externally.  The current preflight
also does not yet authenticate generated LP/nonlinear data at the exact point
of consumption or provide resumable theorem-state checkpoints.  No S1/S2/S3
milestone is advanced by this gate alone.
