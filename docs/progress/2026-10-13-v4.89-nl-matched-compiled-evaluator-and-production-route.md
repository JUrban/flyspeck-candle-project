## Fast trusted production route

There are now two deliberately separate deployment stages.

### Stage 1: compiled general evaluator

The general `compute_pure_fast_eval` is already proved to satisfy
`compute_fast_eval_ok`, translated into the Candle kernel, and connected to
the existing `compute_with_thm`.  On a successful result, `compute_with`
constructs the ordinary assumption-free equality theorem directly; it does
**not** replay the generic `exec` evaluator.  A miss or fuel exhaustion falls
back to the existing evaluator.

The exact cell theorem and global kernel value/permission/function proofs are
green.  The remaining deployment step is to materialize the complete
compiler/REPL runtime containing these kernel bytes and run the captured call
through it.  The current kernel prefix itself serializes, compiles, links,
and starts successfully.  Exporting a complete legacy compiler tail exposed
a serializer failure after high memory use, so that failed splice is not a
production route and has not been retained.

This stage gives the smallest actual theorem-producing runtime milestone, but
the approximately three-second recurring cost and multi-gigabyte heap make it
an interim baseline.

### Stage 2: specialized complete checker

The existing `bounded_case10173_checked_cell64` already performs the complete
per-cell numerical contract:

- center and box calculations;
- square-root and reciprocal certificates;
- positivity, geometry, and domain guards;
- source constant and coefficient calculations; and
- final Taylor completion and strict-negative verdict.

Its proved translated repeat benchmark is about **1.371 ms/cell**, although
that benchmark repeats one prepared genuine cell.  The smallest production
extension is therefore not another numerical layer.  It is:

1. a canonical compact packet containing the changing box, center, roots,
   reciprocals, and certificate/topology fields;
2. a total fail-closed decoder checking field shape, exact widths/ranges,
   complete consumption, and the approved shared source/program identity;
3. a canonical result encoder matching the original wrapper verdict; and
4. one general refinement theorem from decoder plus specialized checker to
   the registered characteristic-equation semantics.

The fast evaluator will first authenticate the logical equation/program role
and call schema, decode the packet, run the complete checker, and return the
canonical `cval` result.  Its general refinement theorem will discharge
`compute_fast_eval_ok`.  `compute_with` then creates the Candle theorem from
that result without executing the roughly three-second pure evaluator or the
older generic `exec` path.  The generic semantics remains in the static proof
statement, not in the accepted production execution.

Reusable machinery already present is:

- `compute_fast_eval_ok`, `compute_with`, and their kernel soundness proof;
- the general pure-evaluator refinement, useful as a specification and
  fallback;
- the complete word checker, genuine cell theorem, CakeML translation, and
  verified-compiler boundary;
- the universal source/analytic/Taylor soundness results; and
- the live source/topology contract for case 10173.

Still to implement is the compact decoder, its general refinement, combining
the checker translation with the kernel program lineage, the live adapter to
the exact original inequality theorem, and distinct genuine fixtures.

## Acceptance milestones

The implementation sequence is now concrete:

1. **FAST-NL-1R:** materialize the already-proved general-fast Candle runtime,
   obtain the genuine assumption-free cell-0 equality, and time equation
   checking, fast evaluation, term construction, and analytic handoff.
2. **FAST-NL-2D:** define and prove the compact decoder/result encoder on cell
   0, including malformed/trailing/range adversarial cases.
3. **FAST-NL-2K:** execute the specialized checker in the kernel lineage and
   return the same genuine Candle equality without pure/generic replay.
4. **FAST-NL-2T:** apply the universal analytic bridge and source
   correspondence to obtain the original genuine Flyspeck inequality theorem.
5. **FAST-NL-2B:** capture at least a small varied family of genuine cells,
   authenticate shared preparation once, and report decoding, numerical
   checking, theorem handoff, total wall time, acceptance, and peak memory.

The varied batch—not the repeated-cell controls—will determine production
throughput.  If kernel-lineage translation requires a broad translator
change, this gate will stop and report that specific obstruction before
expanding the architecture.
