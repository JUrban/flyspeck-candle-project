## Why the source-shaped path was added

The optimized checker deliberately postpones Taylor completion across
additions.  This gives a tight and fast final bound, but the unchanged
Flyspeck source completes intermediate results after each opcode.  Proving
that both evaluation orders yield the exact same final object was becoming
the largest remaining suffix obligation.

The development checker instead uses the existing bounded decimal primitives
to execute the literal source order directly:

1. Taylor-complete each coordinate variable;
2. validate and execute each square root on its actual `value_bound`;
3. multiply by the six literal coefficients;
4. construct the seven literal constant results;
5. compute the historical dihedral item;
6. multiply that item by the literal `-1`; and
7. perform the thirteen source-order result additions, Taylor-completing each
   intermediate sum.

All intermediate intervals remain bounded fixed-width data.  This is not a
return to the generic rational evaluator.
