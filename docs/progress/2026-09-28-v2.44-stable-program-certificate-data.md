## Question

The architecture review identified a mismatch between the desired checker
boundary and the current proof adapter. The reflected evaluator already
consumes encoded programs and exact boxes, but the adapter was constructing a
fresh certificate-decorated analytic AST, compiling it, and proving its
program encoding for every cell. Only seven square-root interval payloads
change for this 54-instruction action-296 expression.

This discriminator asks whether one authenticated encoded program can remain
stable while those seven payloads and the exact box are supplied as untrusted
data. It deliberately does **not** authorize a Flyspeck theorem yet. Its
purpose is to establish exact compatibility and measure the preparation
boundary before undertaking the general soundness proof.

## Bounded stable-program prototype

Candle commit `c4523764` adds an untrusted ML data layer that:

1. directly encodes exact rational intervals and interval lists as `cval`
   data;
2. traverses an already authenticated encoded analytic program;
3. replaces only instructions whose exact tag is the square-root tag 1;
4. copies every other instruction and the complete program topology
   unchanged;
5. fails on a missing, extra, or malformed interval payload; and
6. returns the patched program and the exact number of consumed square-root
   slots.

The genuine action-296 benchmark uses the authenticated 54-instruction
program and requires exactly seven slots. It constructs distinct accepted
families of 1, 8, and 32 exact Flyspeck cells. For each cell it prepares the
seven center certificates and exact box as ordinary data, patches the stable
program, and calls the existing proved fixed-algebraic numerical checker.

After the numerical calls, a deliberately separate oracle phase runs today's
theorem-producing AST replacement, compilation, and encoding. On all 41
cells it requires:

- exact `aconv` equality of the patched center program and oracle program;
- exact equality of the direct box encoding and theorem-produced encoding;
- exact equality of the shared whole-box program and its oracle; and
- an unchanged global axiom set.

All 41 numerical verdicts accepted and every equality check passed. The
concrete `Kernel.compute` results are assumption-free, but they are not yet
linked to the original source theorem through this new data interface. The
run therefore prints `theorem_authority=none` and remains explicitly
DEVELOPMENT / NON-RELEASE.

## Matched measurements

The refined replay separates exact domain normalization from the new
certificate-data path. Interactive printing is outside every reported phase.

| Cells | Exact domain normalization | Stable certificate data | Existing theorem-producing oracle | Preparation speedup | `Kernel.compute` |
|---:|---:|---:|---:|---:|---:|
| 1 | <0.001 s | 0.506 s | 2.131 s | 4.22x | 0.912 s |
| 8 | <0.001 s | 2.580 s | 16.080 s | 6.23x | 17.820 s |
| 32 | 6.683 s | 10.246 s | 65.789 s | **6.42x** | 67.843 s |

At 32 cells, the replacement reduces the matched changing-certificate phase
by **84.4%**. Including domain normalization, recurring per-cell preparation
falls from 72.471 seconds to 16.928 seconds, a **4.28x** improvement.

The shared whole-box data patch was below the observer's useful resolution;
the existing whole-box source reification, compilation, and encoding oracle
took 13.092 seconds in the same contended session. If that reusable shared
cost, per-cell preparation, and the unchanged numerical call are summed, the
measured phases fall from 153.407 seconds under the current construction to
84.772 seconds under the proposed stable boundary, or **1.81x**. This is a
phase-sum projection, not yet an end-to-end proof-path result, because the new
soundness handoff has not been implemented.

Peak sampled RSS was 2,253,704 KiB. The 32-cell numerical phase is still
about four times the complete new per-cell preparation phase. The result
therefore validates the architectural preparation change while also
confirming that evaluator arithmetic remains the next major performance gap.

## What is established and what remains

This experiment establishes that the stable-program representation is not
missing information needed by the current checker: on real data it reproduces
the current encoded bytes exactly, rejects structural payload-count errors,
and materially removes recurring proof-producing work.

It does not make an untrusted host patch authoritative. The production route
still needs a general proved boundary with these properties:

1. one authenticated source expression and compiled instruction skeleton;
2. an executable patch operation that consumes exactly the declared interval
   payloads and cannot alter tags, polynomial programs, ordering, or topology;
3. a general theorem identifying a successful patch with compilation of the
   corresponding certificate-decorated analytic expression;
4. a general erasure theorem preserving source identity for every supported
   expression, not a per-expression calculus proof;
5. a stable-program batch checker that consumes only box/certificate data;
   and
6. one compact acceptance theorem feeding the existing universal analytic,
   cover, and live-Flyspeck handoff theorems.

Once that proof is complete, the appropriate integration test is the same
action-296 grouped family. It should compare theorem digest, exact root
coverage, final-cell count, and end-to-end preparation/compute/handoff time
against the current digest-pinned replay. Until then the current proved
adapter remains the authority.
