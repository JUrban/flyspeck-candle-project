## Controller and launch-audit repairs

The project controller was introduced at project commit `c1c2e64`, hardened
at `cc0531f`, and made crash-consistent at final frozen launch commit
`4ca56a9e5d1f99e2e6794de2cccaebce910b7122`. The final controller SHA-256 is
`79cf708e2ed356ca8a9f6d600b83faab5ed6aeda9fca922333118d0cb38c373c`.

The first independent launch audit stopped the run before evidence collection.
It found that a killed controller could release its outer flock while a HOL
child continued, that the outer controller/Python/Git provenance was not fully
pinned, that Git index flags and replacement/graft state were not all rejected,
and that the artifact-root owner and mode were not exact. Commit `cc0531f`
repairs those points with an inherited flock descriptor through controller,
collector, validator, and HOL; TERM/HUP process-group cleanup; exact isolated
outer startup and executable pins; hostile Git-state rejection; and private
mode-0700 artifact directories.

A second independent audit again stopped the launch. Terminal contract,
success, and failure JSON had been streamed directly under its final name, so
a hard kill or power loss could leave truncated terminal evidence and wedge
every resume. Commit `4ca56a9` now stages and fsyncs a private pending inode,
seals it read-only, publishes the terminal name by atomic no-overwrite hard
link, fsyncs the parent directory, removes only the pending alias, and fsyncs
again. It recovers the exact same-inode two-link crash window, retains
pending-only attempt receipts as interrupted evidence, inventories partial
contract publications, and rejects conflicting links, modes, owners, names,
symlinks, or terminal bytes without overwriting them.

The implementation suite passes 12/12 controller tests in 276.314 seconds,
including real SIGKILL, TERM, and HUP injection, every publication crash
window, lock inheritance, resume and revalidation, and hostile provenance
state. The other project tests pass 54/54. Final independent rereview reran the
ten highest-risk tests (10/10), replayed the isolated GCD candidate from the
current Candle policy, and rebuilt and revalidated the exact real-input
contract. It returned an explicit launch PASS with no remaining blocker.

identity sets must agree. Only then may a separate review assemble an approval
artifact. The approved manifest must subsequently drive two clean Candle
Great 100 sweeps before S1 can pass. Direct Flyspeck stratum execution, repeat,
resume, and cross-run agreement remain later S2/S3 gates.
