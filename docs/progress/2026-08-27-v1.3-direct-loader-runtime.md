## Implemented behavior

- Non-`full` mode fails before HOL or Flyspeck source loading.
- Full mode starts the pinned Candle/HOL source stack in the clean process.
- The runtime environment is a manifest-supplied allowlist containing only
  `HOLLIGHT_DIR` and `FLYSPECK_DIR`; absent serialization raises `Not_found`.
- Required roots are checked through ordinary marker files.  This uses
  CakeML's TextIO-backed file predicate and deliberately makes no claim about
  directory existence.
- The OCaml `Filename` compatibility module no longer shadows and discards
  Candle boot's verified `concat`, `basename`, and `dirname` operations.  It
  also supplies `parent_dir_name` and `check_suffix`, the remaining filename
  operations found in the direct corpus.
- HOL Light's standard `load_path` name is the same reference as
  `Cakeml.loadPath`, so no parallel loader state is introduced.

## Decision and next gate

The selected direction is an explicit static-library contract in the Candle
frontend, or an exact manifest-recorded mechanical normalization.  Only the
three pinned library names may be accepted; an arbitrary `#load` no-op would
violate v1.3's no-silent-fallback invariant.  Acceptance of a library name is
not semantic closure: every used `Unix`, `Str`, and `Num` operation remains in
the compatibility ledger and must have tests.

Other immediate runtime obligations exposed by this slice are exact
`Digest`/MD5 behavior, reproducible non-shell substitutes for strictbuild's
`date` and `whoami` probes, and sandboxed directory existence/enumeration.
