## Architectural finding: R4 remains blocked

The experiment passed the external-interface test but exposed a more important
limitation: the shared checker currently implements an explicit disjunction of
the case-10173 and case-16594 checkers.  It is therefore a valid two-family
development executable, not a general all-NL runtime.  A third family would
still require changing runtime source and paying the verified rebuild again.

The next bounded milestone replaces this enumerative dispatch with a checker
parameterized by a decoded supported program and versioned evidence plan.
Family-specific source correspondence belongs in theorem input and handoff
proofs, outside the compiled runtime.  The two present checkers become exact
regression oracles for the generic implementation.

The remaining source-language routes are fixed as follows:

- `hminus`: the existing proved seventh-coordinate interval-parameter fallback
  and append-parameter theorem; one genuine source box and `m_cell` handoff
  already pass, but the data-driven certificate-family route remains open;
- `matan`: a general checked instruction using the existing exact series,
  analytic soundness and fixed-scale theorem stack; one genuine original
  theorem exists through the earlier reflected route, but the instruction is
  not yet in this generic CakeML checker; and
- five `asn`/`acs`/`arc_hhn` leaves: guarded formal normalization using
  `ASN_ATN` and `ACS_ATN`, with `arc_hhn` unfolded, into `atan`, `sqrt`, and
  existing arithmetic instructions.

This is the stopping discriminator promised by R3.  It forbids starting the
20--36-hour verified-runtime rebuild merely because two cases pass.  The next
edit/test loops remain capped at ten minutes.  If a first generic schema slice
cannot represent both existing fixtures within eight focused development
hours, work stops for a concrete schema/proof-gap review rather than expanding
build duration.
