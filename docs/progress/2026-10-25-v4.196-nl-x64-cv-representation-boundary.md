## Preserved first x64 failure

The `v660` x64 consumer stopped at 2026-10-25T07:40:27Z with status 1 and
`last_phase=x64-assembly`.  It ran for 40m43.71s, peaked at 80,481,144 KiB
RSS, and used no process swap.  The completed compiler artifact loaded and
the x64 theory reached all of these boundaries:

```text
Created theory "x64Bootstrap"
compiler64_prog_cv_eq
compiler64_prog_cv_thm
cv_trans_deep_embedding prog_def finished

```

The first failure was then:

```text
Different constants:
  basis_cv$from_mlstring_mlstring_mlstring
  compute_evalPure$from_mlstring_mlstring_mlstring
```

Thus this is not a compiler-program translation failure and not a numerical,
analytic, or original-theorem failure.  It is a mismatch inside
`cv_repLib` between the selected decoder identity and a representation
theorem for the same HOL `mlstring` type.

## Bounded diagnosis

`basis_cv` and `compute_evalPure` were developed in separate theory
ancestries.  Each therefore generated its own from/to function and `cv_rep`
theorem for `mlstring`.  A mechanical comparison of their generated theory
exports found exactly one overlapping converter/representation family:

```text
cv_rep_mlstring_mlstring_mlstring_datatype
from_mlstring_mlstring_def
from_mlstring_mlstring_mlstring_def
from_mlstring_to_mlstring_mlstring_thm
to_mlstring_mlstring
to_mlstring_mlstring_def
```

The focused probe

```text
tools/probes/fast_nl_cv_rep_mlstring_alias_probe.sml
```

runs from the existing `cake_compile_heap` in 3.57 seconds and under 349 MB
RSS.  It establishes all three discriminating cases:

```text
BEFORE_FROM=compute_evalPure$from_mlstring_mlstring_mlstring
MISMATCH_FROM=compute_evalPure$from_mlstring_mlstring_mlstring
MISMATCH_REP=rejected
AFTER_FROM=basis_cv$from_mlstring_mlstring_mlstring
AFTER_REP_FROM=basis_cv$from_mlstring_mlstring_mlstring
FAST_NL_CV_REP_MLSTRING_ALIAS_PROBE_OK
```

Registering only the standard `basis_cv` representation theorem reproduces
the namespace mismatch.  Registering its matching from/to theorem then makes
the same derivation succeed with one coherent identity.  This directly tests
the mechanism reported by the failed x64 run; it is not merely a source-shape
or name-presence test.
