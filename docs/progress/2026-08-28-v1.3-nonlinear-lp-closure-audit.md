## LP proof path and acceptance hole

The source chain is theorem-producing rather than a trust of certificate
answers:

1. `lp_certificate.hl:117-122` deserializes each pinned certificate file.
2. `verify_all.hl:46-66` obtains its hypermap ID and calls
   `verify_lp_certificate` for every selected certificate.
3. `prove_flyspeck_lp.hl:1041-1054` constructs the certificate theorem.  The
   selected exact normalization changes only the immediate-int branch
   `n == 1` to `n = 1`.
4. `linear_programming_results.hl:40-68` calls `verify_all` with the empty
   `test_archive_ids`, builds an ID table, and constructs
   `|- linear_programming_results`.
5. `the_kepler_conjecture.hl:89-91` rewrites this theorem into the final
   implication, so LP is no longer an explicit premise.

The empty `test_archive_ids` is material: the three IDs at
`good_list_archive.hl:17-20` are commented examples, while lines 14-22 select
the complete archive.  A one-ID run using the first documented ID is therefore
a useful authenticated diagnostic only; it cannot be reported as the loaded
`linear_programming_results_th` or as S3.

The narrow missing check is result coverage.  `Hashtbl.find` at
`linear_programming_results.hl:59` makes a missing archive ID fatal, but
`Hashtbl.add` at line 49 permits duplicates and the final traversal ignores
extra IDs.  The runtime acceptance record must require:

```text
certificate_result_count = 19715
set(certificate_result_ids) = set(archive_const_ids)
every result ID has multiplicity 1
all 39 declared files were consumed once in declared order
```

Only then should the theorem statement/hypotheses/axioms/canonical digest be
admitted.  The source comment warns that full verification can exceed 15
hours; no elapsed-time estimate from that comment is evidence for compiled
Candle performance.

## Nonlinear proof path and acceptance hole

`mk_all_ineq.hl` loads the two authenticated generated data files plus
`break_case_exec.hl`, proves the prepared nonlinear leaves using serialized
subdomain theorems, rejects `TRUTH` sentinels from caught `Failure`s at lines
364-366, combines the results into `prepared_nonlinear`, and finally proves
`|- the_nonlinear_inequalities` at lines 387-402.  The final L2 glue consumes
that theorem directly.

This is ordinary HOL theorem construction; the C++ program mentioned in the
header generated the pinned partition data but is not part of the selected
proof runtime.  Conversely, hashing `prep.hl` and `break_case_log.hl` does not
show that all their proof leaves were reconstructed.

Two source diagnostics are non-gates:

- `break_case_exec.hl:1649` evaluates `List.length all_parameters = 23242` but
  does not assert it; and
- `mk_all_ineq.hl:412-415` binds the comparison with expected digest
  `e607b9e5e7f4c495236c6546d6889963` but does not assert it.

The narrow repair is to make these observations fatal in an exact normalized
source action or in the authenticated runner.  A log that merely prints
`false` must never be accepted.  The release record must additionally capture
the theorem statement, empty hypotheses, permitted axiom set, canonical
fingerprint, exact successful leaf count, and input identities.

3. **Nonlinear-support prefix.** Continue through entry 49.  This establishes
   parsing/loading of the support stratum only; it does not consume

5. **Full LP closure.** Continue the cumulative driver through entry 184.

7. **Full nonlinear closure.** Continue the authenticated cumulative sequence

8. **Final target and release repetition.** Evaluate the manifest target glue,
