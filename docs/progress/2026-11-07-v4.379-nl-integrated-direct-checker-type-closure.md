## Cheap type-closure discriminator

The initial diagnosis of the CakeML type error was too broad.  A declaration-
prefix search over the already exported 1.2 MB program showed:

- every verified checker declaration is type-clean;
- both `compute_syntax$compute_exp` and `compute_exec$cv` datatypes are
  registered with distinct generated constructors; and
- the mismatch first appears only when the ad-hoc quoted main supplies its
  own `Pair` and `Num` values to the `cv` checker.

Both HOL datatypes use the source constructor spellings `Num` and `Pair`.
Inside the unannotated quotation those spellings selected `compute_exp`, not
`cv`.  Mechanically changing only those wrapper references to the generated
`cv` identities made the exact complete program pass type inference in 7.03
seconds.  This discriminator ran before another source build.

The durable repair keeps all wrapper-side construction and pattern matching
behind four explicitly typed HOL definitions and translates them normally:

- `bounded_case16594_direct_probe_cv_num`;
- `bounded_case16594_direct_probe_cv_pair`;
- `bounded_case16594_direct_probe_replace_cv_head`; and
- `bounded_case16594_direct_probe_drop_cv_head`.

The final S-expression is 1,249,348 bytes with SHA-256
`5afd8bc79e5c66e509491054a99273b70b324c3b6e1f24c8b07755a6e641e4df`.
CakeML type inference accepts it in 10.26 seconds at 1,059,072 KiB RSS.  The
compiler then emits assembly with type inference enabled in 17.31 seconds at

## Oracle correction before execution

Inspection immediately before the genuine run found a second wrapper-only
defect: the first type-clean probe still compared the complete 875-leaf result
with the historical cell-0 expected value.  Its mutation modes tested only
inequality with that stale value, so a different successful `Some` result
could have been mislabeled as rejection.

The obsolete captured value was removed.  The final oracle follows the proved
checker contract directly:

- positive requires `Some _`; and
- every mutation requires exactly `None`.

This also removes the large cell-0 constant from the program.  LR-208 records
the rule that a captured result may not cross a cell/topology scope change.
The error was caught before paying for a genuine execution, but after one
unnecessary 14:40 source build and 4:42 export.  The corrected source build
took 11:10 at 11,577,852 KiB peak RSS; its export took 6:03 at 9,435,100 KiB.
