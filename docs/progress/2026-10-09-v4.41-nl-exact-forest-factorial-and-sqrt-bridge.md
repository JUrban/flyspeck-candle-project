## Why this exact factorial was needed

Earlier complete-certificate experiments had already separated several
effects:

- directed padding alone was about a 1.18-times effect;
- exact checked versus padded hardware arithmetic was about a 1.6--2.1-times
  recurring effect on the current strong algorithms;
- the historical dihedral operation changed both enclosure quality and
  search materially; and
- authenticated compact source scheduling saved only about two percent
  because it did not remove interval or nonlinear work.

The remaining cheap control was an exact-only comparison on the current
genuine online forest.  The accepted experiment holds outward rounding and
the numerical formulas fixed when comparing representations.  It separately
holds one checked representation fixed when comparing the generic and strong
algorithms.  Every timed lane includes input parsing and reusable program
preparation; fresh build costs are reported separately.

An attempted full two-by-two cross failed closed before timing.  The generic
forest overflows checked 128-bit endpoint multiplication at genuine node
3,754.  Running that lane with built-in unchecked 128-bit endpoints would
therefore be an invalid oracle.  The failed run is preserved as
`nl-native-fifth-sibling-exact-representation-factorial-v1-dev-001`.

The accepted design instead uses:

1. checked 192-bit endpoints for the generic-versus-historical algorithm
   comparison; and
2. checked Boost 128-bit versus built-in 128-bit endpoints, both with a
   checked 192-bit Taylor accumulator, only on the range-safe historical
   path.

All arithmetic remains exact fixed-scale dyadic arithmetic.  No hardware
floating point or relaxed rounding participates in this result.

mathematical algorithm, search, and range contract interact usefully, whereas
representation alone remains a material but modest constant factor.

boundary.  It now proves:

- analytic Hessian symmetry converts the mirrored executable matrix entry to

- the supplied positive input and root intervals contain the derivative and

## Concrete larger-gap plan

The next work remains split into two independent gates.

### 1. Checked execution of the low-work path

Move the authenticated historical whole-box operation through the existing
fixed-layout `Kernel.compute` boundary using the general interval and
universal analytic results now proved.  On the same genuine forest, measure:

- authenticated plan/input preparation;
- checked numerical execution;
- decoding and compact theorem handoff;
- total elapsed time and peak memory; and
- exact decisions and complete certificate acceptance.

The exact built-in native stream is the regression oracle, never proof
authority.  This gate targets the independent approximately 15-times
matched-work boundary and is the primary implementation task.

### 2. One stronger native search discriminator

The next cheap native experiment will keep exact arithmetic and the current
historical formulas fixed while testing derivative-sign/monotonic pruning on
the same authenticated forest.  The whole-box evaluator already computes
outward gradient information.  A development-only replay can expose those
bounds, require a definite sign over the parent, and validate any skipped
branch against the recorded split/child identities.  It must report total
visited nodes, all numerical work, preparation, elapsed time, memory, and
zero rejected leaves.

This choice follows the source audit's independent C++ observation that
derivative pruning reduced a specialized search from 8,896 to 5,334 visits
and improved time by about 1.45 times.  It is a diagnostic lead, not a speedup
claim for Candle.  A material native result could justify one reusable
monotonicity theorem and instruction; a small result stops the path before
proof investment.

If that search gate is small, the next candidate must pass a static
multi-fold screen before implementation: an authenticated generated
value/gradient/symmetric-Hessian operation must predict a reduction of at
least several-fold in the remaining 7.44 million interval products or in
visited nodes.  Merely deleting outer dispatch, zero entries, or repeated
source scheduling is already rejected by measured evidence.

Complete-forest time and acceptance remain the deciding measures.
Preparation is charged at its actual reuse scope.  No local proof or native
prototype advances merely from a faster isolated kernel.
