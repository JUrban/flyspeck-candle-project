## Narrowed execution boundary

The clean restored run emitted these proof phases in order:

```text
phase=prepare path_length=12 precision=3
phase=prepared instructions=1273
phase=boxes-encoded
phase=center-environment-computed
phase=center-jet-computed

```

The missing next marker is `phase=finish-computed`.  Thus the failure occurs
inside `Kernel.compute` for
`candle_cv_q_dim_analytic_first_center_finish`, after both expensive jet
results already exist.  The process did not report a HOL exception or the
checker's ordinary fail-closed `box rejected` result.  Peak resident size of
the restored process remained about 18.1 GiB immediately before termination;
the host still had substantial available RAM.  Those observations make a
simple host out-of-memory diagnosis unlikely, but they do not by themselves
identify the runtime exit cause.

The earlier uninstrumented attempt stopped at the same logical point.  The
repeat therefore establishes a reproducible boundary rather than a stale-log
or checkpoint-readiness error.

## Consequence

The current generic exact-rational theorem producer is not yet a scalable
production route for real leaves of this size.  Its source compiler and jet
evaluation are sufficient for this leaf, but the final exact Taylor result is
still represented and reduced through a large generic `cval` term.

The next production milestone remains the already planned registered compiled
checker theorem, which is intended to return the ordinary assumption-free
Candle equality theorem without repeating this large generic evaluation.  The
long-running exact case-10173 translation continues independently.  A bounded
diagnostic may decompose the failed final aggregation, but it must not grow
into an alternative architecture unless it directly informs the compiled
route.

Full NL still additionally requires:

1. one complete genuine inequality through the fast route to its literal
   original theorem;
2. a reusable decoder/refinement rather than a case-specific exact-result
   ledger;
3. prepared-source and checker coverage for the remaining expression
   families;
4. proof-producing replay of complete certificate trees, not only untrusted
   plan reconstruction; and
5. a representative batch followed by the complete corpus, with preparation,
   recurring checking, theorem handoff, and memory measured separately.
