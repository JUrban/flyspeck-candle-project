## Frontend implication

These cases strengthen the earlier observation that standalone expressions
inside a module are a distinct frontend grouping issue, separate from the
already repaired transitive-`open` export behavior. Source normalization is
currently the smallest faithful way to keep the functional lane moving: the
expressions still execute at the same source point and only their ignored
results become explicit.

A central frontend repair could eventually synthesize the equivalent
discarded-result phrase and reduce file-specific normalizations. That remains
a bounded compatibility improvement, but it should not displace the active
cumulative Flyspeck replay unless the same pattern recurs often enough to
dominate the source lane.
