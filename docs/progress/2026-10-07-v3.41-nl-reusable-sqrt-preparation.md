## Question

The accepted scale-`10^7` native diagnostic spent part of every box evaluation
computing seven exact fixed-point square-root enclosures.  The experiment asks
whether those roots can instead be prepared once as untrusted certificates,
then checked cheaply and reused without changing any final bound.

## Computed versus prepared certificates

The source plan authenticates the six coordinate-square-root slots and the
dihedral radicand slot.  Preparation computes tight fixed endpoints for those
seven slots.  Evaluation retains the existing square checks before using each
certificate; arbitrary supplied values do not bypass domain validation.

Twenty order-balanced 4,173-box pairs gave:

| Lane | Mean preparation | Mean evaluation | Mean batch | Accepted |
|---|---:|---:|---:|---:|
| Compute roots during evaluation | 0.183491426 s | 0.408547342 s | 0.592038768 s | 4,173/4,173 |
| Prepare roots, then validate | 0.345616653 s | 0.324471469 s | 0.670088122 s | 4,173/4,173 |

All 4,173 output bounds are byte-identical.  Prepared roots reduce recurring
evaluation by a factor of **1.259**, but a cold single batch is 13.2% slower
when it must regenerate the preparation.  The result supports materializing
or amortizing external preparation; it does not justify moving the same work
between phases inside every checker invocation.

## Hardware seed with exact correction

A second experiment replaced binary-search initialization of preparation's
integer square roots with a hardware floating-point seed.  Exact integer
division comparisons correct the seed downward or upward, and the existing
square certificate check remains in evaluation.  The floating result is
therefore only an untrusted performance hint.

Twenty paired batches gave:

| Preparation algorithm | Preparation | Evaluation | Complete batch | Accepted |
|---|---:|---:|---:|---:|

## Interpretation and gate

Prepared-root recurring evaluation, 0.3245 seconds, is close in magnitude to
the historical generic-double batch, 0.3302 seconds.  The comparison is not an
equivalence proof: the numerical algorithms and resulting enclosures differ,
and historical generic composition accepted only 52/4,173 boxes.  It does show
that root generation is now bounded and cannot explain the remaining factor
of approximately 3.93 to historical specialized C++.

No new proof target is selected from this packet.  The current dihedral
specialization remains rejected.  External root preparation is useful only
when materialized or amortized, and its hardware seed is untrusted data
preparation rather than a proof primitive.

The next bounded architecture experiment is one of:

1. a hardware-rounded endpoint implementation of the accepted operation graph
   to isolate fixed integer endpoint cost; or
2. a genuinely low-work specialized primitive that avoids the generic dense
   Taylor graph and must pass all 4,173 acceptance, tightness, and total-cost
   gates before proof work.

Direct Flyspeck execution remains the primary lane while that choice is made.

## Bounded source-surface check

The historical low-work route is not the small identity patch already tested.
In the inspected source it spans approximately 430 lines across optimized
`setU126`/`setU135`, `setDeltaFull`, `setDeltaX4`, `Dsqrt`, and
`setDihedral`, before shared interval primitives and tests.  `setDeltaFull`
alone performs sign-directed range selection for every gradient and Hessian
component.  A faithful formal port would therefore be a substantial reusable
numerical-library project, not a small follow-up lemma.

That work remains plausible because the historical complete-batch result is
the target scale, but it should begin with a native low-work prototype and the
same complete gate.  The present dense specialization is not an adequate
stand-in and will not be extended formula by formula.  While action 184 is
still running, the next cheap discriminator is the hardware-rounded endpoint
lane; a full historical-style port should start only if that experiment leaves
the low-work algorithm as the measured dominant gap.
