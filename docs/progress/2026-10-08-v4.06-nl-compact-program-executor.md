## General product boundary

CakeML commit `9e3e4f1fc` adds checked multiplication over the compact Taylor
state.  It computes:

- the center product;
- `g*df + f*dg` for the six center-gradient entries;
- `g*Hf + df*dg^T + dg*df^T + f*Hg` directly in the 21-entry compact
  symmetric-Hessian layout; and
- whole-box value and gradient bounds through the existing complete Taylor
  constructor.

The symmetric outer-product helper rejects mismatched vector shapes.  The
product rejects malformed inputs and any checked arithmetic overflow.  A
general theorem establishes that every successful result is a well-formed
compact Taylor state.  Closed tests cover the six-by-six outer-product shape,
exact constant multiplication, and malformed-state rejection.

The final theory build took 40.09 seconds with 684,112 KiB peak RSS.  The
complete definition translated to CakeML in 98.81 seconds with 2,167,496 KiB
peak RSS.

This first implementation rounds each stored interval product before adding
the product-rule terms.  The best native path instead uses wide raw products
and rounds after aggregation.  The DEVELOPMENT executor is therefore sound
at its current data boundary but is not assumed to reproduce native enclosure
tightness.  A genuine-prefix comparison must decide whether the product
instruction needs one generally proved fused wide accumulator.

## Prepared postfix executor

CakeML commit `69bfd6531` adds a small prepared instruction language:

```text
constant | variable | neg | add | mul | square
```

The total postfix evaluator:

- accepts prepared fixed-scale constant intervals and the six-coordinate
  center/box environments;
- uses only the checked compact operations;
- rejects stack underflow, malformed operands, arithmetic overflow, and any
  final stack other than one result; and
- proves generally that every successful step preserves a stack of
  well-formed states and every successful complete evaluation returns a
  well-formed state.

The executor is not tied to case16594 or to instruction position.  The
enclosing authenticated plan compiler remains responsible for connecting
source rational constants and source operations to these prepared
instructions.

The theorem build took 42.58 seconds with 518,384 KiB peak RSS.  Translation
took 87.49 seconds with 2,881,440 KiB peak RSS.

## What is and is not complete

This closes the reusable polynomial execution core selected by the v4.05
profile, where polynomial and generic multiplication accounted for 51.03% of
the winning native lane.  It is also the fixed prepared-plan boundary proposed
for attacking evaluator traversal and allocation.  It does **not** yet claim
a complete Flyspeck inequality check or a measured speedup.

The remaining integration work is explicit:

1. compile the authenticated rational polynomial source into prepared
   constant intervals and postfix instructions, then validate that plan
   mechanically rather than trusting positions or basenames;
2. provide authenticated center/radius/box input conversion for each genuine
   cell;
3. keep the scalar certificate cursor separate from the executor.  The
   existing native capture contains 50,750 reciprocal records (about 3.1 MB)
   for the 875-box batch; its exact input/output sequence must be checked, but
   the data should not be baked into the generic evaluator definition;
4. extend the outer analytic executor with the already translated
   square-root, reciprocal, and arctangent instructions and exact scalar
   certificate consumption;
5. run the smallest genuine prefix first and compare failure point, bound
   containment, normalization cadence, fallback, time, and memory; and
6. only after that prefix is faithful, run all 875 boxes and charge reusable
   preparation, computation, theorem handoff, repeats, and total elapsed time.

If the prefix loses acceptance because of per-product rounding, the bounded
next change is a general wide fused product/Hessian instruction with the same
prepared-program semantics.  If bounds match but traversal dominates, the
same instruction stream moves to fixed tuples/arrays or coarse straight-line
blocks behind one simulation theorem.  Neither outcome justifies a
case-specific calculus proof.

The complete gate remains 875/875 acceptance and under 22.58 seconds against
the current reflected control, followed by validation on a second genuine
expression family.  No qualified Great100/S1 runtime, source, report,
transcript, or semantic evidence was changed.
