## Controlled question

The independent case16594 factorial left two distinct gaps: about 3.22 times
between exact mixed-width and padded hardware arithmetic on the same graph,
and about 98 times between the matched native exact computation and the
existing reflected batch.  This experiment asks whether per-operation
overflow checking explains a material part of the first gap.

Both lanes use the same 128-bit endpoint and 192-bit Taylor-accumulator
layout, dyadic `2^40` grid, directed shift rounding, 167-instruction graph,
875 genuine boxes, and acceptance predicate.  The control uses Boost checked
fixed-width integers.  The diagnostic changes only those two backends to
their unchecked fixed-width counterparts.  It is deliberately not a checker
candidate: wraparound would be unsound outside the already measured fixture
ranges.

## Decision and larger-gap plan

Dynamic checking is rejected as the next optimization target.  Even deleting
it entirely has only about a one-percent measured ceiling, so a large static
range-proof packet whose sole purpose is to remove those checks would not
address the remaining gap.

The evidence now separates the same-graph costs more sharply:

1. safe 39-step graph lowering: about 1.045 times under exact arithmetic;
2. dynamic overflow checks: about 1.012 times;
3. exact mixed-width versus padded hardware arithmetic: about 3.22 times; and
4. matched native exact versus reflected execution: about 98 times.

The bounded specialization stays useful only as reusable machinery and will
not expand beyond a small proof.  The immediate proof-performance gate remains
one word-level compute operation with a total overflow result and unchanged
exact fallback.  That experiment must include representation conversion,
execution, theorem/result handoff, and fallback.  If it wins, the next packet
adds wide multiply and directed shifts before attempting the complete
875-box reflected batch.  If it loses, the compute datatype extension stops
and the broader work returns to flat evaluator/control representation.

The historical approximately 340-times generic-native/specialized-C++ gap
remains an algorithm-architecture starting point, distinct from these
same-graph arithmetic and reflected-execution measurements.  On case10173,
source-derived native specialization has already reduced that particular
native residual to about 1.35 times; transferring generally reusable winning
instructions into the proved checker remains the route for that axis.
