## Explicit HOL-term ordering at the mixed boundary

The first full run accepted both numerical verdicts and extracted all forest
roots, then failed at the first mixed-function merge with:

```text
Failure "Stdlib.compare: polymorphic ordering is unavailable; use an explicit comparator"
```

This was traced exactly to `formal_ineqs/verifier/m_verifier.hl` in
`merge_m_cell_list_pass`, where the source tactic compares two HOL terms.
Same-function merges had compared equal terms and therefore had not exposed
the missing order. This is an actual term-order requirement in the nonlinear
merge tactic; it is unrelated to the earlier, superseded speculation about
MESON rule ordering.

A focused compatibility helper copies that source tactic with its one
polymorphic comparison replaced by Candle's explicit `Term.compare`. A test
over the two real production function terms confirms that the legacy call
fails with the exact message above while the explicit helper preserves the
domain, function set, assumptions, and axiom set. No theorem, merge lemma,
certificate, source proposition, or numerical verdict was changed.
