# Great 100 inactivity-timeout repair — 2026-08-28

The first clean 65-entry baseline remains active and unmodified in
`/project/worktrees/candle-coverage` at
`110a18d485557ae877d0cb47bb9172e6558ddf61`. It is intentionally retaining
all failures for the compatibility inventory.

That run exposed a harness problem while loading `100/pascal.ml`. The Candle
transcript continued through Gröbner-basis progress, reached 67 basis elements
and zero critical pairs, and printed `Generating HOL version of proof`, but did
not record the file-completion sentinel before the runner moved to the next
entry. There is no Candle `ERROR`, `EXCEPTION`, or parsing failure in the
transcript. The final baseline JSON remains authoritative for the result
classification.

Inspection of the runner explains why useful output did not protect this
case: `_check_output` made one `pexpect.expect` call with the complete
`--timeout` value and recognized only loading, value, error, and completion
sentinels. Ordinary progress text remained buffered but did not restart that
call's clock. Thus the option was a maximum interval between recognized
sentinels, not the documented practical intent of an output-inactivity limit.

The isolated branch `codex/flyspeck-v13-top100-idle-timeout` fixes this at
`c90fd48e8be0a676d8d35e4601bfa953b7325ff4`. Semantic sentinels retain
priority, while otherwise-unclassified complete lines are consumed as
progress and restart the inactivity interval. This also bounds the unmatched
progress buffer. JSON reports now state
`"timeout_semantics": "per_output_inactivity"`, and CLI/documentation text
uses the same meaning.

Evidence at that commit:

- three focused subprocess tests cover progress across a total duration
  longer than the timeout, error-sentinel priority, and loading/value/finish
  stack behavior;
- Python bytecode compilation and the 65-entry `--list` inventory pass;
- the repaired stream parser successfully drives an actual compiled Candle
  process through a source-file load.

The same semantics were then ported onto the fingerprint- and wall-timeout-
aware release integration branch as
`2cbdc8c0152f61dfa43fcd24f0e8c602734ceb21`. Its ten focused timeout tests,
actual compiled-Candle streaming smoke, 65-entry inventory check, and complete
67-test host suite pass. Recomputing the effective timeout after every generic
progress line preserves that runner's independent absolute wall deadline.

This repairs the G1 measurement harness; it does not promote G5/S1. In
particular, `pascal` must be rerun under the repaired semantics, all real
compatibility failures must still be fixed, and semantic fingerprints remain
to be added and matched.
