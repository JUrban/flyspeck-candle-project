# Pristine startup versus loader-ledger boundary audit (2026-08-30)

## Finding

The accepted pristine raw protocol currently requires `candle:hol.ml` to be a
stock HOL Light `loaded_files` event before the original `strictbuild.hl`
event.  That requirement is not implementable by the planned pristine process
route.

In the pinned HOL Light source, `hol_loader.ml` initializes
`loaded_files = ref []`.  Only `load_on_path` appends a file identity after a
successful `use_file`; `loads` and `loadt` are wrappers around that function.
The top-level `hol.ml` is instead executed by OCaml's `-init` option before the
request source runs.  It loads its dependencies through `loads`, so those
dependencies can appear in `loaded_files`, but `hol.ml` never loads itself
through `load_on_path` and never appends its own identity.

This conflicts with the following current protocol facts:

- entrypoint step 0 starts pristine HOL Light from `candle:hol.ml`;
- step 1 installs the request-local native-ledger observer only after startup;
- `LOADER_LEDGER_POLICY` claims a stock `loaded_files` success ledger; and
- `validate_native_execution_closure` requires both `candle:hol.ml` and
  original `strictbuild.hl` in the bootstrap event slice, in that order.

The inspected inputs are content-fixed as follows:

- pinned `hol_loader.ml` SHA-256:
  `01d0f6b5a8ba557b58a352a464c25a408b80585a778d7cc61b11ea688290db29`;
- pinned `hol.ml` SHA-256:
  `9eabbd17397d942d116f1087e4b11d82746acc19ca77c11fed04046fdbec3e32`;
- reviewed pristine protocol SHA-256:
  `3c8fd6b5cfc2240a57ff45e3d1aa1592e3bb73f713101c975fa1dc4cd6f1fc84`;
- accepted semantic/capture design SHA-256:
  `e029cbf4b07e65865097a837fa7ec34dd297506548a3142583d4420b7be7a0e0`.

A generator could print a plan-bound `hol.ml` marker, but that would be a
synthetic startup claim, not a stock loader-ledger observation.  Relabelling it
as a native load would make the retained evidence internally well-shaped but
semantically false.  The step-4 request generator is therefore prohibited from
synthesizing this event, and no collector pilot is authorized under the
current closure contract.

## Evidence boundary affected

The startup source can still be authenticated, but by a different mechanism.
A held descriptor plus a recorded `-init /named/path/hol.ml` argument is not
sufficient: another same-UID process can replace the name for OCaml's open and
restore it before every later named-edge and descriptor check.  The collector
must instead bind the kernel execution route and make the consumed startup
bytes immutable independently of a mutable pathname.

The pinned `ocaml-hol` is itself an OCaml bytecode file with an
`#!/usr/bin/ocamlrun` interpreter line, not the kernel-executed ELF image.  A
complete receipt therefore has to distinguish and bind the `ocaml-hol`
bytecode, the actual `/usr/bin/ocamlrun` executable and its mapped dependency
closure, and the `hol.ml` startup source.  The accepted capture design's
child-binding field list currently has detailed PID, wait, descriptor,
descendant and namespace facts but no closed executable/argv/startup-source
observation.  Relying only on the authenticated collector's source code would
leave these execution facts implicit in the receipt.

The loader ledger and startup invocation therefore need disjoint evidence
classes:

1. `hol.ml` is an authenticated startup-input observation derived from an
   immutable inherited descriptor and the same exact child invocation;
2. the bootstrap loader ledger records its initial stock `loaded_files`
   snapshot count and ordered digest separately, requires original
   `strictbuild.hl` absent from that baseline, and then requires it in the
   post-observer delta; and
3. later action and post-action events remain stock ledger deltas, including
   the exact final-target/serializer suffix.

The later coverage adapter may include the authenticated `hol.ml` startup
input in the common selected logical closure, but it must derive that member
from the held startup capture rather than from a loader event.  Whether the
common closure includes or explicitly classifies that startup member must be
made exact before comparison; it cannot be left to a collector-local choice.

There is also a pre-ledger startup closure.  The pinned `hol.ml` immediately
loads generated `hol_loader.cmo`, later loads `pa_j.cmo`, and reaches topfind,
camlp5 archives and configuration through startup helpers.  In particular,
`hol_loader.cmo` implements the ledger whose output the request will observe.
Those OCaml bytecode/configuration reads are not necessarily HOL
`loaded_files` events or persistent `/proc/<pid>/maps` entries.  Exact
interpreter, bytecode, `hol.ml`, ELF-map and argv bindings therefore do not by
themselves authenticate the initial ledger implementation or its other
dynamically read inputs.

## Proposed repair

Because the existing closed artifact kinds already assign schema 3 to the
false combined interpretation, the conservative repair is a disjoint raw
schema/kind migration before production.  The migration must cover the plan,
request, transcript, native closure, complete and incomplete source
rederivations, disabled candidate identity, marker contract, capture envelope,
terminal capture completion, bundle and pair surfaces.  Retaining an old
`*-v1` capture kind while changing its closed key set would itself be schema
drift.  The existing versions must reject or remain categorically disabled;
they cannot accept the repaired shapes.

The proposed execution route is a full-run immutable filesystem, not a
startup-only hash observer.  This is required because stock HOL Light hashes a
source in one pathname open and later reopens it for parsing, while the LP
reader separately opens and unmarshals its input.  Protecting only the bytes
seen before the baseline would leave every action and LP claim unauthenticated.

The route closes mutable input-path/file-byte races.  It does not claim to
resist an otherwise privileged process that can alter the collector, enter its
private namespace, mutate writable scratch, or alter the kernel; the absence of
hostile same-uid process interference remains an explicit trusted boundary, as
it is in the existing provenance controllers.  Namespace, non-dumpable and
ptrace probes are recorded defense in depth, not a false claim that reusable
subordinate uid ranges are exclusive leases.

1. Before execution, a fixed-source launcher opens and authenticates the raw
   plan, source/LP inventories, generator, generator loader/runtime closure and
   exact generated request bytes.  It creates fresh user, mount, PID, IPC and
   network namespaces, makes mount propagation private, and constructs a new
   initially empty tmpfs root.  Through already held source descriptors it
   copies exactly the closed immutable inventory, re-reads every destination,
   and matches size, mode and SHA-256 before publication.  Absolute plan paths
   are reproduced inside this private root without changing the source text.
2. The immutable inventory covers the entire execution closure: dynamic
   loader, `ocamlrun`, `ocaml-hol`, `hol.ml`, request script, generated
   `hol_loader.cmo` and `pa_j.cmo`, findlib/camlp5/runtime archives and
   configuration, every strictbuild/action/final/serializer source, all 39 LP
   certificate inputs, and every authorized `/bin/sh`, GP, CSDP or other
   external-tool executable, library, script and read-only data input.  It
   includes exact directory entries and symlink targets; an unlisted name is
   absent.  Generated CMO/CMA and host-tool members retain the closed build
   receipts described below.
3. Before the child can run, the launcher creates separate, initially empty
   writable tmpfs submounts for only the closed scratch/output paths, plus
   fixed supervisor-owned stdin/stdout/stderr endpoints and the minimum
   reviewed virtual filesystems/devices.  It remounts the input root read-only,
   pivots into it, detaches the old root, closes every old-root or writable
   input descriptor, and drops mount/namespace capabilities.  The child and
   every descendant receive `PR_SET_NO_NEW_PRIVS`; seccomp denies
   `mount*`, `umount*`, `pivot_root`, `chroot`, `open_tree`,
   `move_mount`, `fsopen`, `fspick`, `setns`, `unshare`, new user/mount
   namespaces, network creation and every route back to the host namespace.
   The retained namespace/mount record binds namespace inodes, mount IDs,
   read-only flags, root/scratch topology, uid/gid maps, credentials,
   capabilities and the canonical inventory/tree digest.
4. Invoke the exact runtime from the immutable root as a noninteractive
   positional script:
   `ocamlrun ocaml-hol -init /exact/hol.ml /exact/request.ml`.
   Stdin is a fixed empty endpoint, not the request.  This preserves stock
   `-init hol.ml` startup while suppressing OCaml interactive phrase-result
   output between semantic markers.  The kernel executable and `PT_INTERP`
   paths, bytecode and libraries all resolve inside the read-only inventory.
   Exact argv, environment, cwd, umask, fd table and initial mappings are bound
   at the same-PID `PTRACE_EVENT_EXEC` stop before the new image runs.  The
   new request-source capture binds the positional argv member and its exact
   immutable open; the retired child-stdin binding cannot validate this shape.
5. The supervisor installs
   `PTRACE_O_EXITKILL|PTRACE_O_TRACESYSGOOD|PTRACE_O_TRACESECCOMP|PTRACE_O_TRACEEXEC|PTRACE_O_TRACECLONE|PTRACE_O_TRACEFORK|PTRACE_O_TRACEVFORK|PTRACE_O_TRACEEXIT`
   and a closed seccomp trace/deny policy before exec.  Filter and supervision
   persist through startup, strictbuild, all 297 actions, all LP reads, final
   target/serializer, every authorized external tool, terminal drain and exit.
   Clone/fork/vfork is forbidden before the baseline.  Afterwards ordinary
   fork, or clone/clone3 without `CLONE_FILES` or `CLONE_VM`, is allowed only
   at a predeclared action/tool site; `vfork` and every shared-file-table or
   shared-address-space creation remain denied.  This restriction is a pilot
   condition, not an assumption about the workload: any required external
   tool that cannot run under it forces a reviewed extension of the state
   machine before production.  Every new task is stopped before execution,
   assigned an exact parent/start-ticks/task record, inherits the filter, and
   remains traced until a bound wait/exit status.
6. The seccomp trace class contains every filesystem-open, exec, fd-transfer,
   process-creation and wait operation needed by the workload.  At syscall
   entry the supervisor accepts only `PTRACE_EVENT_SECCOMP` and first brings
   every live `CLONE_FILES` sharer and `CLONE_VM` peer to an all-stop barrier.
   The production pilot should have none because step 5 denies their
   creation, but the barrier and an empty-sharer assertion are still
   mandatory.  Only after that barrier may it read
   `PTRACE_GET_SYSCALL_INFO` or copy any pointer-referenced path, argv or
   structure from tracee memory.  It records the exact task, architecture,
   syscall number/arguments, dirfd generation, bounded copied bytes, flags and
   expected logical role.  The relevant peers remain stopped while that task
   is resumed with `PTRACE_SYSCALL`, through its matching same-task
   syscall-exit stop, descriptor duplication, named-edge/object binding and
   atomic ledger-state commit.  An intervening signal/event, restart, changed
   syscall, task death or missing exit follows a separately closed state or
   fails.  At a successful fd-producing exit, the supervisor duplicates the
   returned descriptor while the barrier still holds and binds a unique
   inventory logical-object ID, the normalized relative edge below a held
   inventory-root/parent-dir descriptor chain, symlink traversal decisions,
   `statx` mount ID, device and inode, any filesystem-supported stable inode
   generation/version required by the preflight, object type, mode, size and
   SHA-256.  A platform that cannot supply the identity fields required by the
   selected filesystem profile fails the preflight.  Content equality alone
   never proves that the opened object is the authorized logical edge.  The
   descriptor then receives its monotonically increasing fd generation.
   Clone/clone3 `CLONE_FILES`, fork-copy inheritance,
   `close_range` (including the new table created by
   `CLOSE_RANGE_UNSHARE`), `close`, `dup*`, `fcntl(F_DUPFD*)`, descriptor
   flags, `O_CLOEXEC`/`FD_CLOEXEC` and exec-time table unsharing/closure are
   explicit transitions.  The
   fd must resolve either to the immutable inventory or to one allowed
   scratch/output generation.  Because the input mount is already immutable,
   the descriptor the child reads cannot change after this observation;
   pre/post hashing of a live host inode is never byte authority.  The exact
   seccomp/ptrace event loop requires a kernel preflight probe and fail-closed
   implementation test before use.
7. Mutable outputs have a disjoint state machine.  The observer records their
   create/open/truncate/rename/unlink plus `write`, `pwrite*`, `writev`,
   `truncate*`, `fallocate`, copy/sendfile/splice destinations, writer fds
   and producer task lineage.  It also tracks `mmap` with
   `MAP_SHARED|PROT_WRITE`, later `mprotect`, `mremap`, `munmap`, fd close,
   and mapping inheritance across clone/fork/exec/exit.  It also records every
   readable fd and every file-backed readable mapping, including
   `MAP_PRIVATE`, until close, unmap, exec replacement or task exit.  No read
   consumer is allowed while any writer fd or writable shared mapping exists,
   and no writer open, truncate, rename-over or other mutation is allowed
   while any reader fd or readable file-backed mapping of that generation
   remains live.  At the producer's bound wait/last-close/unmap barrier all
   related file-table tasks
   are stopped, the output is re-opened through its held scratch-directory
   identity, and its exact bytes are hashed into a versioned output generation
   together with the anchored logical edge, mount/device/inode tuple and
   supported stable inode generation/version before any consumer resumes.
   Subsequent reads bind that generation and exact object.  A reopened writer
   may create a new generation only after the symmetric
   reader-fd/readable-mapping quiescence barrier above.  Deterministic output
   names are predeclared exactly.  A runtime-generated temporary name instead must match
   a bounded role-specific basename grammar and length below one held scratch
   directory, be created exclusively with `O_CREAT|O_EXCL`, and be bound to
   its role/generation before first use; arbitrary dynamic paths are forbidden.
   Shell pipelines and inherited pipes are allowed only when their complete
   task/fd lineage, byte caps, producer/consumer roles and waits are
   predeclared.
8. `open_by_handle_at`, `name_to_handle_at`, `io_uring*`, `SCM_RIGHTS`,
   unclassified `sendmsg`/`recvmsg`, child `pidfd_getfd`,
   `process_vm_*`, child `ptrace`, unclassified memfd or executable
   anonymous content, host-network access and every unclassified
   content-bearing mechanism are denied.  File-backed `mmap` binds an fd
   generation, offset, length and protections.  `/proc/maps` is an additional
   mapping observation, not byte authority.
9. The baseline endpoint is a supervisor-owned stdout pipe whose inode and fd
   generation are fixed before fork.  The baseline marker must be the final
   bytes of one successful leader-task `write` or `writev`; the syscall-exit
   record binds TID/PID/start ticks, fd generation, pipe inode, requested and
   returned lengths, cumulative stream offset and exact drained interval.
   Before accepting it, the supervisor all-stops and enumerates the complete
   task tree, requires no pending filesystem/process event, and validates the
   event digest.  This boundary ends only the single-task startup phase; it
   never ends filesystem mediation or task supervision.
10. After observer installation, the baseline record contains the exact
   initial stock `loaded_files` count and ordered digest.  It omits both
   `hol.ml` and `strictbuild.hl`: `hol.ml` is authenticated by the immutable
   invocation record, not relabelled as a loader event.  Loading original
   `strictbuild.hl` must create the first nonempty post-observer stock-ledger
   delta.  For every later source, both the loader's `Digest.file` open and the
   parser's reopen resolve to the same immutable inventory object.  The
   supervisor independently recomputes both stock MD5 and SHA-256 from that
   object and requires the emitted stock ledger MD5 to match before joining its
   basename to the SHA-256 identity; MD5 alone never supplies identity.  The
   same rule covers final target and serializer.
11. Every LP marker is emitted only after the original deserializer returns,
   but acceptance additionally joins its read fd/event to the exact immutable
   LP inventory object, relative path, size and SHA-256.  Basename lookup is
   retained only as request-local indexing and cannot supply byte authority.
   All 39 unique joins, their action-184 ordering and the exact final count are
   required.
12. Ordinary HOL stdout is retained, capped and digested but confers no
   evidence; successful stderr retains the current exact-empty policy and
   zero-byte cap.  The byte parser recognizes only the exact reserved direct
   marker grammar and separately rejects the exact reserved PFT grammar; it
   must not reject normal declarations by English-looking prefixes such as
   `exception Sanity`.  A non-TTY, color-disabled environment makes reserved
   ASCII marker lines unambiguous, while nonmarker stdout bytes remain opaque.
   The terminal session marker is the final reserved record, and acceptance
   also requires exact stdout/stderr pipe drain, process-group exhaustion,
   leader/tool wait statuses and no post-terminal byte.
13. Namespace construction, immutable inventory, request generation, full-run
   filesystem events, fd/task generations, mutable-output generations,
   baseline/terminal writes, positional request/empty-stdin binding, ledger
   joins, LP joins and build provenance are separate versioned closed record
   kinds.  Each has an exact key set,
   canonical length-prefixed serialization, record-count/per-field/total-byte
   caps, strict sequence numbers, domain-separated ordered digest and
   distinct-content digest.  Unknown keys, syscall/event classes, outputs,
   tasks, tools or trailing data reject.
14. Every generated CMO/CMA or other untracked build product has a closed build
   receipt from a fresh, initially empty isolated output directory.  It binds
   source commit and tree/input digests, complete compiler/linker/runtime
   executable and library closure, tool versions/hashes, exact argv,
   sanitized environment, cwd, umask and locale, network-disabled execution,
   exit/wait status, stdout/stderr digests, and every output name, mode, size
   and digest.  The immutable inventory points to that receipt and output
   object; a dirty/prepopulated build or omitted tool/input/output is invalid.
15. Coverage construction joins the authenticated startup input, stock-ledger
   source closure, LP closure, tool/output closure and later semantic records
   under one exact rule.  Update the deterministic generator, parser and every
   complete/incomplete/candidate/bundle/pair consumer to the migrated kinds
   before collector implementation.  The reviewed ten semantic payload rules
   may be ported unchanged internally, but their raw namespace/order and
   execution bindings must migrate.

An implementation must reject at least: a synthetic `hol.ml` ledger marker;
an unauthenticated generator or request source; request-at-stdin interactive
execution; a live host-file open followed only by pre/post hashing; an input
mount that is writable, shared, repopulated, remounted or reachable through an
old-root fd; an omitted/extra/wrong-mode/wrong-digest input, directory entry or
symlink; an unclassified virtual or writable mount; an unknown source/LP/tool
open; source digest and parser opens that do not join the same immutable object;
an emitted source MD5 not recomputed from that object; an LP marker not joined
to the deserializer's exact immutable input; a seccomp trace event without its
matching syscall-exit state; copying pointer arguments before all-stopping
every file-table/address-space peer, or resuming such a peer before the
syscall-exit capture and state commit; fd/file-table or mutable-output
generation confusion; a content-equivalent object reached through the wrong
logical inventory edge; duplication without the same barrier; a reader
concurrent with a writer/shared writable mapping; a new writer while any
reader fd or readable mapping of the prior generation remains live; an untracked
write/truncate/copy/writable-mapping transition; a nonexclusive or
out-of-grammar dynamic scratch name; mismatched exec, argv, maps, cwd,
environment, task lineage or wait status; a missing/late/wrong-task baseline or
terminal stop; an untraced or unplanned clone/fork/vfork/tool; `io_uring`, `SCM_RIGHTS`,
`open_by_handle_at`, namespace escape, network access or any unclassified
ingress; a partial, wrong-inode, wrong-offset, nonleader or nonsuffix baseline
write; a nonterminal completion marker or any post-terminal byte; generic
failure acceptance/rejection based on ordinary HOL text; nonempty successful
stderr; substituted, omitted
or unreceipted CMO/CMA/configuration/tool content; a record with unknown fields,
exceeded caps, bad ordering or a mismatched digest; a ledger implementation
differing from the authenticated generated artifact; missing, baseline-present
or reordered original `strictbuild.hl`; alternate `#use` or request-local
startup; a capture bound to another process tree; any legacy-kind/schema
relabelling; and coverage that drops, duplicates or relabels the startup,
source, LP, tool or output closure.

## Independent reviews

Independent review of exact clean commit `f5ffa1b8433718cd8f909434b9de6a2ebcb7ed50`
confirmed the factual diagnosis but rejected the first proposed repair.  Its
P1 finding was the mutable-name open race and omitted bytecode/interpreter
distinction.  Its P2 findings were incomplete migration closure and failure to
separate the initial ledger snapshot from the post-observer strictbuild delta.
Commit `c19272abd4d5289b0dd583e0fc959f1ef84f3ca1` incorporated those findings.
A second independent review confirmed their textual closure but found the
remaining pre-ledger artifact P1 and the missing post-exec/baseline
synchronization P2 described above.  Commit
`6df08a1663abcf803da85abb8f7daf6acc6ead47` incorporated that inventory and
trace proposal.  A third independent review rejected its remaining
hash-at-open/hash-at-boundary premise: a same-UID process could alter an
already opened live inode while the child read it and restore the accepted
bytes before the boundary.  It also required explicit task/syscall closure,
fd generations, a byte-exact boundary write, and closed startup/build schemas.
Commit `f62ff4edd8fd042be0cad5a166dd1a3d2ba3baec` replaced live-file
consumption with startup-only seccomp notification and sealed objects.  A
fourth independent review confirmed that this closes the original read-time
TOCTOU but rejected its boundary: the filter persists, later source and LP
opens have the same digest-versus-consumption gap, the real workload launches
shell/GP descendants, the one allowed initial exec was underspecified, and
reusable subordinate uid ranges are not exclusive leases.  It also required
full-run task/fd/output schemas.

An independent review of the exact request generator added three integration
contradictions: its producer authority omits the generator itself; stdin
toplevel execution prints phrase results between semantic markers; and the
parser rejects legitimate ordinary declarations beginning `exception`.
The present revision consequently replaces startup-only injection with a
complete private read-only execution root, positional request script,
full-process-tree observation, disjoint mutable-output generations and a
reserved-marker-only parser.  A local non-evidentiary probe confirmed that
this host can create a private user/mount/PID namespace and remount a fresh
tmpfs read-only.  The revised route again requires fresh exact-commit review.

Review of exact commit `f6467f25d45bffb1ef3e397c02f02e9e99716c0a`
accepted the private-root, full-run and parser direction but found two process
state P1s: `PTRACE_O_TRACESECCOMP` was absent, and fd capture did not stop all
tasks sharing one file table.  It also required complete writer/mapping
lifecycle events, bounded exclusive dynamic scratch names, explicit
empty-stderr/positional-request migration, and recomputation of stock MD5 from
the same immutable object.  The present revision incorporates each finding and
again requires exact-commit review.

Review of exact commit `7aa8606f4ed2e2f47370ec7d2131f908cd40ffac`
found no P0 issue but rejected three remaining object/state boundaries.  Its
first P1 required the all-stop barrier before copying pointer arguments at
syscall entry, maintained through the matching exit and atomic state commit,
not merely before descriptor capture.  Its second P1 required symmetric
mutable-output exclusion: a later writer must wait for every reader fd and
readable mapping, including `MAP_PRIVATE`, to disappear.  Its P2 required an
anchored logical pathname/object identity rather than treating mount/type/mode,
size and digest as proof of the exact authorized object.  The present revision
denies shared tables/address spaces in the pilot and incorporates all three
requirements; it again requires fresh exact-commit review.

## Status

This is a blocking design audit, not an accepted repair.  It changes no
validator, generator or runtime and creates no candidate, coverage, approval,
PFT, S2, S3 or release evidence.  A hostile design review is required before
the schema boundary changes.
