## Positive native-source-tree leaf

`validate_native_source_tree` and
`validate_canonical_native_source_tree_bytes` now enforce:

- exact schema/kind/role/root-policy fields and exact built-in JSON types;
- immutable canonical bytes with the retained size cap checked before decode;
- 1--65,536 files, consecutive indexes, strict ASCII-relative byte order and
  no duplicates;
- 4096-byte paths, 255-byte components, no absolute/dot/backslash/NUL path and
  categorical case-insensitive PFT namespace rejection;
- exact read-only data/executable full modes, positive bounded sizes,
  overflow-bounded total and a recomputed complete-list SHA-256; and
- normalized `ProtocolError` rejection for duplicate keys, excessive integer
  width, nesting recursion, malformed UTF-8 and non-finite numbers.

Hostile tests cover equality-spoofing objects, dict/list/record/string
subclasses, an empty recomputed tree, PFT paths with recomputed digests,
noncanonical bytes and cap overflow.  V3 canonical decoding remains consistent
with its preexisting value validator, including a 21-digit positive integer.

reported no P0, P1 or P2 finding and passed the 53-test focused gate.  The
