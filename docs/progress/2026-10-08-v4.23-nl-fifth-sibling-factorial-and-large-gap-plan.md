Holding the mathematical route fixed, padded arithmetic is 1.733 times faster

This cleanly separates the two effects.  Exact representation and directed

## Decision and bounded proof scope

For this complete selected-leaf batch, source DAG is the winner: both routes
already accept every cell, so the historical route's additional tightness
does not save any work here.  No historical-dihedral proof is started on this
evidence.  At the forest level it would have to reduce node count by more than
about 18.1% to repay the measured fully charged per-node penalty, or about
21.2% against recurring evaluation alone, before accounting for forest
orchestration.

The source-DAG proof remains worthwhile and bounded.  Its measured verified
875-cell path already reduced theorem-producing time by 27.6%.  The current
HOL packet authenticates the exact source schedule and identities, proves
cache hits equivalent to the sequential source step, and now proves that
filling a previously empty authenticated slot preserves successful node
evaluation and the global cache-validity invariant.  The remaining intended
boundary is the run induction and compact-verdict handoff; it is not being
expanded into an expression-specific calculus library.

## Concrete plan for the larger gap

The next cheap native experiment is the sealed-parent forest replay.  It will
hold exact arithmetic fixed and compare source DAG with the historical
enclosure while recording complete forest acceptance, visited nodes, maximum
depth, preparation, recurring execution, total elapsed time, and peak memory.
This is the decisive test of whether tighter enclosures repay their higher
per-node cost.  A leaf-only timing cannot answer that question.

After that discriminator, the larger performance work stays ordered as
follows:

1. Finish only the source-DAG sequential-equivalence induction and universal
   analytic verdict handoff.  Measure the complete checked batch, including
   program/input preparation and theorem handoff.
2. Select enclosure algorithms by complete-forest time and acceptance, not by
   isolated bound width.  Promote a specialized analytic instruction only if
   it wins this gate and remains useful on an independent source family.
3. Attack the distinct checked/native boundary with a total checked-word
   executor: narrow stored endpoints, checked wider products/accumulators,
   explicit overflow data, unchanged exact fallback, and one compact batch
   verdict rather than returned intermediate jets.  Charge conversion,
   fallback, numerical work, handoff, repeats, and memory separately.
4. Repeat the winning complete architecture on another genuine expression
   family and then on an adaptive certificate forest.  Shared preparation is
   charged once when it is actually reusable across the batch.
5. Use those profiles to choose the next low-work numerical kernel.  The
   historical approximately 340-times generic-native/specialized-C++ result
   remains an architectural warning, not a literal current residual:
   case10173 native work has already approached its specialized baseline.
   The present actionable gaps are the measured checked/native boundary and
   total forest node count.

This keeps the orders-of-magnitude objective active without committing proof
effort to a local specialization that loses its complete-batch gate.
