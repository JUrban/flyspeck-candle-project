## Selected behavior

The original `text_formalization/build/strictbuild.hl` defines a
byte-at-a-time `process_to_string` using `Unix.open_process_in` and
`Unix.close_process_in`.  Its immediate load call is `date`; its build report
uses `date` and `whoami`.  The Candle loader configures exactly these two
commands:

- `date` reads `candle/flyspeck_metadata/date.txt`, 21 bytes, SHA-256
  `8f2148c336b70d69d770cd80e0f3decc5a1c9716fac2fc7961f7a5b2d57701e8`;
- `whoami` reads `candle/flyspeck_metadata/user.txt`, 16 bytes, SHA-256
  `ad29b534dd27882add87d6996aa4ccf39bf1e5b15ccfd08804636905e8b8d864`.

Both are ordinary required loader inputs and appear in the generated manifest.
Any other `open_process_in` command fails.  `open_process`, `close_process`,
`gettimeofday`, and `mkdir` also fail explicitly pending their separate
sandbox/refinement contracts.

The same source change supplies the pure OCaml `Buffer` subset selected by
strictbuild and serialization: `create`, `add_char`, `add_string`,
`add_channel`, `contents`, and `reset`.  This deliberately shadows Candle
REPL's unrelated token queue.

Indirect command helpers elsewhere in Flyspeck, including executable probes
and nonlinear test tooling, are not authorized by this slice.  Whether they are
needed for the theorem-checking release route still requires execution evidence
or a narrow sandboxed implementation.

## Critical gate correction

The first version of the compiled Unix test checked its final marker and
`EXCEPTION:` diagnostics only.  Candle's REPL continues after parser and
unresolved-name errors, so the marker could still print after an earlier
failure.  An independent full-loader run exposed this false-positive shape.
The gate now rejects `Parsing failed`, `ERROR:`, and `Undefined variable:` as
well.  The existing `Str` differential gate received the same defensive check.

The corrected gate then exposed a real missing dependency: strictbuild uses
OCaml `Buffer.create`/`add_channel`/`contents`, while the boot image's `Buffer`
is a token queue.  Implementing and testing the selected OCaml subset made the
corrected gate genuinely green.
