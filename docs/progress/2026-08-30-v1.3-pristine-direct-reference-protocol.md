# Pristine direct-reference raw protocol v2 (2026-08-30)

## Status

Commit `52b5a6d` advances the strict pure protocol for retained pristine
OCaml/HOL Light direct-reference evidence to disjoint schema v2.  It does not
launch a runtime, authenticate a
named file or process, build a comparison descriptor, approve a reference,
approve S2/S3, or authorize release.  Every accepted raw candidate explicitly
has `authentication_status = not-authenticated`, status
`complete-unapproved`, and false PFT, approval, promotion, S2, and S3 fields.

The implementation is `scripts/pristine_direct_reference_protocol.py`; its
focused hostile suite is
`scripts/test-pristine-direct-reference-protocol.py`.

## Exact artifact chain

All five top-level JSON artifacts use exact schema-2 / `*-v2` kinds and reject
schema-1 or `*-v1` relabelling.  Their unchanged embedded LP inventory and
success-stream subprotocols remain explicitly schema 1.  Every artifact uses
exact key sets, canonical pretty JSON, duplicate-key and non-finite-number
rejection, and integer checks that reject booleans and floats.

1. The raw plan fixes role `pristine-clean-reference`, ordinal 1 or 2, a
   lowercase 64-hex session nonce, final boundary, fresh action-zero process,
   no checkpoint, one thread, and `FLYSPECK_SERIALIZATION` absent.  It retains
   exact clean project/HOL Light/Flyspeck Git claims; producer entrypoint,
   protocol, and immutable-output-parser content; OCaml/GP/CSDP executable
   content; ELF closure; plan,
   400-source-inventory, generated-input, serializer, and final-target content;
   297 ordered original-build actions; and 39 canonical LP input identities.
2. The request content-binds that plan and its generated ML source.  Its exact
   entrypoint sequence starts pristine HOL Light, installs a native
   `loaded_files` observer, loads original `strictbuild.hl`, executes actions
   0--177, installs the LP wrapper only after
   `lp_certificate.hl`, executes 178--296, loads the final L2 target, emits the
   common semantic/dependency observation, and completes.  Its exact v2 marker
   contract includes the native-load marker rather than leaving that name to
   parser-local convention.  The wrapper emits only after successful
   `Lp_certificate.read_lp_certificates` returns.
3. The transcript content-binds the plan and request, requires exit 0 without
   timeout and exact start/complete status, and retains stdout/stderr content
   records.  It has exactly 297 nonce-bound completion records with contiguous
   loader-ledger spans and exactly 39 nonce-bound, successful-once LP records.
   Every LP event is bound to canonical input identity and original consumer
   action 184.
4. The native execution closure content-binds plan, request, and transcript.
   It describes only the stock HOL Light successful-load ledger; it explicitly
   says that request parentage and cache outcomes were not observed.  Every
   canonicalized ledger event has exact bytes/SHA-256/MD5, phase, and optional
   action index.  Every action selects either an event in its own ledger delta
   or a matching prior loaded event.  The bootstrap ledger must observe the
   HOL Light anchor before the original `strictbuild.hl` anchor.  The
   post-action ledger contains exactly one final-target and one
   common-serializer observation, in that exact order as its terminal two
   events; the serializer's SHA-256 and MD5 are authority-bound.  Raw LP order
   is retained and must equal the transcript stream.  At candidate validation,
   the unique canonical ledger source set and every source's
   bytes/SHA-256/MD5 must exactly equal the common coverage-v2 selected logical
   closure; the separately content-bound serializer is the sole exclusion.
5. The raw candidate content-binds all four raw artifacts plus the canonical
   semantic and cross-runtime coverage-v2 projections.  It cross-checks its
   actions, LP identities, source inventory, generated inputs, serializer, and
   final target against those common projections before remaining explicitly
   unapproved.

The module also validates a pair of complete raw bundles.  The pair must have
ordinals 1 then 2, distinct 64-hex nonces, distinct request/transcript/native
closure/candidate content, and identical authority, action plan, and LP input
inventory.  This pair operation does not compare or approve semantics; the
independent comparison protocol remains the later equality gate.

## Runtime-neutral boundary

Native reference observations reject the four exact compiled-only identities:

- `candle:candle/flyspeck_full_build.ml`;
- `candle:candle/build/insulate.ml`;
- `candle:candle/flyspeck_source_digests.ml`;
- `candle:candle/flyspeck_source_integrity.ml`.

They also reject the `control:` namespace and every PFT-labelled source or
path.  The final target and common fingerprint serializer remain valid explicit
post-action inputs; neither is relabelled as a Candle physical-trace control.

The exact sibling `direct_release_protocol.py` is loaded by resolved source
location only to validate the existing common semantic and coverage-v2 values.
The import fails closed if the final boundary, action count, reference role,
nonce kind, or excluded-key tuple differs.  No authenticated comparison
descriptor builder is exported.

## Independent review closure

The first independent review of `5243602` found a P1 complete-ledger binding
gap and a P2 unconstrained producer path.  Full-content attacks could replace
bootstrap identities, add an unrelated post-action source, duplicate a logical
source with different content, and reverse the terminal observations.  Commit
`0c9c9a6` added exact native/common logical-closure equality and logical-source
uniqueness; `ccb32ba` fixed the terminal final-target/serializer order.

A second review found that the bootstrap success order and serializer MD5
were still underbound.  Commit `68ac41c` requires the HOL Light anchor before
the original `strictbuild.hl` anchor and binds the serializer MD5 in both the
authority and native event.  Independent exact-commit rereview then returned
PASS with no P0, P1, or P2 finding.  It reproduced the earlier attacks, tested
phase relocation and malformed MD5 values, and reran the focused 9/9 suite.
The reviewer confirmed that changing a raw authority and event consistently
does not create authenticated evidence: every such bundle remains explicitly
`not-authenticated` and nonpromotable until the deferred byte/process
authenticator rederives it.

The first immutable-output parser implementation originally left its native
marker name parser-local and omitted its own source from producer authority.
Commit `52b5a6d` closes that gap with a disjoint migration: schema-1/kind-v1
top-level artifacts and v1 wire markers now reject; authority policy v2 adds
the exact fixed-path content record
`scripts/parse-pristine-direct-reference-output.py`; the request owns all v2
marker names including `native_load`; and the parser compares its source bytes
captured at module initialization with the plan authority before parsing.  It
also rechecks an exact sibling schema/kind/marker/loader contract on every use.
The two-reference validator continues to require identical full authority, so
the parser identity cannot differ between nonce-distinct runs.

A subsequent hostile rereview found coercive nested equality and source-loader
gaps.  Commit `c5aebf0` makes all affected composite bindings canonical-byte
exact and requires canonical inputs to be immutable `bytes`; bool/int state
flips in marker, entrypoint, serialization, action-binding, artifact, and pair
objects now reject.  Commit `7fb6775` introduces the fixed-root, no-bytecode
loader that verifies both parser and protocol source content before compiling
their exact bytes.  Direct parser activation is disabled, and the compatibility
contract now includes the pristine reference role and nonce kind as well as
the previously checked constants.

## Deferred production work

This protocol deliberately does not yet prove its content claims.  The v2
parser rederives action, LP, and loader observations from immutable output, but
a later collector/authenticator must:

- generate and authenticate the exact schema-v2 plan/request and parser bytes
  plus the trusted loader under a clean committed, held-lock producer
  checkout;
- implement and validate an unambiguous canonical source resolver for stock
  HOL Light's basename/MD5 `loaded_files` ledger, including lexical aliases;
- reauthenticate source, runtime, GP/CSDP, ELF, serializer, generated-input,
  and final-target bytes before and after each run;
- demonstrate that the original process actually had
  `FLYSPECK_SERIALIZATION` absent and stayed fresh, pristine, and one-threaded;
  and
- run two nonce-distinct pilot references before any full pristine runs.

Until those steps and the independent comparison/approval validators exist,
there is no authenticated pristine direct-reference candidate and no change to
S2, S3, PFT, or release status.
