retains the established rational implementation for square root, reciprocal,
arctangent, addition, multiplication, and all domain guards.  Only paired
tag-0 polynomial blocks execute through the signed fixed-scale backend before

## Assessment of the performance research note

The note's leading explanations are useful, but they now have different
evidential status.

### Already covered or directly measured

- **Rational normalization/GCD is materially relevant.**  The earlier
  isolated 64-box result was 8.03x faster with fixed scale.  The new result
  shows that the improvement survives the complete genuine analytic program,
  where it still gives 2.69x on the recurring two-box computation.
- **Repeated evaluator setup is real but already avoidable.**  The benchmark
  runs all cells behind one evaluator entry and returns one aggregate numeral.
  Earlier fixed polynomial measurements showed a 2.22x numerical improvement
  from this batching alone.
- **Large returned diagnostics are not the main cost at the current compact
  boundary.**  Earlier matched batches returning compact `(verdict, upper)`
  pairs and returning only an aggregate count took essentially the same time.
- **Changing point-certificate preparation is separated from fixed source
  authentication.**  The reusable point plan compiles once, and ordinary ML
  rational evaluation proposes each box's square-root interval.  The checked
  program and certificate-erasure theorem remain decisive; an untrusted hint
  calculation does not authorize acceptance.
- **Source preparation is shared.**  Its 5.49-second cold cost is visible and
  important for small samples, but it is no longer paid per box.

### Plausible, but not yet shown to dominate

- Constant/zero special cases, Hessian-only operations, endpoint-product
  sharing, sparse jets, and symmetric Hessian storage could reduce work.
  However, the complete-check result already identifies arithmetic
  representation as a larger proved opportunity.  These changes should wait
  for a profile on a larger hybrid batch or an operation counter that can
  distinguish their contribution.
- Persistent compiled evaluator contexts could remove more per-call setup,
  but batching already amortizes the current setup without changing Candle's
  kernel interface.  A new persistent-context architecture is not justified
  before measuring the batched hybrid at larger scale.
- Interpreter specialization or verified compilation remains a possible
  later layer if a numerically efficient hybrid is still far behind an
  ordinary implementation.  This experiment does not isolate interpreter
  overhead from fixed arithmetic execution.

## Proof status and next boundary

The diagnostic hybrid is deliberately **not theorem-authorizing**.  Exact
agreement on two real cells is strong regression evidence, but it is not a
soundness proof.  Existing fixed-scale invariants already prove that a
compiled polynomial result contains the polynomial's value, gradient, and
Hessian.  The next reusable proof boundary is to lift that result into the
general analytic Taylor-result invariant, then replace the polynomial case in
the program-compilation induction.  The existing analytic-operation proofs
can remain unchanged.

After that invariant is green:

1. make the hybrid complete-check verdict theorem-authorizing;
2. derive the same genuine action-296 parent theorem through the hybrid;
3. run a larger distinct-box batch with preparation charged once; and
4. compare compute, compact theorem handoff, accepted subdivision count, and
   memory before considering sparse/Hessian-specific refinements.

This sequence preserves the universal soundness investment and tests the
largest measured cost before introducing another numerical architecture.
