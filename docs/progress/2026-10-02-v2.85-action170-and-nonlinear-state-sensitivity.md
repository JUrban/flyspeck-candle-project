## Exact-input nonlinear state discriminator

The 32-cell genuine case-16594 numerical computation was repeated from the
older, lean variable-raw-plan checkpoint. A separate identity probe in both
the lean and richer proof states produced the same term digests:

```text

source_md5=7d38e4aa48d328365865e1e2ab2dc1f6
```

The fixture construction, first 32 plan cells, raw encoding function, source
program term, checker constant, and characteristic-equation bundle were the
same. The raw compute-equation sources did not change between the two source
snapshots; the only relevant intervening source change added a theorem used
after computation. This rules out certificate, expression, or equation-list
drift as the explanation for the timing difference.

Both executions returned the accepted closed theorem. The measured numerical
phase was:

| State | CPU time | Wall time | Sampled RSS |
| --- | ---: | ---: | ---: |
| richer reflected-proof state | 1,313.82 s | 1,342.374 s | 2,253,704 KiB |
| lean variable-raw-plan state | 498.41 s | 509.251 s | 2,253,704 KiB |

The lean state is therefore **2.636x faster**, reducing both CPU and wall time
by **62.1%** on the same genuine computation. The encoding phase also fell to
4.596 wall seconds from the richer run's surrounding 15-second scale, but the
important result is the separately delimited `Kernel.compute` phase.

This is a state-sensitivity result, not yet a complete causal diagnosis. The
identical sampled RSS reflects the fixed runtime heap reservation and does not
measure the live object graph. Plausible mechanisms include extra live proof
objects increasing garbage-collection work, or other evaluator costs caused
by a heavily populated logical state. It is no longer reasonable to treat a
timing taken after many proof experiments as representative of a production
checker launched from minimal stable prerequisites.

## Architectural consequence

The production reflected nonlinear path should preserve a lean checkpoint at
the exact stable-support boundary and evaluate numerical batches in fresh
disposable restores of that state. Large named certificate definitions and
unrelated experiment theorems should be introduced only after the numerical
verdict, or in a separate downstream proof state. This complements the
post-compute naming result: both the order of operations within one run and
the logical state inherited by that run materially affect total cost.

This does not weaken the proof boundary. `Kernel.compute` still returns the
same closed acceptance theorem from the same equations and input, and the
general soundness handoff remains downstream. The optimization is checkpoint
placement and state discipline, not an untrusted numerical shortcut.
