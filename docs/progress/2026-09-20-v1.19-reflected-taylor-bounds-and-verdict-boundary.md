## Batched reconstruction result

Candle commit `461fcf2` adds a proved multi-job native-float evaluator, and
Flyspeck commit `df508328` adds the corresponding Taylor adapter. One
authenticated computation evaluates multiple cells, and soundness retains the

This is a second plan-changing negative result. One `Kernel.compute` call is
not by itself a useful coarse boundary when it returns and reconstructs a long
list of independent theorem results. The representation/handoff cost becomes
superlinear on this workload.

## Single-verdict proof-producing core

Candle commit `27c21a8` implements the revised boundary as a generic
proof-producing threshold checker. It consumes encoded thresholds and exact
polynomial jobs, computes one Boolean `cval`, and proves that a successful
verdict implies every corresponding exact source-polynomial upper bound. The
logical source polynomials, target exponents, alignment relation, and output
inequalities remain explicit in the soundness theorem; neither the OCaml
wrapper nor the computed Boolean is trusted as an axiom.

The clean functional test computed one successful verdict for three distinct
jobs and derived all three exact threshold theorems with no assumptions. It
took 2:10.61 wall / 127.81 user seconds including HOL startup, peaked at
1,088,640 KiB RSS, and used no swap. This establishes the machinery and the
kernel contract. It is not yet a performance claim for a full Flyspeck
partition: the next measurement must use a checker-shaped real workload large
enough to separate evaluator cost from startup and theorem setup.

## Revised nonlinear boundary

The next integration target is therefore one authenticated checker verdict,
not a larger list of arithmetic answers. For the actual Flyspeck nonlinear
path, the desired contract is:

1. consume an encoded partition/certificate plus its explicit arithmetic
   payload;
2. compute one pass/fail result;
3. use a once-proved soundness theorem to imply the existing root inequality;
   and
4. preserve the current theorem statement and assumption/axiom boundary.

This matches the real reconstruction bottleneck. The current path constructs
23,242 subdomain parameters and repeatedly combines serialized leaf theorems
through `prove_iargs_cases` and `PROVE_HYP`. Returning 23,242 reflected results
would reproduce that theorem traffic rather than remove it.

The near-term partition prototype may continue to consume the existing
authenticated serialized leaf statements; that preserves, but does not
remove, the current deserialization axiom. The longer-term analytic checker
must validate the interval/Taylor leaf computation itself before that axiom
can be removed from the nonlinear path. The exact-expression/recentering
experiment already showed why isolated interval algebra is insufficient: it
reduced the first leaf's raw upper bound from about 684.81 to about 4.995, but
did not prove negativity. Faithful Taylor dependency and remainder semantics
are required.

## Next decisions

1. Preserve the cumulative, focused nonlinear, and PFT processes.
2. Profile the single-verdict checker on a checker-shaped real workload, then
   use it as the arithmetic core of the first Flyspeck partition bridge.
3. Model the existing partition constructors and prove that one successful
   verdict implies the same root `ineqm` proposition currently reconstructed
   by `prove_iargs_cases`.
4. Keep existing leaf theorems as the first equivalence oracle, then broaden
   the checker toward exact Taylor remainder and transcendental bounds.
5. Retry the full inclusive LP terminal comparison only after a protected
   18-GiB process exits or equivalent memory/swap headroom is available.
