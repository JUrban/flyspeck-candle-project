- subsequent `update_database` and `!theorems` occurrences are inside deferred

This is evidence for a dead-effect hypothesis, not proof of non-observation.
Reflection, an external caller, or a later dynamic path could invalidate it;
that is why the complete run remains the acceptance gate.

## Open gates and next step

The remedy remains `regression_pending`.  The newly integrated verified Dopen
compiler must run the direct loader past the old `open Parser_verbose`
frontier.  The first later active call to an eliminated binding, any source
action failure, or any mismatch in theorem, definition, assumption, target,
nonlinear, or LP fingerprints rejects this design.  In that case the fallback
is an explicit typed theorem registry or verified dynamic-evaluation design,
not a dummy successful shim.

This conclusion is consistent with `audit1.md`: direct-source execution is the
governing route, while PFT remains an independent compatibility oracle and
cannot close S2 or S3.
