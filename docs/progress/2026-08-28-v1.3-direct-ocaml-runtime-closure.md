# Direct OCaml runtime compatibility closure — 2026-08-28

## Outcome

The direct-source branch now provides the selected OCaml runtime slice that
blocked an honest compiled Flyspeck prefix: `Array.init`, `float_of_num`,
`frexp`, selected `Stdlib` operations, `Sys.word_size`, `Gc.compact`, and the
selected `Hashtbl` surface.  The implementations are CakeML source and add no
foreign-function interface.  Candle commits `58cf275`, `8348e2c`, and
`472f3e6` implement and bind the changes.  Commit `c50a410` additionally adds
authenticated diagnostic cumulative prefixes.  A pre-run review then caught a
stale hard-coded 16-output check in the compiled setup; `638dfe6` replaces it
with the authenticated generated normalization count and is the exact
materialization head.

The generic compatibility operations fail closed.  Unequal
`Stdlib.compare` values and all `Hashtbl.hash` calls are rejected rather than
assigned an invented semantics.  Four active selected sites are instead
changed by digest-bound normalizations to `Term.compare`, `String.compare`,
`Int.compare`, and `Hash_term.hash_of_term`.  `Gc.stat` progress telemetry is
likewise replaced only at its exact selected source site; the outer runner
owns resource measurement.

The static manifest now authenticates 297 actions, 400 source nodes, 43
generated inputs, and 18 normalized outputs containing 39 exact operations.
It evaluates compatibility capabilities over the normalized execution bytes
and reports no unsupported selected compatibility use.  All 107 host tests,
the normalization reconstruction, and the full manifest reconstruction pass.

The source-level compiled oracle `test_flyspeck_ocaml_slice.sh` also passes for
normal, signed-zero, subnormal, and infinite `frexp` cases; rational-to-double
conversion; both hash-table modes; array initialization; system word size;
the GC no-op; and the fail-closed generic operations.  It loaded the new
sources using the prior clean executable, so it is parser/type/runtime evidence
for the slice but not provenance evidence for a newly linked artifact.

## `audit1.md` disposition

The audit's central distinction is accepted: PFT replay is an oracle and
engineering diagnostic, not proof that the direct Flyspeck sources ran through
the verified CakeML frontend.  Consequently neither the PFT run, the host
manifest/plan, nor the source-level runtime oracle is labeled S2/S3.  The
direct compiled route remains primary, and generic comparison/hashing was made
fail-closed specifically to avoid hiding a semantic gap behind a permissive
emulation.

The audit's remaining material concerns are still visible: outer action-ledger
events do not expose every nested physical loader event, direct semantic
fingerprints are not yet independently approved, and aggregate descendant
resource limits are externally supervised.  These are not silently promoted
away by a successful prefix.
