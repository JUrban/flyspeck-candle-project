## The batch verdict now has an exact reusable split-tree contract

The centered Taylor checker now has a logical split-tree datatype. A leaf
records its certificate-only center expression and exact rational box. A node
records an exact root box, split coordinate, and two children. Its
well-formedness predicate requires:

1. the root and child boxes to have the source dimension;
2. the root lower face to equal the left lower face;
3. the root upper face to equal the right upper face;
4. all non-split child faces to equal the corresponding root faces;
5. the left upper and right lower split faces to coincide; and
6. both child trees to be well formed.

The general induction theorem proves that source validity, one accepted batch
whose jobs are exactly the tree leaves, and that topology predicate imply
`m_cell_pass` on the tree root. The proof uses the existing certified
centered-Taylor theorem at leaves and the existing Flyspeck cell-glue theorem
at nodes. It neither trusts an ML coverage assertion nor reconstructs a
separate source theorem for every leaf.

The proof-producing adapter authenticates that the tree's flattened jobs are
the exact batch jobs, consumes one topology theorem, and returns one source
theorem over the root box. The adapter fails closed on a tree/job mismatch,
malformed topology theorem, mismatched source-validity premise, or residual
hypothesis.

## Assessment of the 2026-09-25 performance research note

The note's observations are useful and consistent with the current source,
but they separate into already-addressed costs, still-live candidates, and
work that needs measurement.

### Already covered or substantially reduced

- The checker evaluates one shared source program and shared jet machinery;
  it does not build 43 independently differentiated programs.
- Centered reconstruction, outward rounding, analytic guards, and cached
  whole-box bounds are already inside the reflected numerical algorithm.
- The current genuine leaf uses **one** `Kernel.compute` for both boxes. This
  removes repeated evaluator setup between those boxes, although the one
  batch call still pays equation validation/building once.
- The computed result is an acceptance bit, not the old full diagnostic
  trace. Large result conversion is therefore no longer part of this path.
- Stable analytic-library loads are checkpointed. The new tree support is now
  stable enough to advance that checkpoint boundary as well.
- One box source expression is prepared once. Per-box center-certificate
  variants change only certificate fields and are proved to erase to that
  shared source.
- The exact tree theorem completed the larger missing proof boundary: accepted
  leaves now yield one root theorem and one live-domain handoff.

### Still relevant

- Exact rational normalization and GCD machinery still run inside rounded
  instructions. Bounded output denominators prevent runaway growth but do not
  make the internal fraction engine cheap.
- The reported `4n^2 + 6n + 4` completion work, including 184 normalized
  operations at dimension six even for constant/variable-shaped results, is a
  credible hot-path candidate. Zero/sparse short circuits are not yet part of
  the current checker.
- Rebuilding the 128-pair GCD fuel value for each normalization is a concrete
  allocation candidate. It should be tested independently of a fixed-point
  redesign.
- Full-jet calls whose value/gradient results are discarded, repeated interval
  endpoint products, and dense Hessian handling remain plausible recurring
  costs. Dedicated operations can sit below the existing soundness theorem if
  proved equivalent.
- Every batch still pays `Kernel.compute` equation validation/table building
  once. Batching amortizes this but does not identify how large that fixed
  cost is.
- Per-box square-root hint preparation still invokes proof-producing rational
  reduction even though the proposal theorem is discarded. The exact checker
  subsequently validates the hint, so ordinary untrusted arithmetic is a
  plausible replacement. Variant compilation/encoding is also still
  per-box. These costs affect preparation more directly than reflected
  numerical execution.

### Targeted experiments, in order

The first experiment should use the now-complete root interface, not another
synthetic end theorem:

1. preserve a checkpoint after the stable tree support;
2. time base source preparation, per-box hint/variant preparation, batch
   encoding, `Kernel.compute`, acceptance linking, topology proof, and the one
   root handoff separately;
3. run **1, 8, and 64 distinct accepted subboxes** in one live session and one
   internal batch per size, charging shared preparation once; and
4. run a constant-return call with the same equation set to estimate fixed
   evaluator setup, without mechanically treating that estimate as an exact
   subtraction.

That experiment distinguishes fixed compute setup, recurring interpreted
arithmetic, untrusted preparation, and theorem handoff while preserving the
amortization picture requested by the project owner.

The next independent microbenchmark should exercise constant and variable
completion at dimension six and compare the exact baseline with (a) a proved
zero/sparse shortcut and (b) reused or numeric GCD fuel. It should count
normalizations, GCD iterations/fuel construction, constructor operations, and
integer sizes as well as wall time. If those controls win, they are bounded
local refinements. If ordinary execution of the same algorithm is fast while
`Kernel.compute` remains slow, evaluator specialization becomes the better
next target. A fixed-point backend should wait until these measurements show
that normalization remains dominant.

The note therefore helps explain why reflection has not yet produced an
orders-of-magnitude speedup: the current prototype removed many arithmetic
proof objects but still executes an allocation-heavy exact numerical
algorithm in a general interpreter, while some untrusted preparation remains
proof producing. It does **not** yet establish which one dominates. The
1/8/64 phase breakdown is the smallest experiment that can answer that on the
real architecture.
