## Proof-producing and compiler boundary

This milestone is proof-producing at the implementation level, not merely an
observed executable verdict:

- HOL4 proves the genuine input is accepted without expected outputs;
- `ml_translator` proves the CakeML function implements the HOL function;
- the 4,173-call fold itself is HOL-defined, proved for every count, and
  translated; and
- this repository's `eval_cake_compile_x64` path completed successfully in
  **361 seconds**, supplying the verified x64 compiler boundary for the
  one-cell program.

The first handwritten CakeML repeat harness usefully failed: its direct
application returned `rejected` even at count 1, whereas the translated closed
constant accepted.  Power-of-two diagnostics showed this was not accumulated
GC state.  Replacing the handwritten recursion with the HOL-defined,
translated, universally proved fold made every count 1--4096 and the final
4,173-call runs accept.  The failed artifacts are preserved in the evidence
directory; no result from that harness is used as positive evidence.

This still is not yet a theorem returned by a running Candle kernel.  The
compiler theorem says that the specialized CakeML program implements the
proved HOL checker.  The remaining registered-evaluator refinement must tie
that result to the exact authenticated Candle characteristic equations and
closed call.

## Production theorem without generic replay

The intended production chain is now concrete:

```text
authenticated ceqs + closed call
        |
        v
exact role/schema recognizer and cval-to-word decoder
        |
        v
complete specialized word checker
        |
        v
static HOL4 refinement to generic exec semantics
        |
        v
compute_with_thm gives an assumption-free Candle equality
        |
        v
existing analytic/source/topology theorems give the original inequality
```

The generic `exec` evaluator occurs in the **proof statement** of the static
refinement, but is not run after a registered fast result at production
runtime.  The already committed `compute_with` proof establishes exactly this
behavior: a fast result satisfying `compute_fast_eval_ok` enters the ordinary
theorem constructor directly; an unrecognized call falls back to generic
evaluation.

Reusable pieces now available are:

- the verified `compute_with` kernel seam and unchanged public fallback;
- the complete word checker and its genuine fixture theorem;
- the CakeML translation and verified x64 compilation route;
- the checked analytic/source contract on the HOL Light side; and
- the existing source/topology handoff for case 10173.

The remaining implementation obligations are deliberately narrow:

1. define one canonical registered call schema and decoder for a cell packet;
2. authenticate the exact characteristic-equation identity and call shape,
   rejecting extra equations, aliases, and malformed values;
3. prove the decoded word result refines `exec` for that registered schema;
4. combine the specialized checker translation with the Candle-kernel program
   state and rebuild the verified kernel;
5. obtain the first assumption-free fast Candle equality for genuine cell 0
   and apply the existing analytic theorem to it; and
6. generalize the same decoder to a distinct-cell streaming batch, then apply
   the established tree/source handoff to obtain the original Flyspeck
   inequality theorem.

The main implementation uncertainty is item 4: the current checker and kernel
translations have separate accumulated program states.  The bounded next
experiment is to translate the exact one-cell recognizer and checker in the
kernel lineage, rather than inventing a new callback or trusting an external
executable.  If combining those states requires a broad translator change,
the gate stops and reports that fact before expanding the architecture.
