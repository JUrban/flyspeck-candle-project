## Development-loop gate

Further NL work uses the following gate:

1. changing an expression, box, packet, decoder, or local theorem must be
   testable from a preserved clean checkpoint or a small standalone theory;
2. basic source/typing/shape failures must become visible in minutes;
3. successful `.uo` and checkpoint layers are preserved rather than rebuilt
   after unrelated edits;
4. the same generic checker and refinement boundary must handle at least two
   distinct genuine inequalities without generating another large
   case-specific result ledger; and
5. full kernel/runtime builds are reserved for coherent integration
   milestones after the short tests pass.

If item 4 fails, the packet/refinement boundary must be redesigned before
another long build is authorized by the development plan.

architectural decision: the witnessed zero-crossing boxes already refute a
global positive-branch normalization.

logically equivalent reusable theorem/opcode).  A blanket replacement by
`atn(sqrt x) / sqrt x` is invalid for the actual corpus.  This result narrows
the remaining source-language work without opening another long-running
integration cycle.
