# S1 review-only reference identity collection — 2026-08-28

Candle integration commit
`73a0bdb5f4d219216dd0ea6df790ae8c6d95c4d4` adds a fail-closed
HOL Light reference collector without weakening the independent approval
boundary.  No reference theorem workload was executed for this implementation.

## Collection contract

`candle/reference_fingerprints.py` plans and runs one target in a new reference
process.  Before execution it records a clean full Git revision; hashes for the
collector, launcher, runtime, `ocamlc`, `hol.ml`, manifest, serializer, and every
ordered load file; the OCaml version; audited theorem mapping; and a random
256-bit session nonce.  The launcher receives only an allowlisted environment,
with checkpoint/preloaded theorem state and inherited HOL/OCaml override
variables excluded.

The request loads the exact fingerprint serializer, ordered source files, and
ordered theorem requests.  Fingerprint records are accepted only between the
nonce-bound start and completion markers.  The process must exit zero, all
records and global-axiom identities must be internally consistent, and every
pin plus Git cleanliness is rechecked after exit.

## Deliberate approval barrier

The output schema is `candle-s1-reference-candidate-v1`, with
`approval_status=candidate_unapproved`, `promotion_allowed=false`, and observed
identities nested under `candidate_identities`.  It contains no approved
`expected_identities` object and the tool provides no conversion command.
Both manifest generation and runtime comparison reject the candidate shape if
it is copied into the approved identity table.

An independent review must still establish reference suitability, inspect the
theorem and global-axiom records, and enter a separate exact two-field approved
object in a reviewed commit.  Candidate generation can therefore supply raw
reference evidence but cannot approve its own observations.

## Validation and limitations

Six collector tests cover pin/order planning, source/manual-mapping rejection,
fresh-process collection, review-only candidate shape, marker failures, and
fingerprints outside the nonce interval.  The related focused suite passes 25
tests and the complete Candle host suite passes 89 tests.  The first focused
invocation was run from the repository root and failed imports because these
tests follow the existing `candle/` working-directory convention; the corrected
invocation from `candle/` passed all 25, and discovery passed all 89.

The current no-run plan succeeds for `100/gcd` against the clean pinned
reference, but launcher-to-runtime trust, transitive dependency enumeration,
reference/Candle `hol.ml` suitability, normalized-source policy, and
cross-runtime serializer naming remain explicit review obligations.  Approved
identity coverage is still 0/65 and no S1 status advances from this tooling.
