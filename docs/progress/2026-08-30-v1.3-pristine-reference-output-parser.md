# Pristine direct-reference immutable output parser (2026-08-30)

## Status

Commit `e1abc14` adds the first pure byte-to-observation layer for the pristine
direct-reference protocol.  It is based on the reviewed protocol at `68ac41c`
and the documentation-only review closure at `dacd886`.  It does not start
OCaml/HOL Light, inspect a live process, authenticate an executable or source
tree, create a raw candidate, build a comparison descriptor, approve a
reference, use PFT, or make S2/S3 evidence.

The implementation is
`scripts/parse-pristine-direct-reference-output.py`, activated only by the
fixed-source loader `scripts/load-pristine-direct-reference-output.py`.  It
accepts only immutable
stdout/stderr `bytes`, the already validated raw plan/request, and the exact
separate process result `{"exit_code": 0, "timed_out": false}`.  It revalidates
the plan and request and constructs the transcript and native execution closure
instead of accepting either projection as input.

## Exact source-observation wire

The supported v2 wire is the exact printable ASCII range `0x20`--`0x7e`, plus
tab field separators and LF-only line endings with a required final LF.
Marker decimal fields are canonical unsigned decimals
`0|[1-9][0-9]*`.  It uses the request's exact start, action-complete,
LP-success, native-load, and session-complete names.

Every supported marker carries the plan's 64-hex session nonce.  Start also
binds ordinal and boundary.  Native-load records carry the exact consecutive
event index, phase, action index or `-`, canonical logical source, basename,
positive byte count, SHA-256, and MD5.  Action-complete records carry exact
action index and the plan-selected source/SHA-256.  LP-success records carry
the raw event index, consumer action 184, canonical input index and identity,
and successful-deserialization count one.  Complete binds the boundary and
exact counts 297, 39, and the observed native-ledger length.

The state machine requires one start and one terminal complete marker; exact
actions 0 through 296 in order; native bootstrap records before action zero;
action-phase loader deltas belonging only to the current action; all 39 unique
LP events during action 184 and before its completion; and post-action loader
events only after action 296.  It derives ledger spans, per-action delta
digests, and `loaded` versus `already-loaded` from the observed ledger.  Those
values never occur as accepted marker fields.  Existing strict protocol
validators then recheck the complete transcript and native closure, including
bootstrap anchors, selected source content, uniqueness, exact final-target /
serializer suffix, and serializer authority.

Both stdout and stderr content records are recomputed from their exact bytes.
Successful stderr must be empty.  The v2 source wire is a single retained
stdout artifact, so both the loader-ledger and LP-success artifact records bind
that same complete byte string.  Arbitrary non-protocol diagnostics before the
terminal marker remain retained in that binding.  Marker namespaces, generic
success/failure-like lines, and all bytes following complete fail closed.

## Explicit evidence limit

The current pristine request names a semantic-observation class, but it does
not specify exact fields, ordering, nonce binding, dependency-history terminal,
or how the existing theorem/state fingerprint wires compose into a complete
pristine semantic record.  Coverage-v2 additionally needs independently
observed final semantic/completion facts.  The parser therefore rejects
semantic/fingerprint/dependency and all other unknown success-like lines.  It
returns `semantic_projection = null` and `cross_runtime_coverage = null` with
explicit `not-parsed` / `not-derived` statuses.

Consequently this is a source-observation prerequisite, not a full producer:

- its process-complete transcript only records the exact terminal source-wire
  marker and must not be treated as proof that the request's deferred semantic
  operation was performed;
- its envelope says `authentication_status = not-authenticated`, includes no
  candidate, and has false approval, promotion, PFT, S2, and S3 fields;
- no current raw candidate or comparison descriptor may be constructed from
  this result; and
- despite the v2 content bindings below, a later producer must still
  authenticate the parser/request and execution under a clean held lock.

The next prerequisite is an independently reviewed producer grammar for the
four final theorem fingerprints, final state fingerprint, four ordered
dependency-history records and terminal, and the remaining coverage-v2
completion observations.  Only after that grammar exists should this parser
accept those lines and derive the common projections.

## Hostile review repairs

Independent review found that `e1abc14` could retain a PFT claim in an
otherwise ordinary stdout line while returning `pft_used = false`.  It also
accepted ambiguous Unicode formatting/control characters, and Python's own
large-integer conversion limit could escape the protocol exception type.
Commit `c001fef` closes those findings before any authenticated producer use:

- every stdout line is searched for a case-insensitive, delimiter-bounded PFT
  token before marker-versus-ordinary classification; exact `PFT`,
  `PFT_USED`, `PFT_SUCCESS`, whitespace-delimited, and path/punctuation-
  delimited variants all reject;
- stdout is restricted to the explicit printable ASCII/tab/LF alphabet, so
  DEL, C1 controls, BOM-prefixed markers, bidi/format controls, Unicode line
  separators, and non-ASCII confusables reject; and
- canonical decimals are bounded to 19 digits before conversion, while any
  conversion failure is translated to `OutputProtocolError`.

The focused suite is now 13/13 and includes the exact reported PFT strings,
mixed-case and path variants, all requested hostile code-point classes, a
BOM-prefixed `CANDLE_` marker, and a 5,000-digit decimal.  The no-semantic,
no-candidate, unauthenticated, unapproved, non-PFT, and S2/S3-false boundary is
unchanged.

Independent exact-commit rereview of `c001fef` then returned PASS with no P0,
P1, or P2 finding.  It extended the delimiter attacks across case, whitespace,
slashes, punctuation, and embedded non-token substrings; checked DEL, C1, BOM,
RLO, ZWJ/format controls, Unicode line separators, and non-ASCII printable
characters; and exercised empty, signed, float, exponent, padded, leading-zero,
NaN, infinity, 20-digit, and 5,000-digit decimals.  The parser, pristine
protocol, and direct protocol suites independently remained 13/13, 9/9, and
30/30 respectively.

## Schema-v2 parser authority binding

Commit `52b5a6d` makes the earlier parser-local prerequisites explicit and
disjoint.  The full top-level raw chain is now schema 2 with `*-v2` kinds and
v2 marker names; schema-1/kind-v1 artifacts and v1 native markers reject.  The
unchanged nested LP inventory/success schemas remain v1 and cannot be confused
with the top-level version.

The v2 producer authority has the exact additional key `output_parser`, an
exact content record at the fixed path
`scripts/parse-pristine-direct-reference-output.py`.  Test fixtures bind its
actual bytes.  The parser captures those bytes when its module initializes and
requires the plan claim to match before parsing.  Its sibling loader also
rechecks the exact v2 plan/request/transcript/native-closure kinds, complete
marker contract, final boundary/count, LP consumer/success contract, loader
policy/order, and fixed parser path each time it is used.

The request's exact marker contract now owns
`CANDLE_PRISTINE_DIRECT_NATIVE_LOAD_V2`; the parser reads that field from the
validated request rather than exporting a parser-local marker authority.  The
pair validator's existing full-authority equality requires both distinct
nonces to use the same parser content.

Hostile coverage now includes schema/kind-v1 downgrade attempts across all
five top-level artifacts, v1 authority policy, missing/path-drift/bool parser
records, missing or v1 request native markers, actual parser-content mismatch,
v1 native output, and an incompatible cached sibling.  Current isolated
results are parser 16/16, pristine protocol 10/10, direct protocol 30/30,
direct-result consumer 18/18, and parser-result consumer 7/7.

## Exact-JSON and trusted-loader hostile repair

Hostile rereview of `fd9be93` found that Python's coercive composite equality
could accept `False` for `0` and `True` for `1` inside otherwise exact JSON.
It also found that a directly executed parser could hash arbitrary `__file__`
bytes and relabel them with the fixed authority path, while the sibling checks
did not cover all consumed role constants.

Commit `c5aebf0` replaces the affected nested comparisons with canonical JSON
byte equality.  This covers the request entrypoint sequence, marker contract,
serialization environment, content records, native action bindings and LP
stream, candidate serialization/artifact closure, and pair authority/plan
inputs.  Canonical JSON entrypoints now require immutable `bytes` rather than
accepting `bytearray`.  Regressions include bool/int changes to entrypoint
indexes and success flags, marker and serialization booleans, candidate
serialization, and an action-binding `index = false` closure whose recomputed
content record previously let a full raw candidate pass.

Commit `7fb6775` adds the trusted fixed-root loader.  It receives the project
root as an external trust input; rejects redirected source paths; reads the
fixed parser and protocol through no-follow ordinary-file descriptors with
before/after identity, size, and modification-time checks; compares both exact
byte records with producer authority before execution; and compiles those
captured bytes directly with no bytecode import.  The parser requires injected
trusted activation, rechecks both byte records and the project root against the
plan, and checks the exact schema/kinds, full marker contract, role/nonce,
boundary/action/LP, and loader constants on every use.  A direct or copied
parser cannot rederive evidence, a mismatched protocol claim rejects before
compilation, and a hostile `.pyc` fixture is ignored.

The loader is a trust-boundary prerequisite, not an authenticator: its caller
must later pin the loader and trusted project checkout/head under the held-lock
producer authority.  It does not construct a candidate or alter any semantic,
approval, PFT, S2, or S3 status.  Current focused counts are parser 17/17 and
pristine protocol 10/10.

No OCaml, HOL Light, Flyspeck, Holmake, proof replay, reference sweep, or PFT
workload was started.
