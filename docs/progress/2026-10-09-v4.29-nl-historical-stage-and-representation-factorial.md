## Question and controls

The broad nonlinear investigation continues to treat the two historical gaps
as different problems:

1. approximately 15 times between a native numerical implementation and its
   encoded `Kernel.compute` execution; and
2. approximately 340 times between the original generic native fixed-scale
   implementation and the historical specialized C++ verifier.

Those are starting observations, not current universal ratios.  The first is
an execution-boundary problem.  The second combines arithmetic cost,
derivative/Taylor work per box, enclosure quality, and the number of boxes the
adaptive search must visit.

## Arithmetic-representation factorial

The next experiment holds the historical algorithm and outward-sound
contract fixed while changing checked mixed-integer exact arithmetic to the
existing padded hardware representation.  It also profiles both backends at
the same stage boundaries.  Nine warmed, rotation-balanced repetitions gave:

| Backend | Preparation | Evaluation | Complete batch | Accepted |
|---|---:|---:|---:|---:|
| Checked mixed integer | 0.077306 s | 0.530290 s | 0.607595 s | 682 |
| Padded hardware | 0.072170 s | 0.269528 s | 0.341697 s | 682 |

The hardware representation is **1.967 times** faster in recurring evaluation
and **1.778 times** faster including preparation.  Profile instrumentation is
neutral within run noise: 0.990 times for the exact lane and 1.004 times for
the hardware lane.  Within each backend, enabling the profile leaves every
result row byte-identical.

The stage ratios localize the representation cost:

| Historical stage | Exact / padded time |
|---|---:|
| Root, inverse, and denominator | 4.966x |
| Delta jet plus square root | 2.459x |
| Gradient and logarithmic-`U` work | 1.817x |
| Denominator Hessian | 1.660x |
| `delta_x4` | 1.511x |
| Final Hessian assembly | 1.503x |
| Triangle-`U` jets | 1.419x |
| Denominator gradient | 1.350x |
| Arctangent and value | 1.337x |

The padded lane has one broad-node representation failure, which is treated
as a mandatory subdivision; both lanes nevertheless make the same 682
negative pruning decisions.  Against exact results, padded bounds are equal
on the 84 domain-subdivision nodes, wider on 1,259 nodes, and tighter on one.
This is a development discriminator, not yet a verified backend.

The previous rounding-only factorial is still important: removing directed
padding from the same hardware representation improved the complete batch by
only 1.182 times.  Together, the experiments say that exact root/inverse
representation is a useful target, while outward rounding alone is not the
large gap.  In the padded run the complete historical instruction is only
34.30% of evaluation; making all of it free would still cap speedup near
1.52 times.

## Larger-gap plan

The next native experiment should change mathematical work while keeping the
now-measured arithmetic backend fixed.  It will use one complete genuine
inequality from its initial box rather than replaying only a pinned forest:

1. Put the current historical/Taylor evaluator and a faithful complete
   specialized numerical evaluator behind the same native adaptive-forest
   driver, split policy, scale, and outward hardware interval type.
2. Record separately: preparation, per-box evaluation, visited boxes,
   enclosure margins, domain/representation subdivisions, total elapsed
   time, and peak memory.  A fixed-node replay will check per-box cost; the
   root-started run will expose the multiplicative effect of enclosure
   tightness on search size.
3. Attribute the complete expression, not only its three dihedral nodes.  The
   current exact instruction profile shows substantial remaining generic
   square-root and multiplication work outside the historical primitive.
   Candidate direct instructions should therefore cover a reusable compact
   centered-jet block or the complete certificate leaf, not another isolated
   delta micro-shim.
4. Run the winning design on a second genuine nonlinear family.  Require
   unchanged certificate acceptance and a material complete-batch win before
   beginning its general soundness theorem.  Bound tightness and visited-node
   count are gates, not secondary diagnostics.
5. After selecting the numerical algorithm, implement a proved compact
   checked-word arithmetic layer with explicit overflow data and exact
   fallback.  The present 1.97-times representation result sets a plausible
   payoff, but also shows that doing this before reducing box count and
   mathematical work cannot deliver the overall objective.
6. Only then run the same accepted instruction plan through `Kernel.compute`
   and measure numerical execution plus theorem handoff.  That directly
   addresses the independent approximately 15-times execution-boundary gap.

This ordering keeps preparation and general proof effort reusable, while
using complete-certificate cost and acceptance—not microbenchmark speed—as
the decision rule.
