## Complete independent native factorial

The case16594 source contains three 39/85-step polynomial pairs.  A cheap
site-by-site screen established a sharp enclosure boundary:

- deferring intermediate Taylor completion at any one 39-step site retained
  875/875 acceptance; and
- doing the same at the three 85-step sites retained only 866, 870, and 868
  cells respectively under the first hardware screen.

The accepted complete experiment therefore lowers every polynomial of at
most 39 steps while retaining the unchanged path for the 85-step partners.

hardware arithmetic at the same `2^40` grid.  Five rotation-balanced runs on

## Adaptive normalization does not rescue the large blocks

A bounded follow-up retained fused box jets but recomputed Taylor value and
gradient enclosures after every polynomial product.  This tests whether the
85-step failure was merely caused by leaving the fused state unnormalized for
too long.  It was not sufficient: individually normalized sites 35, 78, and
121 accepted only 867, 872, and 869 cells, and normalizing all fused
polynomials through 85 steps accepted 859/875.

This branch is rejected before proof work.  A future 85-step optimization
would need a genuinely tighter source-derived derivative/enclosure algorithm,
not a different normalization cadence in the present generic jet.

## Bounded proof packet

The CakeML branch now also specifies total option-valued bounded operations:

- 128- and 192-bit addition;
- 128-bit endpoint multiplication into a 192-bit accumulator;
- checked 192-to-128 narrowing; and
- floor and ceiling dyadic shifts from the wide accumulator to an endpoint.

For every operation, `NONE` is proved equivalent to the exact overflow
condition and every `SOME` result is proved equal to the corresponding
natural-number operation.  These are logical refinement contracts, not fast
word implementations.  The existing exact Candle fallback remains unchanged.
Clean focused HOL4 builds pass at CakeML commits `395f35356` and `05b42fa4a`.

The next executor packet is one actual word-level operation plus its
refinement and explicit overflow result, followed by a closed compute
microbenchmark.  It must win before the compute datatype and correctness
proof are widened further.  A complete 875-cell proof-producing batch, not
the scalar microbenchmark, remains the integration gate.
